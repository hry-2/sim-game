# NEON SCRAPLINE

赛博朋克像素俯视角生存射击 · 纯前端单文件 · 无构建 · 无依赖

本目录的 `index.html` 一个文件就是完整游戏（HTML + CSS + Canvas 2D + WebAudio 合成音效，零外部资源，仅可选加载 Google Fonts）。

> 游戏合集里的一款，返回 [游戏柜](../../README.md)。

## 运行 / 部署

双击 `index.html` 即可。仓库根目录本身就是可发布的静态站点，
开启 GitHub Pages（`main` / `/(root)`）后本作在 `/games/neon-scrapline/`，
详见[根目录说明](../../README.md#部署到-github-pages)。

单独拿出去用也没问题——这一个文件就是完整游戏，没有任何外部依赖。

## 玩法结构

- **波次制**：每波持续 18–28 秒，清空后进入 3 秒补给间隙，第 5 / 10 / 15… 波刷 BOSS「母体核心」（掉到一半血进第二形态）。
- **三张场地**轮转，形状各不相同；打赢一个 BOSS 就换个地方。
- **敌人**：拾荒机兵（追击）、刀锋犬（间歇冲刺）、哨戒无人机（保持距离射击）、重装机甲（三连弹 + 高血量）、母体核心（环形弹幕 + 召唤）。
- **武器**：六把（含一把近战），开局一把，其余从升级卡里拿，`Q` 切换。改的是打法不是数值，详见下面一节。
- **绿色核心**是经验，粉色十字是治疗包；磁力范围内自动吸附，掉落 2.5 秒后也会缓慢向你飘。
- **升级三选一**，18 条改装词条可叠加（3 条要先解锁）：射速、伤害、穿透、多弹丸、移速、生命上限、拾取范围、反应护盾、冷凝减速、爆裂击杀、击杀回血、幽灵冲刺（冲刺撞击伤害）、弹幕透镜、静电场、暴击回路。
- **连杀 Combo** 提升得分倍率，受伤清零。
- **最好成绩存本地**，标题页显示，死亡屏告诉你差几波。
- **道具外显**：每条词条在人物身上都有对应的一件东西，五把枪五个枪型。空手和拿满是两个样子。
- **涂装**：六套配色，纯外观不带数值，里程碑解锁；每日局用当天主题。
- **每日局**：种子取当天日期，全世界今天同一局，固定配置、词条全开。
- **义体档案**：九个里程碑解锁武器与词条，废钢买起手武器，三个底座各带代价。开局只有脉冲步枪和 15 张基础词条，其余都要打出来。

## 六把武器：改的是怎么打，不是数值大小

开局只有脉冲步枪，其余五把作为**换装卡**出现在升级三选一里，拿到就永久带着，
`Q` 键在带着的枪之间切换。

| 武器 | 手感 | 强在哪 | 弱在哪 |
| --- | --- | --- | --- |
| 脉冲步枪 | 中速单发 | 没有短板 | 也没有长处 |
| 霰弹枪 | 一次七发扇形，**有后坐** | 贴脸撕开一片 | 远了什么都打不到 |
| 磁轨枪 | 一条光束，**穿透整条线上所有敌人** | 他们排队的时候 | 慢，要预判 |
| 电弧链 | **自动跳**到最近的敌人，连锁三次 | 不用瞄，群战 | 伤害低，对单体差 |
| 榴弹 | 抛射落地爆炸，**能越过前排** | 成堆的时候 | 站太近会炸到自己 |
| 振动刀 | **近战**：身前扇形一刀砍一片，击退 + 回血 | 贴身、人堆里 | 你得贴上去，而敌人碰到就伤你 |

### 第六把：振动刀（近战）

近战在这个类型里有个真问题：**敌人是靠碰撞伤人的，而近战要求你贴上去**。
所以它不能只是"射程为 0 的枪"，得自带贴上去的理由。三条补偿写进武器本身：

- **一刀砍一片**（cleave）：身前 110° 扇形、半径 42，扇形里的全砍到
- **命中击退**：把敌人推开 12px —— 这是核心，它自己把近战需要的空间打出来
- **命中回一点血**：奖励你留在人堆里；但每刀回血有上限，砍到六个也只回 3 血，
  不能就地满血

一刀左一刀右交替，挥出去有一道看得见的弧从一侧扫到另一侧。
解锁条件是**近身拆掉 8 台重装机甲** —— 机甲慢、血厚，只能贴上去打，
所以解锁本身就是一次近战预演。

**两条对刀本来是废卡的词条被改了说法**，不然拿到就等于跳过一次升级：

| 词条 | 对枪 | 对刀 |
| --- | --- | --- |
| 双联发射 | 弹丸 +1 | **扇形加宽 18°** |
| 穿甲钨芯 | 多穿透 1 个 | **砍得更远 6px** |

> 击退这里踩过一次：一开始写的是 `击退力 / 距离`，验收也过了 ——
> 但打印出来才发现只推了 2px，**等于没有击退**。
> 除以距离在贴身时会退化成零，而近战恰恰是贴着打的。
> 改成「单位向量 × 固定像素」，并把断言从「推开了」改成「至少推 6px」，
> 又补了一条「贴身砍也推得动」。**断言写成"变了"是不够的，得写成"变了多少"。**

**词条作用在倍率上，不直接改武器数值。** 这一条很重要：射速、伤害、弹丸数、
弹速那几条词条改的是 `P.mul.*`，换枪时重新用「武器基础值 × 倍率」算一遍。
不这么做的话，换一次枪就把攒了十级的强化清掉了。

## 人物与怪物：先分轮廓，再谈细节

原来五个单位都是「圆角方块加个亮心」，在一群怪里只能靠颜色区分，靠不了轮廓。
重画之后每个的剪影都不一样：

| 单位 | 剪影 | 会动的地方 |
| --- | --- | --- |
| 玩家 | 朝镜头的护盔人形，枪跟着准心转 | 四帧走路，脚交替 |
| 拾荒机兵 | 带四条短腿的方箱 | 腿交替 |
| 刀锋犬 | 又低又长的水滴，前端一把刀 | 冲刺时刀锋伸出 |
| 哨戒无人机 | 菱形本体 + 四个角上的旋翼 | 旋翼三帧转 |
| 重装机甲 | 上下两条履带的宽板 + 肩炮 | 履带滚动 |

地面单位有投影，无人机有悬浮起伏 —— 这两样让它们看起来是"踩在地上"和"飘在空中"，
而不是都贴在同一个平面上。

**辉光只让亮的部分参与了。** 原来是整帧下采样再加回去，等于把中间调也一起点亮，
新精灵的细节全被糊平。改成先提亮度加对比度近似一个阈值，霓虹还在发光，像素也看得清。

## 验收

```bash
npm run check:neon
```

游戏整个包在 IIFE 里，`node --check` 只能查语法，查不出**初始化顺序**这类错。
`tools/verify-neon.js` 用一个最小 DOM 桩把整段脚本真的跑一遍，再检查 17 项：
精灵每行宽度、武器表字段、换枪不清词条、五把枪各自的产物（几发子弹 / 一条光束 /
一条折线 / 一枚抛射物）。

> 加这个脚本是因为踩了一次：词条表里引用了还没声明的武器表，
> 浏览器里的表现是「标题页正常，点开始没反应」，控制台什么都不报。

## 人物：身体朝镜头，道具挂在身上

以撒和土豆兄弟的人物之所以看得清、之所以挂得住道具，是因为**身体始终朝着镜头**。

原来这里的人物随准心整体旋转 —— 俯视角的人必然是个圆块：没有头、没有手、没有脚，
也**没有固定的地方能挂东西**。所以换了画法：

- **身体朝镜头**，16×20，四帧走路循环（护盔、面罩、肩甲、两条腿交替）。往左瞄就水平翻转。
- **只有枪跟着准心转**，绕胸口一个支点。朝左时上下翻一次，否则枪会倒过来。
- **枪型按武器换**：五把枪五个形状（细管 / 双管 / 带线圈 / 叉状电极 / 粗口）。

### 升级了，身上就多一件

每一条能叠的词条都对应一片贴花，挂在固定槽位，分三层：

| 层 | 挂什么 |
| --- | --- |
| 枪上（跟着枪转） | 散热片、冷凝罐、配重、长针、制退器、环形透镜 |
| 背后（被身体压住一半） | 药罐、爆裂罐、电容组 |
| 身上 | 头侧目镜、头顶残影环、肩上输血管、左肩盾板、腰间磁环、腰侧电极、腿侧助推、脚后尾翼 |

**双联发射走的不是贴花，是真的多一根枪管** —— 叠两层就是三根管，这是最看得出来的叠加。

空手 → 拿六条词条 → 拿满，人物是明显不同的三个样子。
贴花只用调色板键，所以**跟着涂装一起换色**，不用为六套涂装各画一遍。

> 验收里有一条守着这件事：**每一条能叠的词条都必须有对应外显**，
> 少一条就红。否则以后加词条很容易忘了给它画东西，
> 而"升级了看不出变化"正是这次要解决的问题。
> 另有一条查贴花不许挤在同一个槽位 —— 挤在一起会糊成一团。

> 顺带一个手感上的取舍：人物现在 16×20，比受击半径（7px）大不少，
> 尤其纵向。这是刻意的宽容方向 —— 子弹擦着头顶和脚边过去不算命中。

## 涂装：只换外观

精灵是**字符网格 + 调色板索引**画出来的，不是位图：

```js
const ch = rows[y][x];          // 网格里的一个字符
t.fillStyle = pal[ch];          // 查调色板
```

所以**换一份调色板就是一套新皮肤，网格一个字都不用改**。六套涂装：

| 涂装 | 怎么解锁 |
| --- | --- |
| 神经索 | 默认 |
| 母体 | 拆掉一个母体核心 |
| 废钢 | 累计 1000 废钢 |
| 磁轨 | 活到第 12 波 |
| 霓虹 | 累计拆解 1500 个 |
| 幽灵 | 打满 20 局 |

换涂装同时换掉冲刺拖尾、护盾环、身周光圈和小地图上的自己 —— 一处配色贯穿到底。
每套烤一份精灵缓存住，之后换涂装是零成本。

**每日局用「今日主题」涂装**（种子取当天日期），而且不看解锁 ——
外观不影响公平，没道理拦着。

### 刻意不带数值

涂装不附带任何效果。带了它就成了第二套底座系统，跟已有的底座打架，
而且会把「选好看的」变成「选强的」。

这一条不是靠自觉，是**被测试守着的**：`tools/verify-neon.js` 里有两条断言 ——
换遍六套涂装开局，玩家的 17 个数值字段必须完全一致；
以及涂装的定义里不许出现任何生效函数（结构上就没法带数值）。

> 顺带一句：加涂装的时候，那条「所有里程碑给的都是新东西，不是永久数值加成」的
> 元断言直接红了 —— 因为它只认「卡池 / 词条 / 底座」三种奖励。
> 这正是它该做的事：**逼我明确把「涂装」加成第四种奖励类型，而不是偷偷混进去。**

## 三种要战术应对的敌人

原来五种敌人只在血量和速度上不同，**应对方式全是「对着打」**——
所以六把武器的差异是存在的，但没有敌人来考它。加这三种就是为了考它：

| 敌人 | 机制 | 逼你做什么 | 谁是答案 |
| --- | --- | --- | --- |
| **铁闸** | 正面 ±65° 只吃 15% 伤害，转身慢 | 绕到它侧后方 | 任何武器 + 走位；**或者榴弹** |
| **爆囊** | 靠近 30px 点火，0.55 秒后炸，连锁伤敌 | 远距离点掉，别贴着 | 远程；**振动刀在这里是短板** |
| **信号中继** | 给 78px 内的敌人减 65% 伤害，画连线 | 先打谁后打谁 | 电弧链自动跳、磁轨穿透一整排 |

**爆炸无视盾**，这不是特例，是从实现里自然掉出来的：`hurtMob` 只有带来源坐标时才判方向，
而爆炸不传来源。所以榴弹和「爆裂核心」词条天然是铁闸的答案 —— 一个规则，两个后果。

**中继的连线是关键的界面**。被护着的敌人套一层绿环，中继和它护着的每一个之间画一条线，
所以"为什么打不动"和"该先打谁"不用文字解释。中继一死，护盾在几帧内自己掉 —— 不是永久的。

> 盾的方向我第一次写反了：`rel > 115°` 挡的是**背后**。
> 验收里那条「正面打只进多少伤害」当场就红了（正面 100、背后 15，正好倒过来）。
> 这类方向错误看代码很难看出来，**必须写成两个方向都量一遍的断言**。

## 观感设置（可及性，不是打磨）

震屏最高到 10、辉光叠两层，这对晕动敏感的人是硬门槛，而原来**没有关的办法**。
标题页的档案面板上加了一行：

- **震屏** 关 / 弱 / 标准
- **辉光** 关 / 开（关掉时整段后处理都跳过，不是只把透明度调 0）
- **音量** 静音 / 低 / 标准

系统里开了「减少动态效果」时，**震屏和辉光默认就是关的**，不用用户自己去找，
面板上也会说明一句。三项都存在档案里。

## 场地：打赢一个 BOSS 就换个地方

三张场地轮转，**形状不一样才是重点**，不只是换个颜色：

| 场地 | 尺寸 | 打起来的区别 |
| --- | --- | --- |
| 废钢回收线 | 1216 × 768 | 标准，横向跑得开 |
| 熔渣池 | 1024 × 1024 | 方的，横向没那么多逃跑余地，纵向多 |
| 冷却塔 | 1440 × 608 | 又扁又长，视线远 —— 磁轨枪的主场 |

BOSS 在第 5 / 10 / 15 波，所以第 6 / 11 / 16 波换场地：**打赢了就往前走**。
换场地时清掉残留的敌人和子弹，把人放到新场地中间（不然会卡在墙外）。
装饰色和网格色跟着场地变。

## BOSS：两个形态

原来 BOSS 是程序化画的几个旋转六边形，和四种杂兵重画之后**画风是断的**。
现在它走精灵，两套：

- **第一形态**：外层装甲板完整，核心小而暗，十向环形弹幕，偶尔召唤
- **掉到一半血 → 外壳崩解**（屏幕震一下，横幅提示）
- **第二形态**：**一半装甲板没了、核心露出来发白**，速度 ×1.5，
  弹幕从「一波一波的十向」改成**连绵不断的螺旋**，召唤刀锋犬

改的是打法，不是血量。一个只是血更厚的第二形态不值得做。

## 手机上能暂停了

触屏原来只有「冲刺」和「枪」，`P` 和 `M` 是键盘专用的 —— **手机玩家中途没法停**。
右上角加了「暂停 / 音乐」两个键。

> 这里有个坑：触屏层原来的显示条件是「play 且没暂停」，
> 所以一暂停，**连暂停键自己都消失了，再也点不回来**。
> 改成暂停时只收起摇杆和动作键，系统键留着。
> 顺带发现画布上那行暂停提示写着「按 P 继续」—— 手机上没有 P 键，改成分设备显示。

## 每日局：全世界今天同一局

标题页上可以切「自由 / 每日」。每日局的种子取当天日期，所以**同一天所有人面对的是
同一批怪、同一批三选一**，比的是谁玩得好。今日成绩单独存，不和自由局的历史最好混。

**每日局是固定配置**：标准底座、脉冲步枪、**全部词条开放**。
如果让档案生效，解锁多的人天然占便宜，"在同一条起跑线上比"就不成立了。
顺带一个好处：每日局是新手唯一能立刻见到全部内容的地方。

### 随机源分了三条流

仓库的规矩是不用 `Math.random`（市井那边写在文档里）。这次补上了 ——
整份文件现在零处引用。但真正要紧的不是换掉它，而是**分流**：

| 流 | 管什么 | 为什么单独一条 |
| --- | --- | --- |
| `RNG.wave` | 刷怪表、掉落、场景装饰 | 每日局要保证同一批怪 |
| `RNG.card` | 升级三选一 | 每日局要保证同一批卡 |
| `RNG.fx` | 粒子、暴击、护盾 | 不影响公平，随便摸 |

混在一条流里的话，**你多打一发子弹，下一次三选一的三张卡就变了** ——
那"大家一样"就不成立了。验收里专门有一条：粒子流摸 500 次，卡牌流必须还是同样三张。

> 每日局保证的是**刷怪表和三选一完全一致**，不保证逐帧一致 ——
> 敌人的行为会随你的走位分岔，这是动作游戏的每日局都有的性质。

## 成长：义体档案

Roguelite 的成长系统最容易做坏的一点是**给永久数值加成** —— 那只会让前期变简单，
把已经通过的关卡再削一遍，玩得越久越无聊。

所以这里三层，没有一条是纯数值：

### ① 解锁：改变「可能出现什么」

九个里程碑，达成一次永久解锁一样东西。**开局只有脉冲步枪，卡池只有 15 张基础词条**，
四把枪和三张带代价的词条都要打出来：

| 里程碑 | 解锁 |
| --- | --- |
| 活到第 4 波 | 霰弹枪进卡池 |
| 活到第 6 波 | 底座：轻甲型 |
| 活到第 7 波 | 磁轨枪进卡池 |
| 累计拆解 400 个 | 电弧链进卡池 |
| 打满 5 局 | 新词条：过载电容（射速 +45%，生命上限 -15） |
| 活到第 10 波 | 榴弹进卡池 |
| 拆掉 20 台重装机甲 | 新词条：反冲抑制（散布 -60%，弹速 +40%） |
| 累计 600 废钢 | 底座：重载型 |
| 拆掉一个母体核心 | 新词条：幽灵协议（冲刺 CD -50%，生命上限 -20） |

**每一局都在扩大未来局的可能性** —— 这才是「下一局会不一样」。
三张新词条全都带代价，纯加强的卡不会被记住。

### ② 废钢：改变「怎么开局」

每局产出 `波次 × 12 + 击杀`，所以**打崩的一局也不算白打**。
攒 150 废钢把某把已解锁的枪买成起手武器，下一局就从它开始。

### ③ 底座：改变「这一局的性格」

三个底座都带代价，选的是想怎么打，不是哪个更强：

| 底座 | 效果 |
| --- | --- |
| 标准型 | 没有加成，也没有代价 |
| 轻甲型 | 移速 +25%，生命上限 -30 |
| 重载型 | 生命上限 +60，移速 -15% |

档案面板就在标题页上，不另开一屏：废钢 / 局数 / 累计拆解、起手武器、底座、
以及一行「下一个解锁：活到第 10 波 → 榴弹进卡池」。
死亡屏上会写这一局挣了多少废钢、解锁了什么。

> **读档时会补发早该给的里程碑。** 条件满足和奖励发放是两件事：奖励只在一局结束时结算，
> 所以直接改档案或者新版本加了里程碑，都会出现「条件早过了但没发」。
> 进游戏先补一次，否则面板上会写着「打满 5 局」而你已经打了 11 局。

## 一局打完留下什么

Roguelite 的勾子只有一句话：**下一局会不一样**。而一局打完如果什么都不留下，
"我死了"就只是一个会被忘掉的数字。所以死亡屏上现在有三行：

```
义体在第 9 波被重装机甲拆解
打法：磁轨枪 + 超频枪机 + 穿甲钨芯
最好：第 12 波 —— 差 3 波
```

- **被谁拆的**。伤害来源一路带到 `hurtPlayer(dmg, src)`，敌人子弹也带着发射者的类型。
  「被刀锋犬拆的」和「被自己的榴弹炸死」是两种完全不同的教训。
- **这局是什么打法**。打出伤害最多的那把枪 + 堆得最多的两条词条。
  换装卡不算进"堆"出来的词条里 —— 它不是堆出来的。
  一局有了名字，才会想再来一局证明另一套。
- **离最好差多少**。先比波次，波次一样比分数。
  这一条把"我死了"变成"我差三波"，是所有改动里回报最高的。

最好成绩存在 `localStorage['ns.best']`，连那一局的打法一起存 ——
所以标题页上写的是「最好：第 12 波 · 21400 分 · 磁轨枪 + 穿甲钨芯 + 暴击回路」，
你一开局就看见要打败的是什么。读写都包了 try/catch：**无痕模式下 `localStorage`
会直接抛异常**，不能让存档把游戏带崩。

> 还没做的那半边勾子是**解锁改变开局**（打到某一波解锁新的起手武器 / 新词条进池）。
> 那是让"下一局会不一样"真正成立的东西，但要先定解锁什么，是个设计决定。

## 手机上怎么玩

双摇杆射击在手机上有一套约定俗成的做法，照着来：

| 操作 | 做法 |
| --- | --- |
| 移动 | **左半屏任意位置按下**，摇杆的圆心就落在你按下的那一点 |
| 瞄准 | **右半屏按下并拖**，按着就一直开火 |
| 不瞄 | 右手不按时**自动瞄最近的敌人并开火** —— 单手也能玩 |
| 冲刺 / 换枪 | 右下角两个按钮 |

摇杆的圆心跟着手指落点走，不是固定在屏幕角上 —— 固定的话拇指每次都得先去找它。
两个摇杆各自记住自己的 `pointerId`，所以能同时用。

**触屏层盖的是整个视口，不是画布。** 竖屏时 16:9 的画布只占屏幕中间一条，
而拇指是放在屏幕最下面的 —— 只盖画布的话，手指按在画布外面就什么都不会发生。
横过来玩视野宽一倍，竖屏时顶上会有一行提示。

**触屏模式是第一次真的碰到屏幕时才切的**，不是开局用 `pointer: coarse` 猜一次。
触屏笔记本插着鼠标时指针是 fine，但用户照样会用手指戳屏幕；反过来，
猜错了就永久失效。监听器一直装着，碰到屏幕那一刻再切。

顺带处理的几件小事：禁掉双指缩放和双击放大（玩着会被放大）、
关掉下拉刷新和橡皮筋、按钮避开刘海和小白条、切后台自动松开摇杆
（否则回来还在"按着"）、横竖屏切换和地址栏收起都重算画布尺寸。

## 想自己调参

全部数值集中在本目录 `index.html` 的这几个位置，直接改数字即可：

| 位置 | 作用 |
| --- | --- |
| `const VW / VH` | 内部渲染分辨率（越小像素越大） |
| `const ARENA` | 场地尺寸 |
| `const BASE` | 玩家初始属性（速度、射速、伤害、拾取范围…） |
| `MILES` / `CHASSIS` / `WEP_COST` | 里程碑、底座、买起手武器的价钱 |
| `SKINS` | 涂装（只是调色板覆盖，改它不会影响玩法） |
| `RNG` / `seedRun` | 三条随机流；改了会影响每日局的可复现性 |
| `const MOB` | 各类敌人血量 / 速度 / 伤害 / 经验 |
| `const UPGRADES` | 词条名称、描述、效果函数、叠加上限 |
| `nextWave()` / `waveSpawn()` | 波次时长、刷怪预算与刷怪表 |
| `hpS / spdS` in `spawn()` | 难度随波次的成长曲线 |

渲染管线：低分辨率 Canvas → 两级降采样叠加做辉光（bloom）→ 预渲染扫描线 + 暗角 → 移动扫描带。想更"干净"就把 bloom 的 `globalAlpha` 调低。

## 兼容性

Chrome / Edge / Safari / Firefox 桌面端与手机均可运行。桌面用键盘鼠标，手机用双摇杆（见上面一节）。
音频在首次点击或触摸后才会初始化（浏览器自动播放策略）。
