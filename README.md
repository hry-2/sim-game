# sim-game

效用AI 驱动的生活模拟游戏原型 —— 借鉴《模拟人生》的需求驱动 AI
与《行会3》的生产链经济，两者共用同一套打分内核。

## 快速开始

```bash
npm run dev          # 起本地服务，打开 http://localhost:5173
npm run sprites      # 重新生成角色精灵（需 pillow numpy）
npm run check        # 冒烟测试（需 playwright）
```

原型都是零依赖单文件 HTML，直接用浏览器打开 `src/sim/index.html` 也能跑。

## 核心设计：效用 AI + 智能物件

物件不被 AI「认识」——**物件主动广播自己能满足什么需求**。
角色只做一件事：给所有广播打分，挑最高的。

```
分数 = Σ(广播量 × 紧迫度^p × 性格权重) ÷ 距离折扣
```

加新玩法不用改 AI，只需在 `OBJ` 数组里加一条数据。

生产链靠**前置条件**自然串联，没有任何硬编码的步骤顺序：

```
林地(无条件) → 工作台(需木材≥2) → 摊位(需家具≥1)
            → 粮店(需金币≥24) → 炉灶(需食物≥2)
```

### 三个已经踩过的坑（改动 AI 前务必读）

1. **决策抖动** —— 不能用「需求低于阈值就打断」。两个需求同时告急时角色会无限
   横跳，一件也做不成。必须用**迟滞切换**：定期重估，新方案要显著更优才换，
   且当前行动带惯性加成。

2. **事务原子性** —— 需求是连续填充的，但资源只在行动**完成**时结算。
   角色吃饱就中途跑掉会导致食物永不减少。**带产出的行动必须不可中断**。

3. **驱动力不能归零** —— 经营类需求（家计）满值后角色会集体躺平坐吃山空，
   必须给它设一个不会归零的地板。

## 美术

角色不是手绘的，是**代码生成**的：在 10 倍超采样画布上用矢量图元作画，
降采样后吸附到固定调色板。改一个坐标就能重画，换一套调色板就是一个新角色。

好处是风格天然统一，且源文件极小（生成脚本 ~8KB，比几十张 PNG 小两个数量级）。
