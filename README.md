# sim-game

效用AI 驱动的生活模拟游戏原型 —— 借鉴《模拟人生》的需求驱动 AI
与《行会3》的生产链经济，两者共用同一套打分内核。

## 快速开始

```bash
open index.html      # 零依赖单文件，双击即可

npm run dev          # 或起服务：http://localhost:5173
npm run sprites      # 重新生成角色精灵（需 pillow numpy）
npm run check        # 冒烟测试（需 playwright）
```

## 目录

```
├── index.html         游戏本体（自包含单文件，精灵内嵌）
├── tools/             美术生成脚本与测试
├── assets/sprites/    生成产出的精灵图
└── docs/              设计与授权文档
```

## 玩法：一个主角 + 三个 AI

你直接操控 **小满**，其余三人由效用 AI 自主生活。

| 操作 | 作用 |
|---|---|
| `WASD` / 方向键 | 自由移动（连续位移，不是格子跳跃） |
| `E` / `空格` | 与脚下发光格子上的物件交互 |
| `ESC` | 中断当前行动 |
| `T` | 把主角托管给 AI（模拟人生式的"自由意志"） |

**移动会打断正在做的事**——这是刻意的：让"要不要坚持做完"成为一个决策。

### 交互菜单

走到 **NPC** 旁边（会出现青色光圈）按 `E`，弹出社交菜单：

| 动作 | 关系 | 说明 |
|---|---|---|
| 闲聊 | +3 | 安全牌 |
| 称赞 | +6 | 涨得快一点 |
| 开玩笑 | +1 / +9 | **关系 <30 时会冷场**，熟了才有效 |
| 深聊 | +14 | 需要关系 ≥ 40 |
| 送礼 | +20 | 花 15 金币 |
| 争吵 | −16 | 自己出口气，对方掉需求 |

关系变化会以**浮动文字**即时反馈。人的优先级高于物件——站在物件上但旁边有人时，
按 `E` 是找人说话。

**物件**有多种做法时也会弹菜单（床：睡觉 / 小憩；书架：看书 / 钻研；沙发：看电视 / 发呆），
只有一种做法的物件按 `E` 直接执行。变体动作只回一部分需求，也**不结算生产链产出**。

### 同一套打分，两种用途

效用 AI 对 NPC 是**决策**，对玩家是**建议**：

- NPC：算完分直接执行最高分的行动
- 玩家：算完分显示在面板上，你可以完全无视

这样玩家和 NPC 活在同一套规则里，但保留自主权。面板上点任意 NPC
可以看它此刻的打分排名——**你能看见它在想什么**。

> 无人值守跑模拟（比如冒烟测试）时必须先开托管，否则主角会站着饿死。
> 这不是 bug，是手动操控的必然结果。

## 核心设计：效用 AI + 智能物件

物件不被 AI「认识」——**物件主动广播自己能满足什么需求**。
角色只做一件事：给所有广播打分，挑最高的。

```
分数 = Σ(广播量 × 紧迫度^p × 性格权重) ÷ 距离折扣
```

加新玩法不用改 AI，只需在 `OBJ` 数组里加一条数据。

生产链靠**前置条件**自然串联，没有任何硬编码的步骤顺序：

```
林地(无条件) → 工作台(需木材≥2) → 摊位(需家具≥1)
            → 粮店(需金币≥24) → 炉灶(需食物≥2)
```

### 渲染插值：模拟步长 ≠ 渲染帧率

模拟走**固定步长**（0.25 模拟分钟一步，1x 时 16 步/秒），渲染走 **60fps**。
两者频率不同，如果直接拿模拟位置去画，每步的位移会在一帧内跳完——
逻辑完全正确，但看起来是「一格一格闪现」。

解决办法是每步记录上一次位置，渲染时按 `accSim / SIM_DT` 在两步之间插值：

```js
const alpha = accSim / SIM_DT;
s.rx = s.ppx + (s.px - s.ppx) * alpha;    // 渲染用 rx/ry，不是 px/py
```

实测：模拟位置每帧最大跳 9px、只有 26% 的帧在动；
插值后每帧最大 2.4px、98% 的帧都在动。

两个配套注意点：

- **瞬移必须同步 `ppx/ppy`**，否则角色会从旧位置"滑"过整张地图
- **深度排序也要用插值位置**，否则前后遮挡关系会抖

### 三个已经踩过的坑（改动 AI 前务必读）

1. **决策抖动** —— 不能用「需求低于阈值就打断」。两个需求同时告急时角色会无限
   横跳，一件也做不成。必须用**迟滞切换**：定期重估，新方案要显著更优才换，
   且当前行动带惯性加成。

2. **事务原子性** —— 需求是连续填充的，但资源只在行动**完成**时结算。
   角色吃饱就中途跑掉会导致食物永不减少。**带产出的行动必须不可中断**。

3. **驱动力不能归零** —— 经营类需求（家计）满值后角色会集体躺平坐吃山空，
   必须给它设一个不会归零的地板。

## 角色：参数化骨架

角色不是画出来的，是**算出来的**。一个角色由四层独立参数组合而成：

```
角色 = 体型(build) + 五官(face) + 发型(hair) + 服装(outfit) + 调色板(pal)
```

体型档案定义头身比、躯干尺寸、肢体粗细、驼背程度；五官用**头部归一化坐标**
（0~1）描述，再映射到实际头框——所以头身比怎么变，五官都自动落在正确位置。
这是能在同一套代码里做出萝莉、壮汉、老人的前提。

| 体型 | 头身比 | 特征 |
|---|---|---|
| `chibi` | ~2.2 | Q 版，大头圆身 |
| `slim`  | ~3.4 | 瘦长，接近原版饥荒的诡异感 |
| `stout` | ~2.6 | 矮壮宽肩 |
| `child` | ~2.4 | 小孩，整体缩小 |
| `elder` | ~3.0 | 佝偻前倾 |

可换模块：眼形 `round/almond/big/beady/smile/squint`、
眉形 `soft/flat/raised/thin/bushy`、嘴形 `smile/grin/pout/small/frown/line`、
发型 `twintail/long/short/bun/spiky/bald`、服装 `vest/skirt/apron`，
另有睫毛、胡子、鼻型、腮红开关。

现有阵容 8 人，覆盖从可爱到写实的谱系。游戏内默认用其中 4 个
（小满/柯林/老莫/芜青），刻意选了体型跨度最大的组合。

```bash
python3 tools/character_gen.py                    # 生成全部
python3 tools/character_gen.py --only 小满,老莫    # 只生成指定角色
```

### 改造型时的两个坑

1. **归一化坐标和像素坐标不能混用。** 五官函数收的是 0~1 的比例值，
   如果不小心把「像素偏移」传进去，特征会被推到头框外——曾经把老人的
   浓眉推成了头顶两只角，而且不报错。

2. **全局偏移要每个部件都吃到。** 身体整体下移时漏掉了眼睛，结果四个角色
   全变成「耷拉眼」，看着说不上哪里不对但就是很丧。程序化美术里
   凡是有全局变换，必须逐部件确认都应用了。

技术路线：8 倍超采样矢量作画 → 降采样 → 吸附固定调色板 → 加描边。
源文件不到 20KB，比等价的 PNG 小两个数量级。
