# 静街 · 数据规格 v0.1

> 这份文档的目的只有一个：**让 T1 / T3 / T7 能直接照着写，不用再回头做设计决定。**
>
> [策划](静街策划.md)定的是为什么，[任务拆解](静街任务拆解.md)定的是先做什么，
> 这里定的是**具体多少**。所有数字都是初值，标 `⚖` 的是明知道要靠探针调的。
>
> 单位约定：**格**（瓦片，24 世界像素）、**游戏分钟**、**游戏时**（1 游戏时 = 22.5 秒现实）。
>
> **两个时钟，别混**：天级的东西（身体六表、拐点、季节）走**游戏时间**；
> 瞬时的东西（冲刺、硬直、咬人间隔）走**现实秒** —— 玩家感受的是现实秒，
> 而 1 游戏分钟只有 0.375 秒现实，拿它表达"冲 20 秒"会变成 0.125 秒。
> 代码里的规矩：字段名带 `Sec` 的是现实秒，带 `Min` 的是游戏分钟。

## 〇、规格阶段对策划的三处修正

写规格时发现策划里有三个地方不够用，改了，理由记在这里：

1. **房型从 9 种加到 10 种**，补一个**加油站**。D14 断电后发电机是唯一电源，
   汽油必须有明确产地 —— 否则玩家会在整张地图上瞎找，这是纯粹的浪费。
2. **移速定成「跑得掉，但很吵」**：僵尸追击 0.75 格/分，玩家走 0.6、跑 1.5。
   于是**走不掉、跑得掉**，而跑的噪音半径是 7。

   > **这条后来推翻了（见下）。** 实际玩下来，全镇 320 只、每一只都比你走得快，
   > 结果是你永远只能跑 —— 于是跑的噪音从"一个选择"变成了"过路费"。
   > **一个你必须一直付的代价不是决策**，它把决策 2 自己架空了。
   > 现行红线是 **蹲 0.30 < 追击 0.45 < 走 0.60 < 跑 1.50 < 冲刺 1.70**。
3. **负重用两个量**：格（体积）管装不装得下，公斤管走不走得快。
   只用一个量做不出"背了一床被子但很轻"和"兜里两罐汽油"的区别。

### 房间语法

```
房间(面积, 类型) → 摆家具 + 摆容器
  客厅   → 沙发 ×1, 茶几 ×1, 电视柜(容器) ×1, 书架(容器) 40%
  厨房   → 灶台 ×1, 水槽(水源) ×1, 冰箱(容器) ×1, 橱柜(容器) ×2
  卧室   → 床 ×1, 衣柜(容器) ×1, 床头柜(容器) ×1
  卫生间 → 马桶(水源) ×1, 药柜(容器) ×1, 浴缸(水源) ×1
  店面   → 货架(容器) ×n（n = 面积/6）, 收银台(容器) ×1
  库房   → 木箱(容器) ×n（n = 面积/8）
  枪械柜 → 枪柜(容器·锁) ×2
```

**硬约束（红线，来自市井 T30）**：每栋房**至少两条出路**，且每间房至少一扇
窗或门通向另一间。生成后跑一次连通性检查，不满足就重摇这栋。

## 三、噪音与存量（T3）

### 噪音事件

```js
noise(pos, r, durSec)   // r 以格计
```

每只僵尸在自己的 tick 里判：`d(pos, z) < r * atten(墙层数) * env`

| 系数 | 值 |
|---|---|
| `atten(n)` | `0.6^n`（n = 视线上被墙挡的层数，走夜港的 DDA） |
| `env` 雨 | ×0.5 |
| `env` 夜 | ×1.4 |
| 超重 | ×1.5 |

听到的僵尸：转为**追击**，目标是噪音源坐标，持续 30 游戏分钟；
到了没看见人就改**游荡**，且**留在原地附近** —— 这是"一枪把一条街的僵尸永久搬过来"的实现。

### 移速（写死的三角关系）

| | 格/游戏分钟 | 格/现实秒 | 噪音半径 |
|---|---|---|---|
| 僵尸 游荡 | 0.18 | 0.48 | — |
| 玩家 蹲行 | 0.30 | 0.80 | 0 |
| **僵尸 追击** | **0.45** | **1.20** | — |
| 玩家 走 | 0.60 | 1.60 | 2 |
| 玩家 跑 | 1.50 | 4.00 | 7 |
| 冲刺尸 冲刺 | 1.70 | 4.53 | — |

**这几个数之间的关系比它们各自的值重要得多** `⚖`。被一只追着、起始 3 格，十秒之后：

| | 十秒后的间距 | 意味着 |
|---|---|---|
| 蹲行 | **0.0**（八秒被追上） | 蹲着被发现就得站起来 |
| 走 | 7.0 | 走得开一只，安静；丢失目标要 11.3 秒，正好够 |
| 跑 | 33.2 | 急救 —— 但噪音 7，把这条街都喊醒 |

**「跑」因此是你自己选的，不是被迫的。** 这才是决策 2 想要的那个选择：
安静地慢慢挪开，还是花噪音换距离。

`chase` 在代码里直接引 `SPEED.僵尸追击`，不另写数 ——
同一个速度写两个地方，改了一处另一处不跟（已经犯过一次）。

游荡原来写 0.35，折成现实秒是 0.93 格/秒 —— **那是慢跑，不是拖着脚走**，
手玩第一反应就是"怪物走路太快"。改成 0.18（0.48 格/秒），
明显慢过玩家走的 1.60。**拖着脚的和扑上来的必须是两个速度**，
不然"远处那群还没发现我"和"这只已经盯上我了"在画面上分不出来。

### 街区热度与迁移

每个噪音事件累进它所在街区的热度：

```js
heat[i] += r * durSec / 100
```

**每天 04:00 结算一次迁移**，只沿邻接表：

```js
for (每条邻接边 i-j) {
  const d = heat[j] - heat[i];
  if (d <= 0) continue;
  let f = K * pop[i] * d / (heat[i] + heat[j] + 1);   // K = 0.25
  f = Math.min(f, pop[i] * 0.30);                     // 一天最多走掉三成
  pop[i] -= f; pop[j] += f;
}
for (每个区 i) heat[i] *= 0.4;                        // 记忆衰减
```

外加**扩散项**：密度差超过 2 倍的相邻区，每天平掉差额的 8%
（否则清空的区永远空着，玩家会发现"一次清街换终身安全"）。

### 清街与浪潮

- `pop[i] / init[i] < 0.10` → `lock[i] = 7`（天），锁定期内不接收迁移与扩散
- D30 / D60 浪潮：`+WAVE_N`（**70**），从 F 区的两条出镇路压进来，**提前一天可见**
  （远处鸟群 + 夜里的声音）
- **渗入**：每天 `1 + rnd(3)` 只从两条出镇路进来，**累计上限 `SEEP_CAP = 60`**。
  它让"安静"需要维护，但不是给存量补货 —— 上限由校验器钉住
- 镇子真的会被清空，那是一种结局（[ADR-0001](adr/0001-zombie-stock-is-finite.md)）
- **守恒是正确性底线**：`Σpop == 街区表初值和 + WAVE_N × 浪潮次数 + 渗入 − 累计击杀`
  （初值不许写死成 320 —— 做 MVP 切片时表里就不是 320 了）

### 僵尸个体

| 属性 | 白天 | 夜 |
|---|---|---|
| 视距 | 6 格 | 2.4 格 |
| 视锥 | ±60°（按**朝向**算，朝向跟着它实际走的方向） | ±60° |
| 玩家蹲行时视距 | ×0.7 | ×0.7 |
| 贴身无条件发现 | 1.2 格 | 1.2 格 |
| 听觉倍率 | 1.0 | 1.4 |

**视锥不是摆设**：背对着你的那只，4 格外看不见你；贴到 1.2 格内则不管朝哪都会发现 ——
不然可以贴着它的脸站一整天。蹲行把它的视距打七折，这是"蹲行噪音 0"之外
潜行的第二个支点。

**游荡的目标要留着走一段**（8~22 游戏分钟换一次方向），撞墙了立刻换。
第一版每帧重摇一个随机目标，结果一屏的僵尸在**原地发抖**，不是在走。

### 近战（T6）

五件武器差的是**攻速 × 硬直 × 够得着多远 × 耐久**，不是伤害数字：
伤害一律 1，只有斧是 2 —— 血量表本来就是按"几次斧击"写的。

| 武器 | 伤害 | 挥(秒) | 硬直(秒) | 够得着 | 耐久 | 打退 |
|---|---|---|---|---|---|---|
| 空手 | 0 | .45 | .30 | 1.0 | ∞ | .6 |
| 菜刀 | 1 | **.35** | .20 | 1.0 | **80** | .2 |
| 锤 | 1 | .55 | .30 | 1.1 | 300 | .4 |
| 撬棍 | 1 | .75 | .45 | 1.4 | 400 | .7 |
| 长矛 | 1 | .85 | .50 | **2.2** | 120 | .3 |
| 斧 | **2** | .95 | **.60** | 1.3 | 220 | .9 |

（挥/硬直是**现实秒**。空手打不掉血，只能推开 —— 得找件家伙。）

规则：

- **一次只结算一个目标**：扇形 ±75° 内最近的那只。规则是"别被围"，不是"一刀一片"
- **收手期间挪不动**（硬直）—— 这是近战的全部代价，也是"三只以上必死"的来源
- **挥空更吵**（噪音 6 对 4）：你没打着，但街上听见了
- **蹲着打翻倍**：背后偷袭的奖励，也是潜行的第三个支点
- **打退半步**：打中会把它推开，于是连打第二下常常够不着 —— 间距是自己制造的
- **打倒 ≠ 打死**：血剩 1 时有一半概率倒地，**12~20 秒后自己爬起来**；
  **倒地的可以补刀，而且伤害翻倍** —— 打倒是机会，不是十几秒的锁
  （第一版 `swing()` 跳过倒地目标，于是你把它打趴下之后只能挥空）
- 手臂伤压近战命中；**恐慌不管近战**（踉跄链已经在罚被围了）

**推开（右键 / `Q` / 手机长按挥键）**：范围 ±112°、2 格内全部推开 1.5 格，
不掉血、不看武器，**并且把「被围」的计时清零**。硬直 0.35 秒。

这是被围那一秒半里**唯一的答案**。第一版没有它，而挥击一次只打一只、还带硬直 ——
"三只按住你 1.5 秒"于是是个无解的一秒半，手玩的原话是"一下就被打死了"。
推完它们 0.9 秒后又围上来：**推是为了跑或者进门，不是为了赢**。

**踉跄不挡推**（挡挥）。踉跄是"被挤得挥不开"，而推正是用来解它的 ——
第一版把它也挡进来了，等于把唯一的解法锁在了它要解的那个状态里。

**站位**：僵尸之间最小间距 `SEP = 0.72`，僵尸与玩家之间 `SEP_P = 0.55`（**硬钳位**，不是软力）。
第一版两条都没有，追击时它们全都收敛到玩家**同一个点**、叠成一摞，
于是"三只贴身"几乎必然发生。现在它们围成一圈，能同时贴到你的就那么两三只。

### 打击手感：五件东西缺一不可

「打僵尸手感很差」不是一个问题，是五件东西全缺。**分开做每件都看不出来，一起做才有。**

| | 做法 |
|---|---|
| **结算时机** | 挥到 **45%** 才命中（`strikeAt = swingSec × .55`）。第一版在按下那一瞬就算完了，而精灵才刚抬手 —— **你先拿到结果再看见动作，顺序是反的** |
| **顿帧** | 命中冻 **60ms**、打死 **110ms**。冻住 `update()`，`render()` 照跑 —— 最便宜也最有效的"打到了" |
| **震屏** | 命中 1.6 像素、打死 3.2、断武器 2.2、推开 1.2；按 `dt×14` 衰减，偏移取整 |
| **受击闪白** | 被打的那只白闪 0.13 秒 |
| **音效** | 五种实时合成：挥空 / 命中 / 致命 / 断裂 / 推开。命中和致命再叠一个低频闷响给重量 |

**两条结构上的讲究**：

1. **特效计时走 `tickFX(dt)`，不走 `update(dt)`** —— 顿帧冻住的正是 `update`，
   把 `HITSTOP` 放进去就永远解不了冻。特效是真实时间上的东西，不受冻结影响。
2. **视觉与音频的随机单开一条 `vrnd`** —— 震屏抖动和噪声缓冲不能用游戏的 `rnd()`，
   那会消耗种子序列，`?seed=` 当场不可复现。校验器钉了一条：
   **响 30 次音效之后，同种子的结果必须一模一样**。

音效走 WebAudio 实时合成（零外部资源，和霓虹一条路）：噪声缓冲 + 带通/低通滤波器扫频，
命中那两种再叠一个 sine 从 170Hz 滑到 45Hz。`M` 键静音。

### 动作感：六件 + 处决

「怎么更像动作类游戏」那一轮。**只做不改变类型的那一半** ——
闪避和体力明确不做，它们会让战斗变成解决问题的主要手段，而
[决策 9](静街策划.md) 是「规则是别被围，逃跑永远正确」。

| | 做法 |
|---|---|
| **扫掠判定** | 从挥到 45% 起**每帧连续判定**，一直扫到挥完。第一版只在那一瞬做一次锥形检测 —— 擦身而过、或那一帧刚好走出锥形的目标全漏掉，打得中打不中像抽签 |
| **出手垫步** | 攻击时人往朝向前移 **0.22 格**。重心跟着武器走 |
| **音高随机** | `playbackRate ±8%`。每一下声音一样，连打就是机关枪 |
| **受击踉跄** | 挨打的那只往**挨打的方向**退 3 像素、歪 1 像素，持续 0.22s |
| **取消窗口** | 收手的最后 **38%** 可以接下一击或接推开 |
| **连击** | 踩在取消窗口里再按，挥击与硬直都 ×0.7（斧 0.95s → 0.66s） |
| **处决** | 对**倒地**目标的独立路径：不看血量直接结果、顿帧 **180ms**、震屏 4.2、血迹拉满 3、**第 7 列独立姿势** |

**取消窗口是动作游戏的核心语法** —— 它把硬直从"惩罚"变成"要管理的资源"：
砍完一刀立刻取消成推开，推开一圈再跑，这是一套可以练的操作。

处决之所以值得做，是因为它**奖励的是已有打法**（先打倒再补，T6 就有的机制），
不是新开一条资源。图集因此从 24 列涨到 **28 列**（4 向 × 7）。

### 背包里能对物品做什么

「从背包里怎么操作物品」查出来的真答案是：**大部分都不能**。

**最大的一个洞：`treat()` 只定义、从没被调用过。**
被咬了之后**根本没有任何办法包扎** —— 绷带、酒精、针线在包里是死重，
而 `WOUND` 表里那四步处理链（清洗→消毒→缝合→包扎）一次都没跑过。

修法上有个判断：**伤口不该做成"物品的用法"。**
它是**一道有顺序的工序** —— 咬要四步，抓只要两步，少一步这条伤就没处理完。
做成物品用法的话，玩家得自己记住顺序、自己挑对东西。
所以背包页把**伤口单独列在最前面**，一行一条伤，一次只做下一步：

```
右手 咬                    清洗      ← 绿：包里有瓶装水
左腿 抓                    缺绷带     ← 红：缺什么直接写出来
```

**动作要写成动词，不是一律「用」**：吃 / 喝 / 穿 / 背上 / 拿起 / · 手上。
看一眼就知道点下去会发生什么。

处理伤口的东西没有"直接用"这回事，但也不能只显示重量（那看着像一件没用的东西）——
写成 `消毒用` / `缝合用` / `包扎用`，告诉你为什么要背着它。

**每行右边留一个「丢」。** 以前只有开着容器才能放回，
野外背多了就只能站着 —— 这不合理。

> **平衡**：把包扎接上、并且教会机器人用它之后，探针数字**一点没动**（仍是 2.3 天）。
> 因为它**活不到失血要紧的时候** —— 2.3 天就渴死了。
> 「失血」这个死因以前一直是在演"没人会止血"，现在它至少是可修的了，
> 但要看到效果得先有 T8 开场。

### 走路的拍子：四帧等长就是节拍器

「动作僵硬」有两半，我一直只在修**画得好不好**那一半。另一半是**时间分配**，
和美术完全无关：

```js
const nf = Math.floor(P.walkT) & 3;      // ← 四帧各占 25%，这是节拍器
```

真实的走路里，**着地**那两帧脚踩实了、身体压在这条腿上，停留久；
**腾空**那两帧腿从后面荡到前面，过得快。

| | 帧 0 着地 | 帧 1 腾空 | 帧 2 着地 | 帧 3 腾空 | 着地合计 |
|---|---|---|---|---|---|
| 改前 | 25% | 25% | 25% | 25% | 50% |
| **正面/背面** | 28% | 22% | 28% | 22% | 56% |
| **侧面** | **34%** | 16% | **34%** | 16% | **68%** |
| **跑** | 27% | 23% | 27% | 23% | 54% |

**正面和侧面不能用同一张表** —— 这是第一版犯的错，手玩报上来「动作太慢」。

量出来的原因很硬：

| 相邻帧差异 | 0↔1 | 1↔2 | 2↔3 | 3↔0 | **0↔2（两个着地帧之间）** |
|---|---|---|---|---|---|
| 正面 | 2292 | 2192 | 2042 | 2160 | **792** |
| 侧面 | 2288 | 2536 | 2276 | 1856 | **2396** |

正面视角下两个着地帧**本来就像**（真实的正面行走，腿的前后运动大半被身体挡住）。
再让它们各占 32%，就是 **64% 的时间画面几乎不动、然后两下快闪** ——
那是"发粘"，不是"有重量"。

> **教训**：拉长一帧的停留时间，前提是**这一帧和邻帧看得出区别**。
> 区别小的帧拉长，只会把"静止"拉长。

步频也提了一档：走 5.4 → 6.4（2.7 → 3.2 步/秒），跑 9 → 10.5。

### 挥一下要多久

手玩报「动作太慢」的另一半，量出来是真的：

| | 改前 | 改后 |
|---|---|---|
| 菜刀 | 0.55s | **0.39s** |
| 锤 | 0.85s | 0.60s |
| 撬棍 | **1.20s** | **0.85s** |
| 长矛 | 1.35s | 0.95s |
| 斧 | **1.55s** | **1.09s** |

整体砍三成，**轻重次序不动**（斧仍然最重最慢）。
探针跑完死因分布和存活天数**一点没变** —— 机器人活不到战斗要紧的时候。



> 这条判断来自量 LPC 的动捕数据：它的相邻帧差异是 **484/392/496/532**（忽大忽小），
> 我们等长的版本是 **404/412/412/404**。差的就是这个。
> **换不换美术，这一条都该做** —— 它是纯赚的。

**侧面走动时上身往前压一格**。直上直下地平移是"滑行"不是走路，
而这一格不需要任何新美术。只给侧面 —— 正面/背面往哪边压都不对。
**贴花要跟着压**，不跟的话武器会从手里飞出去。

### 装备：以前没有这回事

「撬棍怎么装备」答不上来，是因为**没有答案**：`weapon()` 从一张写死的优先级表
`['斧','撬棍','长矛','锤','菜刀']` 里挑第一个你身上有的。你不能选，
也没有任何地方告诉你它是怎么挑的。

现在 `P.wep` 是你**选**的那把，规则三条：

- 没选过 → 仍按优先级自动挑（**开局不用先做家务**）
- 再点一次 → 交回自动（不会把自己锁死在一把烂武器上）
- 选中的那把丢了/断了 → 自动退回优先级（不会变成空手）

背包页每行右边写的是**"点下去会发生什么"**（`拿起` / `· 手上` / `用` / `放回`），
不是规格。几格几公斤只在柜子那一页有用 —— 那是"装不装得下"的依据。

**「装备了武器，人物没变化」查出来是两层**：

1. **贴花图集生成了却从没用过**。`survivors_decal96.png` 出了十七行
   （五把武器 + 背包 + 冬装 + 血渍 + 绷带 + 冻伤），但只写到 `assets/`，
   **从没嵌回游戏、`decal` 在游戏代码里一次都没出现**。
2. 武器贴花还按**旧的 32×42 坐标**画。人换成 48×63 之后它落在小臂中段，
   而且撬棍是"1 像素宽、8 像素高的一条线" —— 游戏里差 **4 个逻辑像素**。

修完之后端到端量（噪声底 0）：

| 对比 | 改前 | 改后 |
|---|---|---|
| 空手 vs 撬棍 | 36 | **152** |
| 空手 vs 斧 | — | 236 |
| 撬棍 vs 斧 | — | 204 |

**贴花和底板必须用同一套位移**。以前贴花自己算手的位置、底板另算一套，
于是"手在动而家伙不动，比不动还怪"。现在 `handAt(dir, slot)` 从
`WALK_F/WALK_P/ATK_*` 加 `PIVOT.armR` 算出来，两边共用。
断言逐帧检查武器像素有九成落在手心 ±6/±18 之内。

**手机上原来没法开背包** —— Tab 在手机上不存在，于是也就**没法换武器**。补了 `#bP`。

### 画在画布上的 UI 要按【看得见的那一段】排版

布局为了"铺满"允许画布比视口宽最多一格。而浏览器在子元素超宽时会把
**居中退化成靠左** —— 于是多出来的部分全在右边。
320px 的屏上，面板右边的「装不下」「关闭」直接被切掉。

所以 `visX()` 给出可见区间，面板、小地图（靠右）、提示条（居中）都按它排。

**提示条的宽度要量，不能按字数猜**：`长度 × 9` 对中英混排是错的，而且没有上限。

### 桩不像真 DOM，第四、五次

| 第几次 | 缺什么 | 后果 |
|---|---|---|
| 一~三 | `Image` / `AudioContext` / `playbackRate` | 崩，或者那条行为没法测 |
| 四 | `measureText` 固定返回 10 | 所有"排版会不会超出"的断言**全是假绿**：33 个字量出来 22 像素 |
| 五 | `getBoundingClientRect` 固定返回 960×640 | **最阴的假绿**：面板和断言用同一个错值，两边"一致"、双双错 |

第五次那条值得记住：**当断言和被测代码引用同一个来源不明的数，它们会一起错，而且是绿的。**
桩里凡是"尺寸"类的返回值，都得跟着真实来源走（这里是 `style.width`，`fit()` 设的就是它）。

### 搜刮：开不等于拿

原来的搜刮是：靠近按互动 → **东西全自动进包** → 然后才弹一个面板，
把背包最后十件用顿号连成一串。那不是操作界面，是**事后通知**，
而且你没有任何选择 —— "拿什么"这个决定根本不存在。

拆成三件事：`openContainer` / `takeItem` / `putItem`。
容器**翻过之后照样能开**，里面剩下的东西还在 —— 它就是你的临时储藏点。

**「格」这一半以前根本没实现**，只有公斤。于是背包是无底洞。
补上之后规格第三节那句话才成立：**格管装不装得下，公斤管走不走得快**。

| | |
|---|---|
| 腰包 | 6 格 |
| 穿上背包 | +12 格 |
| ≤15kg | 正常 |
| 15~25kg | 超重：移速 ×0.65、噪音 ×1.5 |
| >25kg | **走不动**（不是走得慢）|

>25kg 不会把人困死：你只可能在容器边上拿到这个重量，而面板能**放回**。

**补格数上限时照出来的两个真 bug**：

1. **背包穿不上**。`useItem('背包')` 三个分支一个都不沾，原样塞回包里 ——
   "穿上 +12 格"这条规则一直是死的。
2. **木匠开局就超格**。锤1+木板2+木板2+钉1+钉1 = **7 格**，而腰包只有 6 ——
   一进游戏什么都捡不了。给了他一个背包（木匠本来就背工具袋）。

**画在画布上的 UI 必须自己做命中测试** —— 它不是 DOM，浏览器不会帮你派发点击。
面板每帧重建一张可点区域表，触屏和鼠标都先问它。

> **平衡**：格数上限对探针**一点影响都没有**（2.3 天，前后一模一样）——
> 机器人只翻 4.5% 的容器、拿到就吃，根本碰不到 6 格。
> 对真正会囤东西的人才会咬。
> 探针那 55% 脱水和 2.3 天是**早就有的**，T8 开场没做，不是这次改出来的。

### 手机上的界面：先看得见自己

手机上侧栏是藏起来的，**所有信息都压在画面上**，所以每一条都得自己带底板。
手玩报上来"交互 UI 都不好看"，拆开是六件事：

| 现象 | 根子 |
|---|---|
| **人被自己的按钮埋了** | 镜头顶死在地图下边界。开局就在镇外南缘，所以第一眼就撞上 |
| 提示条被「挥」压住一半 | `CH - 96` 写死，按钮实际占的比 96 多 |
| 四条状态表的字叠成一团 | 行距 7px 而汉字 8px 高 |
| 「饥 渴 累 温」四个字在表**右边老远** | 对不上是哪条；四条还一个颜色 |
| 浮层一半藏在按钮后面，**关不掉** | 面板高度写死 120、y 钉在画布底下；手机上没有 Esc |
| **根本打不开日志** | J 键在手机上不存在，按钮只有挥/互动/跑/蹲 |

**镜头允许越过地图下边界**（`CH × 0.26`）是关键那一条：
贴着南缘站时，人从屏幕 **88% → 61%**。越界只给触屏 ——
桌面没有按钮挡人，没必要在地图外面留一条黑边。

其余的规矩：

- **字要有底板**。没底板的字压在浅色地面上读不出来。
- **行距必须大于字高**。
- **表的颜色也得低饱和**。四条彩带比地图还抢眼；高饱和只留给僵尸的眼睛和"要出事了"。
- **浮层要把底下压暗**，并且**收起触屏控件** —— 不收的话按钮盖在面板上。
- **浮层高度跟着内容走**。写死高度的面板，一行也是那么高，九行也是那么高。
- **浮层开着时不再画提示条** —— 日志里就是那句话，两层写同一句是自己跟自己打架。
- **按钮要分档**。四个一样大的圆饼没有主次：挥最大最顺手、互动次之、跑/蹲最小。

**没做**：桌面侧栏仍是一列等重的细条，没有分组也没有语义色。

### 人物：手摆底板 + 部件位移

参数化生成器到顶了（见下一节「弧度」）。换成**手摆底板**：
头、躯干、四肢的轮廓和明暗一格一格摆出来，写法是 `[行, 起始x, 串]`。
**不数点** —— 上一版数前导点，一行少一个字符就整张图错位。

**分辨率提一档**：逻辑 32×42 ×3 → **48×63 ×2**。
`32×3 = 96 = 48×2`，`42×3 = 126 = 63×2` —— **设备像素一个不涨，图集尺寸不变**，
但同样的地方塞进 2.25 倍的美术信息。"糊"的根源是 art 像素太少，不是画得不好。
也因为设备尺寸没变，**游戏侧一行都不用改**就拿到了这份细节。

**28 帧不是手摆 28 张独立的图**（那必然前后不一致），而是把底板拆成部件，
每帧只给部件一个位移。部件靠「行号 + 起始 x」认出来，不用逐条打标签。

| 规则 | 为什么 |
|---|---|
| 手臂绕**肩**转、腿绕**胯**转 | 整条平移会把肢体从躯干上扯下来 |
| 支点缩放用**向零取整**，不是四舍五入 | `round(5×0.125)=1` 会让紧贴躯干的肩头挪一格 —— 一格就是一道缝 |
| 手臂、腿、靴子**跟着躯干走**（父子关系） | 各走各的，躯干上抬而大腿顶端不动，胯就裂开 |
| 垂直位移不同的行之间要**补上跳过的目标行** | 不补就成一条虚线 |
| 贴地压暗**只作用于脚底那几行** | 对整个轮廓的下沿都压，头发底下会多一道线，头像是断开的 |

**底板只定姿势，颜色仍然是生成的** —— 字母色号映射到每个角色自己的
发色/肤色/上衣/裤子/鞋，16 行的变化一个不少。
代价：发型不再变（只变颜色 + 帽子）。

**不变量**：28 帧每帧都必须是**一个四连通块**。
这条今天抓到四个真 bug（手臂飞出去、虚线手臂、胯部裂开、肩头断一格）。

### 断言的证据要"只可能属于那个部件"

"背面不该有脸"这条错过**两次**：

1. 拿「暗像素」当脸 → **黑头发也暗**
2. 拿「肤色」当脸 → **浅棕色头发也满足** `r>g>b 且 r>120`

第三版拿**眼白**：它是整张图上唯一不过 `grade()` 的颜色，最亮，头发衣服都到不了。

同一轮还修了两条**写死坐标**的断言（脸框死在 `x11~20`、躯干取样在 `x10/x21`）。
人物一改尺寸，采样区就落到头发上或者空气里。改成按导出的常数扫、
或者**每行自己找最左最右再往里收一格**。

### 弧度：像素画里的"曲线"是阶梯

「完全直线，没有任何弧度」查出来的事实：`draw()` 里**一条斜线都没有**，
全是 `px.rect(x0,y0,x1,y1)` —— 头是方盒、躯干是等宽柱、胳膊腿是直条。

**形状**：加了 `px.shape(cx, y0, halves, c)`，按**每行半宽**画 ——
像素画里的"弧度"就是靠一格一格的阶梯做出来的。

| 部位 | 半宽序列 |
|---|---|
| 头 | `[3,4,5,5,5,5,5,4,4,3,2]`（顶收两格、下巴收三格） |
| 躯干 | `ramp(高, 肩半宽, 肩半宽−1, bulge .6)` —— 收腰，中段微鼓 |
| 腿 | 脚踝往外侧收一格 |
| 胳膊 | 肩头宽一格、下半截往身体收一格 |

**运动**：腿和手都改成走**椭圆轨迹**，不是直上直下 ——

```
LEG_ARC = 迈到前面 → 抬起来往前送 → 蹬到后面 → 抬起来往回收
ARM_ARC = 手在后下 → 中 → 手在前上 → 中
```

第一版只有 y 方向的 ±2，所以脚是"上下点"不是"迈步"。
另外**正面和侧面的腿不是一回事**：侧面前后大幅摆动，正面只是轻微一开一合 ——
照侧面的幅度画，正面就成了劈叉。

相邻帧差异 373~400 → **440~459**。

> **诚实的进度**：头和躯干的轮廓、腿的轨迹确实有弧度了，
> 但**胳膊仍然读成横在胸前的一道条**。这是参数化生成器的天花板 ——
> 每个部件都是"带规则的矩形"，而手臂在正面视角需要的是**逐像素挑位置**。
> 下一档只有两条路：把玩家这一行 28 帧【手摆】（霓虹 GRID 那条路），或者外部美术。

### 动作的拍子：别让一拍当三拍用

「人物动作僵硬」查出四条，其中一条是**真 bug**：

**攻击只有一拍。** 第一版 `P.swing > 0` 就直接显示"出手"姿势 ——
斧子那 0.95 秒里**手一直是伸出去的**，然后才命中。没有预备动作。

现在是三拍，而且**不需要新帧**（预备复用"收手"那张，胳膊半收正好是抡起来的样子）：

| 阶段 | 列 |
|---|---|
| 按下 → 结算前（`strikeAt > 0`） | **5 预备** |
| 结算 → 挥完 | **4 出手** |
| 收手（`recover > 0`） | **5 收手** |
| 处决 | 6 |
| 其余 | 走路 0~3 |

抽成 `poseSlot()` 纯函数，校验器逐拍钉。

另外三条：

| | 做法 |
|---|---|
| **待机呼吸** | 站着不动时整个人 1 像素起伏（`ANIM_T` 驱动）。**绝对静止是"僵硬"最明显的来源**，而这个不用加任何一帧 |
| **加减速** | 输入向量指数平滑（`1-e^(-dt·16)`，约 0.12 秒过渡）。瞬间起步、瞬间停死是僵硬的另一半 |
| **步频跟实际速度** | 不是跟按键：慢慢挪的时候腿也慢慢迈。蹲 3.4 / 走 5.4 / 跑 9 帧每秒，再乘当前速度比例 |

**加减速只加在主循环里，不动 `move()` 的语义** ——
探针和验收都按"一次调用 = 一个游戏分钟"在用它，改了它整套速度断言就全假红。

顺带加了**脚步声**（落在触地的第 0、2 帧上）。
`ANIM_T` 跟 `tickFX` 走，所以**顿帧冻住的是世界，不是呼吸**。

**踉跄链**：贴身 1.4 格内

| 几只 | 后果 |
|---|---|
| 2 只 | 随机进入**踉跄** 0.6 秒，动不了也挥不了 |
| 3 只 | 按住你 **1.5 秒**就死（跑起来不算） |

一闪而过不死、按住才死 —— 这样"被围"这个死因读得出过程，
而不是走过去就没了。

### 僵尸和玩家走的不是同一套可通行

| 瓦片 | 玩家 | 僵尸 |
|---|---|---|
| 墙 / 家具 / 树 / 栅栏 | ✗ | ✗ |
| 门（开） | ✓ | ✓ |
| 门（关 / 锁） | 关：开门 / 锁：撬（噪音 8） | ✗ |
| **窗** | **✓ 翻（第一次破窗噪音 12，之后 4）** | **✗** |
| **板窗** | ✗（要先拆） | ✗ |

**第一版两边共用一个 `passable()`** —— 于是你翻窗进屋、它们跟着翻窗进屋，
门不关就直接跟进来。手玩报上来的原话是「进房子也没用」，而它连带制造了
「跑不过怪物」的错觉：空地上跑，每秒净拉开 2 格（实测），
但**没有任何地方能甩掉它们**，于是只能一直跑，跑又很吵，越跑越多。

僵尸现在不会开门、不会翻窗。**拆门拆板是 T9 的事** ——
那时才该给它们这个动作，而且要有进度和声音（夜里听见拆板声是本作最好的恐怖来源）。
在那之前，"关上门"就是一个干净的逃生答案，这正是"进房子有用"该有的样子。

### 逻辑分辨率跟着视口宽高比走（触屏）

桌面固定 17×12 格，整数放大（3 / 2 / 1 倍）。触屏不一样：

```
倍率 s = 2                                   // 一格 48 CSS 像素，人物看得清
若 参考框 7×10 按这个倍率放不下 → s = 1        // 规则是"装得下"，不是"裁掉"
VW = clamp(ceil(视口宽 / (24·s)), 7, 34)
VH = clamp(ceil(视口高 / (24·s)), 10, 28)
```

`ceil` 保证**铺满**（多出来的不超过一格），下限保证**参考框永远完整装在里面**
（霓虹教训五）。实测：

| 屏幕 | 格数 × 倍率 | 多出 |
|---|---|---|
| 375×812 竖 | 8×17 ×2 | 9×4 |
| 812×375 横 | 34×16 ×1 | 4×9 |
| 360×640 | 8×14 ×2 | 24×32 |
| 768×1024 平板 | 16×22 ×2 | 0×32 |
| 320×480 | 14×20 ×1 | 16×0 |

第一版有两个错：**上限定成 16 格**（横屏 812 铺不满），
以及**参考框放不下时直接裁**（横屏下面整条 105 像素没了）。

触屏上侧栏是收起来的，六表、时间、提示条全部画在画布上；
镜头把人放在 **40% 高度**而不是正中 —— 底下那一条是拇指和按钮的地盘。
CSS 断点也改成看**形状**不只看宽度：812×375 的横屏窗口原来被当成"窄屏"竖排，
画布挤在上面、面板占满下面。

### 视野与记忆迷雾（**默认关**）

> **试玩之后关掉了**，`?fog=1` 能开回来。原话是"太丑了，去掉迷雾"。
> 原因写在 [ADR-0003](adr/0003-vision-not-isometry.md) 的后续一节：
> 在 17×12 的俯视图上把大半个屏幕压暗去饱和，**丢掉的可读性比换来的气氛多** ——
> PZ 撑得住那么暗，是因为它的视野更大、瓦片信息更密。我们还没有那个密度。
>
> 雾关着时，僵尸退回**只按视线剔除**（不按视锥）——
> 地形全看得见却看不见背后的僵尸，会很错乱。

参数留档如下。

| | 值 |
|---|---|
| 视锥 | 朝向 ±75°（合 150°） |
| 视距 | 白天 16 格 / 夜里 6 格 |
| 近身圈 | 2.5 格，**不看朝向** |
| 遮挡 | `losBlocked === 0` 才算看得见 |

三档显示：

| 档 | 画法 |
|---|---|
| 看见 | 原色 |
| 记得 | 压暗 34% + 往灰里靠 10%（**不随时间衰减**） |
| 从没见过 | `#0a0b0c` 纯黑 |

- **地形见过就一直记得；僵尸不进记忆层** —— 记了就成雷达了
- 记忆层与血迹都写在**镇子档**里：上一个你探过的地方、清过的街，下一局还亮着
- 白天视距 16 格，所以雾真正起作用的地方是：**你没进过的屋子里面是黑的**，以及夜里

第一版两个数调错了：记得那一档压 45%+16%，整张图糊成一片
（"记得"要的是"看得清但没有当下感"）；屋顶和地板都是中间调的棕，墙和地分不出来
（屋顶从上面看该是**冷灰** `104,104,100`，地板是**暖棕** `108,94,74`）。

### 墙是一条线，不是一块砖

第一版一格画一块 24×24 的实心砖，手玩报了两条，其实是**同一个原因**：

> 「墙很丑，很大一块」·「竖着的墙一节一节的」

- **很大一块** —— 墙占满整格，房子读成厚板而不是房间
- **一节一节** —— 每格各画各的顶边受光和底边影，竖着一串就每 24 像素一道横缝

改成**认邻居的细墙**（自动拼接）：

| | 做法 |
|---|---|
| 墙厚 | `WTH = 9` 世界像素（不到半格） |
| 掩码 | `wallMask(tx,ty)`：上/下/右/左是不是"墙一类"（墙 / 门 / 窗 / 板窗都算） |
| 带子 | 有邻居就往那个方向伸满，接上；孤格只画中间一小块 |
| 受光边 | **只画在上面没有墙的那一侧** |
| 立面 + 影 | **只画在下面没有墙的那一侧** |
| 墙脚 | 挨着地板就铺地板，否则铺草 —— 细墙会露出两边的地面 |

于是一段竖墙是**一条完整的带子**，不是一摞砖。
门算"墙一类"是必须的，否则墙会在门口断开。

### 盒子的画法：顶面要【抬起来】

手玩报的下一条是「房屋改成 2.5D 的，现在还是看着俯视」。查出来是我自己的回归：
**改细墙的时候把顶面的抬升丢了** —— 顶面画在原地、立面补在下面，等于把盒子拍扁。

正确的投影：**轮廓 = footprint ∪（footprint 上移 H）**

```
boxGeom(y, h, H) = { topY: y - H,        // 顶面：整体上移 H
                     faceY: y + h - H,   // 立面：底边往上 H
                     baseY: y + h }      // 脚下
```

| | 值 |
|---|---|
| 墙的层高 `WALL_H` | **16**（10 太矮，读成"有厚度的俯视"；要大于半格 12） |
| 家具层高 `PROP_H` | 8 |
| 立面 | **自上而下变暗**（顶 +18 → 贴地 −30）+ 横向壁板缝 + 顶端一道亮边 |
| 立面底色 | `86,80,74`（第一版 54,52,50 和脚下的影几乎同色，抬升做了也看不出来） |

**竖直渐变是"这是一面墙"最强的信号** —— 比层高本身还重要。

立面往上画会盖住**北边那一行**的东西，那正是对的：站在墙北边的人本来就该被挡住
（按行交错画保证了顺序）。

校验器钉四条：顶面在 footprint 之上、立面正好 `WALL_H` 高、顶面下缘与立面上缘接得上、
层高大于半格。**这条我丢过一次，所以它值一条断言。**

### 人物：光向统一 + 密度

「先优化玩家人物」那一轮做的。桌面上人物占 **96×126 CSS 像素**，
而原来一帧只有 330 个非空像素 —— 那个尺寸上这么稀，只能读成一块色。

**先定光向：左上。** 整张图共用一个方向，不然每个部件各亮各的，看着就散。
两个辅助色函数：`lit(c)` 提亮 16%、`dim(c)` 压暗 38%。

逐处加的体积（每一处都遵守同一个光向）：

| 部位 | 加了什么 |
|---|---|
| 躯干 | 受光列 + 最暗列 + 肩线受光 + 腰上方一道影 + **领口露一点脖子** |
| 腿 | 受光侧 / 背光侧 / **膝盖那道折** / 短裤时的脚踝 |
| 鞋 | 鞋面 + **鞋头受光** + 鞋底压暗；靴子多一道**靴筒口** |
| 手臂 | 受光侧 + **袖口** + 手 + **指节那道暗** |
| 头脸 | 受光半边 / 腮下的影 / **下巴投在脖子上的影** / 耳朵 / 鼻影 / 眉骨下的暗 |
| 头发 | 头顶受光 + 背光侧 + **三缕发丝** |
| 腰带 | 受光段 + **皮带扣** |

结果：非空像素 **330 → 468**（一帧 1344 格），走路相邻帧的差异 290~316 → **373~400**。

校验器钉两条：**平均非空像素 > 400**，以及**躯干八行里至少七成是左亮右暗**
（光向统一，不是各亮各的）。

### 四个朝向

图集 **24 列 = 4 向 × 6 帧**，列号 `dir*6 + slot`；行还是 16（六职业 + 十个按种子生成）。

| slot | 内容 |
|---|---|
| 0~3 | 走路四帧 |
| **4** | **出手**（持械那条胳膊伸出去 5 格，上身往朝向压 1 像素） |
| **5** | **收手**（拉回一半） |

正面往下前伸、背面往上举、侧面横着推出去。**没有重心转移就不像在使劲**，
所以出手那帧上身也跟着压。武器贴花跟着手走 —— 手在动而家伙不动，比不动还怪。

游戏里用的是本来就有的两段计时：`P.swing > 0` → 出手，`P.recover > 0` → 收手。
**时间一直都在，只是以前没喂给精灵** —— 挥击只画了一道弧。

| dir | 画法 |
|---|---|
| 0 南 | 正面（原来那一张） |
| 1 北 | **没有脸**，后脑一片头发 + 后颈；衣服画背缝和肩胛，不画门襟口袋 |
| 2 西 | = 东面**镜像**（省一半的活，也保证两边一致） |
| 3 东 | 躯干收窄 3、两腿叠在中线上靠跨距分前后、**只画近的那条胳膊**、侧脸一只眼 |

**朝向跟瞄准角走**：`dirOf(aim)` —— 桌面是鼠标、手机是摇杆、纯键盘时 `aim` 跟着走的方向。
于是**挥击的方向和人物面朝的方向永远一致**。

贴花也认朝向：背包在背面画在正中（最显眼）、侧面画在身后；
武器正面握右手、侧面握身前、**背面在左手**（转过身左右互换）。

校验器钉四条：96 帧全非空、四向两两不同、西东不是同一张图、
**背面脸那块没有皮肤像素**（第一版拿"暗像素"当脸的标志，结果被黑头发骗了）。

### 人物的走路循环

手玩报的第三条是「人物没有动作」。查出来：**四帧里有两帧完全一样**
（第 0 帧和第 2 帧都是 `lift:0 swing:0`），而抬脚和摆手都只有 1 像素。

改成真正的四帧步循环 —— 触地左 → 过渡 → 触地右 → 过渡：

| 帧 | bob | 抬脚 | 摆手 | 跨距（左/右） |
|---|---|---|---|---|
| 0 | 0 | −2 | +2 | +1 / −1 |
| 1 | −1 | 0 | 0 | 0 / 0 |
| 2 | 0 | +2 | −2 | −1 / +1 |
| 3 | −1 | 0 | 0 | 0 / 0 |

**迈步用横向跨距表达**（前腿往前 1、后腿往后 1），抬起来的那只脚底下露出地面。
实测相邻帧之间 **290~316 个像素在变**（一帧共 1344 格，约 22%）——
校验器钉了一条下限 120，这就是"人物没有动作"那次的回归闸门。

### 地面的信息密度

| | 做法 |
|---|---|
| 地砖 | **烤一次**（72×72 离屏），每种地面 **4 张变体**，按坐标哈希选 |
| 颗粒 | 粗颗粒 `RS×RS` 方块 26~36 个 + 细颗粒 1px 点 90~130 个 |
| 杂物 | 手摆 8 种 8×8 小件；**室外 15% / 室内 8%** 覆盖率，坐标哈希 |
| 血迹 | 打死一只留一摊，等级 1~3，**进镇子档** |
| 墙 | 顶面 / 立面各烤 3 张变体，带横向壁板缝 + 顶边受光 + 底边影 |
| 门窗 | **手摆** 24×10 的立面（门 / 窗 / 板窗） |

参照：市井的 `noiseTile()` 就是这么做的，装饰层覆盖率 23.5%。
静街原来每格每帧 1 底色 + 4 个 3×3 点 —— **是这个仓库已有水平的退步**，
不是程序化的上限。

### 隔着墙看不见活的东西

瓦片照画（你知道自己镇子长什么样），但**僵尸要有视线才画得出来**：
`losBlocked(玩家, 僵尸) > 0` 就不画。

这条不是性能优化，是可读性：不做的话商业街上一屏能看见二十几只
（实测附近 24 只、能看见的只有 8 只），玩家读到的是"这游戏到处都是僵尸"，
而实际上它们分散在各个屋里 —— **噪音引擎要的是"我知道这条街上有多少"，
不是"我看得见所有"**。

血量 3 档（瘦 / 普通 / 壮：2 / 3 / 5 次斧击）。品种只有两种：

| 品种 | 占比 | 常速 | 冲刺 | 冲完 | 时长 |
|---|---|---|---|---|---|
| 普通 | 88% | 0.75 | — | — | — |
| **冲刺尸** | 12% | 0.75 | **1.70** | **0.40** | 冲 `burstSec=4` 秒，累瘫 `coolSec=12` 秒（**现实秒**） |

冲刺 1.70 > 玩家跑 1.50（这 4 秒你跑不掉），冲完 0.40 < 玩家走 0.60（之后你一定跑得掉）。
**这两个不等号是红线**，校验器各钉一条 —— 全程跑的僵尸不做，也不做成开局开关。

折成现实秒（`格/游戏分钟 ÷ 0.375`）：

| | 格/游戏分钟 | 格/现实秒 |
|---|---|---|
| 蹲行 | 0.30 | 0.80 |
| 走 | 0.60 | 1.60 |
| 僵尸追击 | 0.75 | **2.00** |
| 玩家跑 | 1.50 | **4.00** |
| 冲刺尸冲刺 | 1.70 | **4.53** |

冲刺 4 秒走 18 格，玩家跑 4 秒走 16 格 —— **它每次冲刺净赚两格：追得上，但抓不住**；
冲完那 12 秒比你走路还慢，那是你的窗口。横穿全镇 96 格：走 60 秒，跑 24 秒。
**爬起来的时间**：被打倒但没打死的，12~20 秒后重新站起 —— 于是"打倒"和"打死"不是一回事。

## 四、身体（T4）

六表都是 0~100，每**游戏时**结算：

| 表 | 静息速率 | 见底时长 | 低于 25 的后果 |
|---|---|---|---|
| 饥饿 | −2.1 | 48 时 | 体力上限 −40%，0 时昏迷 |
| 口渴 | −4.2 | 24 时 | 视野收窄，0 时昏迷 |
| 疲劳 | −6.25 | 16 时 | 手抖（近战命中 −25%），0 时强制睡 |
| 体温 | 见下 | — | <30 冻伤，<10 死 |
| 恐慌 | 视野内僵尸驱动 | — | **枪械精度 −40%；近战不受影响** |
| 情绪 | 见下 | — | 所有行动耗时 ×1.25 |

**体温**：`Δ/时 = (环境温度基线) + 衣物保暖/6 − (湿透 ? 9 : 0)`

| 季节 | 户外基线 | 室内 | 有火 |
|---|---|---|---|
| 秋（D1~20） | −2 | +1 | +8 |
| 冬（D21~） | −23 | −6 | +8 |

穿齐（外套 38 + 毛衣 22 + 手套 6 + 靴 8 = 74）→ 冬天户外 `−23 + 12 = −11`/时 ≈ 撑 6 时；
再加雨衣不湿、白天躲进屋 → 12 时。**淋雨 → 湿透 → 保暖按 0 算**，这条链是入冬后的主要死因。

**恐慌**：`+3/秒 × 视野内僵尸数`，离开视野 `−6/秒`；酒 −30 一次。
`accuracy()` 返回 `{ melee, gun }`：`gun = 1 − min(.4, 恐慌/100 × .4)`，
`melee` **只看手臂伤**（每条 −35%），与恐慌无关 ——
近战已经有踉跄链在罚被围，同一个状态不许被两套机制罚两次。

**情绪**：独处 `−1.2/时`；收音机 +8/时（**噪音 6**）、书 +5/时、达成一次目标 +15、
**睡在自己据点的床上 +10**（睡在陌生地方 0）。最后这条让情绪成为
六表里唯一奖励"经营据点"的指标。

### 伤（6 部位 × 6 型）

| 伤型 | 来源 | 流血 | 尸毒 | 伤口感染基准 | 必需处理 |
|---|---|---|---|---|---|
| 咬 | 僵尸贴身 | 中 | **35%** | 40% | 全四步 |
| 抓 | 僵尸挥手 | 低 | **7%** | 25% | 消毒 + 包扎 |
| 撕裂 | 翻窗、拆板 | 高 | 0 | 30% | **缝合**否则一直流血 |
| 骨折 | 跳窗、被撞 | 0 | 0 | 0 | 夹板（否则该部位失能） |
| 烧 | 火、燃烧瓶 | 0 | 0 | 35% | 清洗 + 包扎 |
| 划 | 玻璃 | 低 | 0 | 15% | 消毒 + 包扎 |

处理链 **清洗（水）→ 消毒（酒精/消毒棉）→ 缝合（针线）→ 包扎（绷带/布条）**，
每漏一步，伤口感染概率按基准乘一次系数：

```
清洗漏 ×1.5   消毒漏 ×2.2   缝合漏 ×1.3（只对撕裂/咬）   包扎漏 ×1.8
布条代绷带 ×1.6
```

部位效果：手臂 → 挥击速度 −35%/条；腿 → 移速 −30%/条；
头 → 恐慌上升 ×1.5；躯干 → 体力上限 −25%。

## 五、两条感染线（T5）

```
     伤口                    ┌── 处理齐全 ──→ 愈合（2~5 天）
      │                      │
      ├─ 伤口感染 roll ───────┤
      │   （上表基准×系数）    └── 未处理 ──→ 发炎（12~48 时）──→ 脓毒
      │                                        │
      │                                   抗生素 → 治好
      │
      └─ 尸毒 roll（咬 35% / 抓 7%）──→ 潜伏 36~96 时 ──→ 死
```

尸毒四阶段，按潜伏总长的 25 / 50 / 75 / 100% 切：

| 阶段 | 界面文字 | 体感 |
|---|---|---|
| 25% | 「有点不舒服」 | 情绪 −10 |
| 50% | 「在发热」 | 疲劳速率 ×1.4 |
| 75% | 「一直在吐」 | 口渴速率 ×1.8、近战 −20% |
| 100% | 「抽搐」 | 4 时后死 |

**两套词汇严格分开**，文案里一个词都不许重合：

| | 伤口感染 | 尸毒感染 |
|---|---|---|
| 状态名 | **红肿** / 脓毒 | 已感染 |
| 颜色 | 黄 | 红（**只在确诊后**出现） |
| 提示语 | 「左小臂的伤口红肿了」 | 「你被咬了。这个不会好」 |

> 原来第一列写的是「发炎」，提示语是「伤口**在发**炎」—— 校验器按二字词比对，
> 当场抓出它和尸毒二阶段「**在发**热」重合。「发炎」和「发热」在状态栏里
> 只差一个字，正是决策 8 要防的那种混淆。改成「红肿」，两套词汇再无交集。
> **这是量具先于游戏写出来的第一个收益。**

确诊时机：被咬后 **6 游戏时**出现第一阶段才确诊 —— 这 6 小时里玩家不知道自己中没中，
是本作最有张力的一段，不要用即时判定把它抹掉。

## 六、日志与死亡回溯（T7）

### 事件总线要记的字段

每条事件至少 `{t, day, hhmm, kind, pos, block}`，另加各自的：

```js
bite        { part, zid, block }
wound       { part, type, cause }        // cause: 'window'|'melee'|'fall'|'glass'
treat       { part, step, item, ok }     // step: 'wash'|'disinfect'|'suture'|'dress'
infect      { part, kind }               // kind: 'wound'|'zombie'
noiseMade   { r, src }                   // src: 'gun'|'run'|'window'|'hammer'|'horn'
loot        { item, container, house }
hurtByHorde { n }                        // 被围时场上贴身数量
cold        { temp, wet, clothes }
thirst/hunger { level }
sleep       { safe, hours }
```

另外**两份采样**，是第三段文案的前提：

- **背包快照**：每 30 游戏分钟一条，环形缓冲 48 条（覆盖 24 时）。
  只存"关键处理物有没有"：`{water, alcohol, suture, bandage, antibiotic, food, drink}`
- **去过哪**：`seen[]` 位图，按房屋编号记"玩家是否曾进入其视野"。
  T1 生成镇子时就建 `ITEMINDEX: 物品 → [房屋编号]`，**别等到 T7 再补**

### 倒推算法

**急性死因和慢性死因的 origin 不是一回事** —— 这条是探针跑出来的（见第十一节）：

```
1. 致死指标 cause ∈{尸毒, 失血, 被围, 冻死, 脱水, 饿死, 脓毒}
2. 急性（尸毒 / 失血 / 被围）：
     origin = 总线里那一下（bite / hurtByHorde）
     lack   = origin.t 前后最近的背包快照里，处理这件事该有而没有的东西
   慢性（脱水 / 饿死 / 冻死 / 脓毒）：
     origin = 【最后一条"身上还有它"的背包快照】，不是第一次开始难受的时刻
     文案写成"那是你身上最后一份 X，之后的 N 小时里再没找到"
3. where  = ITEMINDEX[lack] 里距 origin.pos 最近、且 seen[] 为真的一处
4. 按三段模板渲染，取因果链上 3~5 条
```

慢性那一支写错的后果很具体：探针第一次跑出来的回溯是
「你死于脱水……**你身上有瓶装水，但一直没用**」—— 它拿被咬那一刻当 origin，
而那时水还在。慢性死因问的不是"什么时候开始难受"，是"**从哪一刻起就没救了**"。

### 三段模板

```
段一  你死于{cause}，第{day}天 {hhmm}。
段二  真正的死因在第{o.day}天 {o.hhmm} —— {o.place}，{o.what}。
段三  {lack.why}。最近的一{lack.unit}在{where.place}，{seen}。
```

渲染出来（就是策划第二节那段，这里是它的来源）：

> 你死于尸毒感染，第 9 天 04:10。
> 真正的死因在第 6 天 14:20 —— 肉铺后巷，你为了省一发子弹改用撬棍，被咬中左小臂。
> 你背包里当时没有酒精。最近的一瓶在药房，你第 4 天从门口路过。

**六种死因各写一套段二 / 段三**，冻死那套是：

> 真正的死因在第 23 天 09:40 —— 你在雨里走了两条街，外套湿透了，然后一直没换。
> 你有一件雨衣，在据点的木箱里。

### 文案红线（校验器要扫）

- 不许出现下划线命名、数字 ID、内部枚举名：`/[a-z]{2,}_[a-z]{2,}|#\d+|\bzid\b/`
- 不许把"当时怎么做才对"写成道德评价（不许出现"本该""你太"）
- `isStory(ev)` 必须是**纯函数**（市井 T15 的约定），日志一天最多 12 条

## 七、存档结构

**三个键，镇子和角色分开** —— 这是传承（T16）的全部实现：

```js
'qs.town.<seed>' = {
  seed, day, season,
  blocks: [{ pop, heat, lock }, ...6],
  waves: 0,
  built:    [{ x, y, kind, hp }],        // 钉的板、修的门、火堆、田、储物箱
  searched: Uint8Array(容器总数),         // 翻过的容器（位）
  stash:    [{ x, y, items }],           // 储物箱内容
  corpses:  [{ x, y, name, items, risen, killed }],   // 上一个你
  deeds:    { <镇志条目 id>: 做成那天 },               // 跨局累积，属于镇子
  legacy:   [{ name, days, cause, deeds }],           // 遗嘱池，最近 5 个
  waterDay, powerDay, waterOn, seeped,
}

'qs.char' = { name, job, skills:{...8}, body:{...6}, wounds:[], infect, inv, pos, day, logPages:[] }

// 【没有】全局的 'qs.legacy'。它原来是这么写的，是个 bug：
// 镇子按种子分开，而遗嘱池全局 —— A 镇那个人的遗嘱会漏到 B 镇去用，
// 而"上一个你"却来自另一座镇，传承当场散架。遗嘱池现在在 town.legacy 里。
// 最多三座镇（TOWN_CAP = 3，UI 上限而非技术上限：再多没人记得哪个是哪个）
```

读档顺序（市井 T32 踩过）：**先 town（地图变动态） → 重建寻路网 → 再 char**。
顺序错了，玩家会站在一块不存在的木板上。

**`built` 里没有 owner 字段，一个也不许有。** 加固、床、储物箱、田全部无归属：
谁下一个进到这栋房，这些东西就是谁的。理由与被否掉的选项见
[ADR-0002](adr/0002-strongholds-have-no-owner.md)，校验器钉的是
"镇子档的序列化结果里不许出现角色名"。

## 七·五、时间、据点、出生点、镇志

拷问第二、三轮定下来的四组数，原来三份文档里一个都没有。

### 时间与夜晚

| | 值 |
|---|---|
| 白天（06:00–20:00） | 一律 1x，1 游戏时 = 22.5 秒现实 |
| 夜（20:00–06:00） | 满足条件时快进，十小时压到 1 分钟以内 |
| 一天的有效长度 | 约 6 分钟；30 天 ≈ 3 小时 |
| 档位 | ⏸ / ▶（白天只有这两档）/ ▶▶（只在夜里且闸门开时） |

**快进闸门** `canFastForward()` 返回 `{ ok, why }`，三个条件全满足才开：
① 是夜里 ② 你在屋里、这栋房的窗**全部钉齐** ③ 8 格内没有僵尸。
`why` 必须说清是哪一条没过（"还有 3 扇窗没钉" / "外面有 1 只"）——
**这个闸门就是据点质量的读数**，不是一个省时间的按钮。

### 据点

`strongholds()` = 同时有**床**和**储物箱**的房屋编号列表。可以有好几个。
床 = 木板 ×2，储物箱 = 木板 ×1 + 钉 ×1，钉一扇窗 = 木板 ×1 + 钉 ×1。
`board(houseId)` 返回 `{ did, lack }` —— 钉不上要说清缺的是木板还是钉
（市井 T29「用不了也要说一声」）。

### 出生点

`ROADS` 三条入镇路（F 区两条、D 区一条）。`spawnPoint()` 取**离最近据点最远**、
且**不在当前密度最高街区**的那一条。于是"回到自己的据点"是第一天的目标而不是起点，
路上会遇到上一个你。

### 镇志

八条，属于镇子（`town.deeds`），跨局累积，每天结算时把八个谓词跑一遍：

| id | 做成的条件 |
|---|---|
| `sweep` | 有一个街区被杀到 10% 以下 |
| `winter` | 有人活过一个冬天（第 28 天且已入冬） |
| `genset` | 发电机进了据点 |
| `day30` | 有人活到第 30 天 |
| `ransack` | 全镇容器都被翻过 |
| `base` | 立起过一个据点 |
| `selfkill` | 杀掉过上一个你 |
| `harvest` | 收过一茬庄稼 |

`deedsLeft()` 是遗嘱页上那句"剩下的 N 件归你"的来源。

## 九、验收钩子契约

量具（`tools/verify-street.js` / `probe-street.js`）已经写好了，在游戏本体之前。
它们只认 `window.QS` 上这一套东西 —— **这份契约就是游戏必须长成的样子**。
完整清单在 `tools/street-stub.js` 的头部注释里，要点：

| 组 | 内容 |
|---|---|
| 推进 | `start(seed)`（不许再用 `Date.now()` 重播种）、`update(dt)`、`render()` |
| 绘制自证 | 每条绘制路径进来时 `paint('名字')` 记进 `__drawn`，清单在 `DRAW_PATHS` |
| 状态 | `TOWN` / `BLOCKS` / `Z` / `P` / `kills` / `waves` |
| 表 | `HOUSE_TYPE` `CONTAINER` `LOOT` `ITEMS` `RECIPES` `WOUND` `NOISE` `SPEED` `TEMP_BASE` `INFECT_TEXT` |
| 动作 | `noise` `move` `lootContainer` `useItem` `treat` `drinkFrom` `advanceHours` `migrate` `wave` `kill` `setUI` `night` |
| 输出 | `LOG` / `death` / `deathReport()` / `tileHash()` / `save` `load` `wipeChar` `wipeTown` |

游戏还不存在时，桩自动改用 `tools/_street_fixture.html` —— 一份**已知正确的最小实现**，
用来自检量具。量具自己的 bug 会被当成游戏的 bug（霓虹教训十九、二十三），
所以它必须有个靶子。目标路径只写在 `street-stub.js` 的一行常量里，定名落定只改那一行。

```bash
npm run check:street     # 50 条断言
npm run probe:street     # 20 局，四张表
```

## 十、量具先于游戏写出来，当场抓到三件事

写这两个脚本的时候游戏还一行没有，但已经有三处设计被改掉：

1. **两套感染词汇重合。**「伤口在发炎」撞上尸毒二阶段「在发热」（第五节已改）。
2. **慢性死因的 origin 取错了。** 渴死的人被告知"你身上有瓶装水"（第六节已改）。
3. **规格里漏了水源。** 前七天的水从哪来，规格只写了"自来水（D10 前）"，
   没说它挂在哪个物件上 —— 于是靶子里根本没有水，探针 55% 的局第 2 天渴死。
   现在定死：**厨房与卫生间的房间自带水源**，停水日 `waterDay = 7 + rnd(4)` 开局就定。

第三条是最值得记的一种错：**规格里写了"有"，但没写"挂在哪"，等于没有。**
表里出现过的每样东西，都要能回答"它在地图上的哪个物件里"。

## 十一、这份规格里最可能错的三个数

1. **`K = 0.25` 的迁移速率。** 太大 → 一枪把全镇拉过来，玩家学会永不开枪；
   太小 → 噪音没有长期后果，决策 2 落空。第一轮探针就该只调这一个数。
2. **空手率（`LOOT` 里的 `空` 权重）。** 它同时决定搜刮的节奏和玩家敢走多远，
   是本作最强的难度旋钮，但也最容易一改就崩。
3. **尸毒 35%。** PZ 是 100%（咬必死）。选 35% 是为了让"被咬之后还有 6 小时不知道"
   这段成立；但如果探针跑出来尸毒占死因 60% 以上，说明这个数还是太高。
