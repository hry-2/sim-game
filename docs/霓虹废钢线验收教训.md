# 霓虹废钢线 · 验收教训

这一轮加了手柄、临时增益、精英与波次修饰、移动端全屏、30 波终点、三种 BOSS
、首次遭遇提示、四档危险等级、构筑面板，以及可玩性补丁、移动端 UI、分档记录、敌人图鉴和三种新杂兵。功能本身不难，值得记下来的是
**验收方式本身踩的坑** —— 断言从 193 条涨到 580 条，其中有几条是把原来
"绿着但什么都没查"的断言换掉的。

## 一、断言不能贴着实现写

原来有一条：

```js
ok((html.match(/已 暂 停/g) || []).length === 2, '只有一处暂停提示，没有重复叠加');
```

意图是"只能有一处暂停提示"，写法却是"这个字符串出现两次"。加了手柄的
START 提示之后它变成三次，断言红了 —— 但游戏没有任何问题。

改成查意图：

```js
ok((html.match(/ctx\.fillText\([^)]*已 暂 停/g) || []).length === 1, '只有一处画暂停提示的地方');
```

## 二、绿的断言不等于测过的断言

两条一直是绿的、其实一行都没执行：

- **精灵宽度**：正则找的是内联 `sprite([...])`，而字符网格全声明在 `GRID` 里，
  于是永远匹配到 0 个，然后报"0 个精灵块，宽度全部一致"。
  改成遍历运行时的 `NS.GRID`，立刻覆盖到 45 帧。
- **`render()` 从来没被调用过**。整套验收只跑 `update()`。
  也就是说所有绘制代码都是到浏览器里才第一次执行 —— 精英标记环、增益掉落物、
  过热横幅，打错一个字要靠手玩才发现。现在有一节专门把每条绘制路径都画一遍。

判断办法很简单：**让断言打印它数到的数量**。`扫到了 45 帧` 和 `扫到了 0 帧`
都是绿的，但只有前者说明它真的看了东西。

还有一类是**桩把状态吃掉了，导致根本没法写断言**。原来 DOM 桩的
`getElementById` 每次返回一个新对象，`classList` 是空实现 —— 于是
"按钮被置灰了没有""芯片建出来了没有"这类改动在离线环境里完全观察不到，
只能退回去查源码里有没有那行字符串。后来把桩改成**按 id 缓存元素 + 用 Set
实现真的 classList + appendChild 真的记下孩子**，这类断言才写得出来。
**桩要贴着真 DOM 的行为做，不然它会把你能测的东西砍掉一半。**

## 三、零件全对，凑起来仍然可能不能玩

`verify-neon.js` 查的是每个零件对不对。它 279 条全绿的同时，游戏里有三个
真问题，全是 `probe-neon.js`（用假手柄驱动机器人真的把局打下去）撞出来的：

1. **词条全满后升级卡死。** 等级够高之后 `rollOffer()` 返回空数组，
   `showLevelup()` 照样把状态切进 `levelup` 再发 0 张牌 —— 界面弹出来、
   一张牌都没有、点哪都没反应。手玩很难玩到那个等级，所以一直没人发现。
2. **一波清不掉就永远卡着。** 波次推进要求场上清空。第 8 波摇到"铁壁"时
   刷出三十只带盾/重装，玩家正面只能打出 15% 伤害，`waveT` 一路跑到负数，
   人被困在盾墙里耗死。修法是加泄压阀：加时超过 12 秒，剩下的护盾**过热失效** ——
   僵局由玩家动手解开，而不是直接放它过关。
3. **波次修饰比它用到的怪先出场。** "精锐"能摇到第 4 波，于是一级角色
   正面撞上十几只 2.6 倍血的精英。每个修饰现在有 `from`，不早于它用的怪。

## 四、种子必须能从外部钉死

探针第一次跑出 14.2 波，第二次 20.2 波，同一份代码。原因是自由模式的
`start()` 里用 `Date.now()` 重新播种，外部 `seedRun()` 定的种子被冲掉了。

改成 `start(seedOverride)` 并支持 `?seed=`。这不只是为了测试 ——
roguelite 里"这把种子太离谱了"本来就该能分享回放。

顺带一条：探针跨种子之间要把 `PROF` 清回零号档案，否则里程碑奖励会累积，
后跑的种子自带一身加成，比的是跑的顺序不是这一局的难度。

## 五、铺满屏幕会把「画布里」和「视口上」的东西撞到一起

移动端原来是固定 320×180 等比缩放，竖屏上下各剩一大片黑。修法是让逻辑分辨率
跟着视口宽高比走，规则定成**参考框 320×180 永远完整装在里面**，多出来的空间
填成更多可见战场 —— 这样任何方向上看到的都不会比原来少，也不用改任何一处
用 VW/VH 定位的代码。桌面仍钉死 320×180：机台观感不变，也免得视野大小跟着
窗口形状漂（每日局大家看到的战场应该一样大）。

三个不那么显眼的连带问题：

1. **视野可能比场地还大。** 冷却塔只有 608 高，竖屏能看到 693。
   相机的 `clamp(v, 0, A.h - VH)` 这时上界比下界还小。得改成「场地比视野小就居中」。
2. **辉光缓冲写死了 80×45。** 它本来是 VW/4，分辨率一变就错位。
3. **画布铺满之后，画布里画的东西开始跟固定在视口上的触屏按钮抢位置。**
   小地图画在画布右下角，冲刺和开枪按钮固定在视口右下角 —— 以前画布居中缩在
   中间，两者天然错开；现在重叠了。小地图挪到左下。同理 HUD 得自己让开
   `env(safe-area-inset-*)`，因为画布现在真的顶到刘海底下了。

顺带一条：竖屏原来只有中间一条，所以有个「横过来玩，视野宽一倍」的催促。
现在竖屏也铺满、而且看得更高，这句话就不成立了 —— 改成一句「横屏左右更宽」，
几秒后自己消失。**改了表现就要回头看依赖旧表现的文案。**

## 六、曲线：猜错了两次，靠量才找到真因

改之前五个种子的笨机器人**全部**推到第 41 波，血量最低还剩 60–78%。

我的第一猜是"玩家复利、敌人线性"，于是打算砍词条。**量了一下发现猜错了**：

| | 第 1 波 | 第 20 波 | 第 32 波 |
|---|---|---|---|
| 玩家 DPS | 46 | 2680（封顶） | 2680 |
| 小兵血量 | 23 | 88 | 156 |
| 杀一只要几秒 | 0.51 | 0.03 | 0.06 |
| **本波预算** | 13 | 89 | **164 只** |
| **场上同时最多** | 4 | 30 | **16 只** |

第 32 波预算 164 只，场上同时**只有 16 只**。刷怪间隔的下限锁在 0.18 秒
= 5.6 只/秒，而玩家能杀 33 只/秒 —— 一百多只怪以 5.6/s 喂进一台 33/s 的绞肉机，
**场地永远是空的**。曲线平掉的真因是刷怪管道，不是玩家太强。

第二猜也错了：把密度提上去之后，五局反而**全部**通关了 —— 因为怪多了经验也多了，
等级从 61 涨到 74。**质量本身也是经验来源**，加密度会喂大复利。

最后落在四条一起改：

1. **按「场上同时多少只」刷怪**，不按「每几秒一只」。上限 `4+0.6w+0.08w²`：
   第 5 波 9 只（贴着老版本），第 30 波 84 只。附带好处是难度跟着玩家水平走 ——
   清得快就立刻补上，清得慢也不会被埋。
2. **补怪速率写成「每秒几只」**，不写成间隔。写间隔的时候 1/间隔 是非线性的，
   "够快"只在最后几波才到，第 12 波还只有 3.2 只/秒。
3. **升级需求分段**：前 8 级跟老曲线一模一样（开局连着升级的爽感是钩子，不能动），
   之后急刹，一局 30 波落在 29 级 —— 65 层词条只拿得到 28 层，每局都得取舍。
4. **敌人血量改二次**：线性 `1+0.17w` 到第 30 波只有 6.1 倍，改成 `1+0.12w+0.011w²`
   后是 14.5 倍，第 5 波跟原来一样（1.87 对 1.85，开局手感不动）。

**一个通用教训：每次调之前先量，调完再量。** 我两次的直觉都是错的，
而每次量出来的数字都直接指向了下一步该改哪里。

## 七、有终点本身就是设计工具

一局收在第 30 波。这不只是"给个结局"——**无界的曲线没法调，30 波的曲线可以**。
上面那四条全都依赖"第 30 波"这个锚点：密度上限、经验总量、血量倍率，
都是按 30 波这个区间算出来的。没有终点的时候，这些数字没有一个算得出来。

## 八、同一个错我犯了两次：别把还没解锁的内容提前

危险等级的第一版，"高危档"的结构性变化写的是「修饰从第一波就开始」：

```js
const pool = MODS.filter(m => w >= (g.modsEarly ? Math.min(m.from, 2) : m.from));
```

探针立刻给出 0/5 通关、3 局死在第 5 波前。原因是「铁壁」（一屏全是带盾的）
能在第 2 波砸到一级角色身上 —— **而 `from` 这个门槛正是我上一轮为了修这个
坑加的**（见第三节第 3 条）。我把它绕过去了一次。

改法：档位改的是【概率】，不是【内容什么时候解锁】。`modTier` 把摇到修饰的
概率整体往深层挪一档，`m.from` 谁都不能动。

紧接着第二个坑：归零档 `modTier: 2` 让第一层的概率变成 100%，而第 4 波唯一
够门槛的修饰只有「兽潮」—— 于是**每局第 4 波必定是兽潮**，4/5 局死在第 4~5 波。
**池子里只有一个候选时，「每波都有」等于「每波都是同一个」，那是单调不是难度。**
补了两条封顶：池子少于两个候选时概率压到 .35；第一层无论什么档位都留出平稳波次。

第三个坑是形状而不是数值：档位倍率一上来就满档（×1.25 血、×1.1 密度），
两局在第 5 波前就死。**「局还没开始就结束」是个烦人的形状，跟难度高低是两件事。**
倍率改成前八波渐进上来，第 1 波跟标准档一模一样。

## 九、测量工具自己的缺陷会被当成游戏的 bug

探针连着报了几次「卡住了」，诊断写着「场上只剩 1 只，母巢还有 10% 血，152 秒没推进」。

其中有一半是**游戏的问题**（母巢是唯一不会追人的 BOSS，而加时冲锋那条规则
把 BOSS 全排除了，于是它站在原地形成死局），另一半是**探针自己的问题**：
机器人的策略只有「太近就退」和「去捡东西」，**从不主动靠近敌人** ——
一只站在远处的母巢能让它干等三分钟。

两条都得修，但第二条更值得记：**如果只看结论「卡住了」，我会一直在游戏里
找不存在的 bug。** 诊断行（预算剩多少、场上几只、BOSS 还有多少血、加时多久、
过热开没开）是唯一能把两者分开的东西。

## 十、先找「已经存在但看不见」的东西，再想加新系统

被问到"要不要加背包/合成"的时候，正确的第一步不是设计新系统，是去看现有的数据结构：

- `G.stacks` 里存着这一局拿到的**全部 28 层词条**
- `P.owned` 里存着带着的**所有武器**
- 而玩家从头到尾只能在死亡结算看到一行「最常用武器 + 前两个词条」

**背包一直存在，只是没有显示出来。** 一局 30 波、28 次选牌，选的时候看不到已有的，
等于蒙着眼做决策。补一个只读面板：零平衡风险、不增加任何输入处理
（鼠标/触屏/手柄三套一行都不用写），就把最大的缺口补上了。

顺带发现了一个重叠：暂停原来是画在画布上的一行字，新面板也居中，两个会叠在一起。
把暂停整个搬到 DOM 层 —— 一处就够，而且 DOM 里能用真字体排版。
**加新东西的时候顺手检查它会不会跟旧东西抢同一块屏幕。**

真要加"合成"的话，这个类型里好的合成（以撒的道具联动）是**涌现的**，
不是一个合成菜单。这游戏已经有一点了：「穿甲钨芯」对近战自动变成"砍得更远"。
多写几条这种联动一点 UI 都不用写，而格子背包在一个从不停下来的双摇杆射击里是纯摩擦。

## 十一、改了机制，要回头看它拆掉了哪些反馈

把刷怪从「每几秒一只」改成「按场上密度」之后，HUD 上只剩一个 `WAVE 12`。
**旧的 `waveT` 倒计时至少还隐含着「这一波有多长」，新机制把这个信息拿掉了，
而我没有补回去。** 而「现在冲过去捡那个增益，还是再撑一会儿」这个决定全靠它。

补法：`还剩 = 没刷出来的（预算）+ 场上活着的`，一根条子加一个数字。
BOSS 不算进去 —— 它自己有血条，算进去会写成「还剩 1 只」，反而误导。

**换掉一个系统的时候，检查一遍它顺带提供过哪些信息。**

## 十二、桩越像真 DOM，能测的东西越多

这一轮为了测四个交互功能，桩又补了三处，每一处都是被一条假红逼出来的：

| 假红的断言 | 真正的原因 |
|---|---|
| `textContent === '10'` 不成立 | 桩不把 textContent 转成字符串，拿到的是数字 `10` |
| 「重画了三张牌」数到六张 | 桩的 `innerHTML = ''` 不清子元素 |
| 「按 2 换枪」没反应 | 两次 `run()` 共用一个监听器表，第二份构建把第一份顶掉了，
按键其实打到了触屏那份上 |

前两条是**桩不够像**，第三条更隐蔽：**桩自己有状态，而我跑了两份构建**。
现在每份构建的监听器挂在它自己的 NS 上，`key(code, ns)` 指明打给谁。

加上之前的「按 id 缓存元素 + 真的 classList」，这个桩已经能测：
DOM 文本、class 状态、子元素增删、CSS 变量、真实按键。
**每次为了写一条断言而改桩，都换来后面十条断言能写。**

## 十三、手机上最该删的是「它没有的东西」

做移动端 UI 优化的时候，第一反应是「加大按钮」。但在这个游戏里，
**最占地方也最没用的是那些讲键鼠的文案**：

- 标题页四行 `WASD 移动 / 鼠标瞄准 / 空格冲刺 / P 暂停·M 静音 / 手柄 双摇杆`
- 升级页 `选择一条改装 · 按 1 / 2 / 3 · R 重摇`
- HUD 武器标签的 `Q▸`

手机玩家一个都用不上，而它们挤掉的是真正该占位置的东西。删掉这些、换成
`左半屏拖动移动 / 右半屏拖动瞄准开火`，标题页立刻松快了一截。

**每加一个设备就要回头问一遍：现有的文案里，有多少是在讲这个设备没有的东西。**

其余几条是常规但确实需要量的：

| 问题 | 量出来的数 | 改成 |
|---|---|---|
| chip 太小按不中 | 22~28px 高 | 触屏 40px，按钮 44px |
| 矮屏标题页被切 | 内容 795 / 视口 667 | 触屏可滚 + 开始按钮吸底 |
| 升级页两头被切 | 它不是 `.screen`，前面加的滚动没覆盖到 | 单独加滚动 + 窄屏压扁牌 |
| 横屏升级页要滚 | 内容 447 / 视口 375 | `max-height:430px` 再压一版 → 375 刚好 |
| 标题页压着占位 HUD | 桌面居中看不出，手机铺满就压上了 | `body.menu` 藏掉局内 HUD |

两个值得记的细节：

1. **吸底按钮必须有实底。** 按钮本身 `background:transparent`，吸底之后
   后面一排排 chip 会从它身上透过去。加了一层 `.startbar`，桌面上
   `display:contents` 不参与布局，视觉一点不变。
2. **升级页不能把 HUD 藏掉。** 选哪张牌取决于现在剩多少血、第几波 ——
   所以是让内容让开 HUD（顶部留 52px），不是把 HUD 关掉。

## 十四、被问「还能加什么」的时候，先去翻数据结构

这次翻出两个洞，都是**数据已经存在，只是没留住或没显示**：

1. **记录只有一条，升档就被顶掉。** `BEST` 是单个对象，而比较顺序是
   「危险档 → 波次 → 分数」—— 通关高危之后，标准档那条 30 波的记录永远消失：
   看不到，也没法再挑战。一个靠刷自己记录驱动的游戏，四个档位该有四条记录。
   （顺带要写迁移：老存档是扁平的一条，得挂到它自己那一档上，不能让人的旧记录凭空没了。）
2. **应对提示只播一次，之后查不到。** `TIPS` 里九条写得挺具体，但只在这一局
   第一次遇见时弹一次横幅，两秒就没了 —— 而你当时正在躲。文案早就在代码里，
   缺的只是一个能翻的地方（暂停面板加一页图鉴）。

这两个加上之前的构筑面板，是同一类：**先把已经有的东西留住、显出来，
再考虑加新系统。** 这类改动零平衡风险，而且到目前为止收益最高。

## 十五、加内容比调数值更能修难度

三种新杂兵（裂解体分裂 / 钉枪手远程蓄力 / 拖曳者甩钩拽人）上线之后，
基准档笨机器人从 **4 胜 1 败** 变成 **2 胜 3 败**，平均波次 28.2 → 21，
而我**一个数值都没动**。

其中拖曳者是刻意针对探针暴露出的支配策略做的：机器人（和大多数人）都在
「边退边打」，甩钩把你往它那边拽，直接破掉这个。它同时给冲刺加了个新用途 ——
冲刺能挣开钩索。**一个好的新敌人应该让一个旧按键多一个理由被按。**

三个踩到的坑：

1. **`d` 被遮蔽。** 刷怪更新循环里 `d` 是【距离】，我照 `killMob` 的习惯
   写了 `d.standoff` → `undefined` → 钉枪手既不退也不蓄力，完全是块木头。
   断言「离得太近会往后退（80 → 80px）」一眼就报出来了 ——
   **写「变了多少」的断言，连「一点没变」都能抓到。**
2. **一条断言其实一直在测两件事。** 「母巢靠吐兵」数的是 BOSS 召唤 + 波次刷怪，
   之前靠巧合过关，我一改刷怪表立刻翻。把正常刷怪关掉才是真的在测 BOSS。
3. **加一条数据会打乱别的测试。** 给拾荒机兵补了图鉴条目之后，
   「提示两秒内只播一条」红了 —— 因为循环里刷出的小兵往队列里多塞了一条。
   测试要自己把环境钉死，不能依赖「刚好没有别的东西进来」。

## 十六、加了新内容，要回头看它有没有真的进到局里

上一轮加了三种新杂兵，这一轮量了一下它们在【最后十波】的占比：

| | 刀锋犬 | 铁闸 | 爆囊 | 无人机 | 重装 | 拾荒 | 裂解体 | 钉枪手 | 拖曳者 | 中继 |
|---|---|---|---|---|---|---|---|---|---|---|
| 改之前 | 25.5% | 14.0% | 12.9% | 11.0% | 10.2% | 10.1% | **5.0%** | **4.0%** | **3.7%** | **3.6%** |
| 改之后 | 23.7% | 13.3% | 14.7% | 9.0% | 6.5% | 8.5% | **6.5%** | **7.7%** | **4.0%** | **6.0%** |

原因：第 21~30 波有 80% 的波次带修饰，而**修饰会整表替换刷怪表** ——
那三张表是七种敌人时代写的，从没更新过。于是六种「逼你改打法」的怪
在高潮段只占 16.3%，只会直线冲刺的刀锋犬占了四分之一。
**我加了三种新怪，却让它们在最需要变化的地方基本消失了。**

补了三个用新怪做的修饰（裂变 / 封锁线 / 拖网）之后，那六种合计
**16.3% → 52.2%**。并且加了一条元断言：**每一种「逼你改打法」的怪
都必须至少进一个修饰的刷怪表** —— 下次加第十一种怪时会直接红。

## 十七、两条被新内容作废的旧决定

改完之后探针 5 局有 4 局死在第 21~22 波，死因高度集中。查出来是两条
**当初合理、现在不合理**的决定：

1. **「封锁线」让钉枪手占半张表。** 远程怪的威胁随数量是【乘性】的 ——
   第 21 波那张表刷出约 40 个钉枪手，就是每秒 40 条弹线，有预警也躲不过来。
   钉枪手该是「盾墙后面的两个神枪手」，不是一整波。压到 1/4，
   并写进断言：远程怪在任何修饰里不得超过 1/3。
2. **「第三层每一波都带修饰」。** 这是只有 4 个修饰、8 种怪时定的；
   7 个修饰 10 种怪之后，同一条规则把第 21 波变成了一道墙。
   压到 0.82 —— 五波里还能摊上一波平稳的，给人喘口气的节拍。

第二条原来还有一条断言守着它（「第三层每一波都带修饰（故意的）」）。
**断言也会过期：它锁住的是一个决定，而决定的前提变了。**

## 十八、机制的频率不能跟场上数量走

拖曳者的钩索，实测第 25 波：

| | 被钩时间 | 同时几条 | 场上几个 |
|---|---|---|---|
| 一开始 | **84%** | 6 | 7~9 |
| 加「同时只许一条」 | **98%**（更糟） | 1 | 8 |
| 改成全场共享冷却 | **34%** | 1 | 3 |

第二步为什么更糟：八个拖曳者轮着钩，一条刚松下一条立刻接上。
**毛病不在「同时几条」，在「频率跟着密度走」** —— 密度是后期必然上涨的东西，
任何挂在它身上的机制都会在后期失控。改成全场共享一个冷却，频率就跟数量无关了。

还有一个细节：冷却必须在**起钩时**就占住。只在结束时设的话，同一帧里所有
冷却好了的拖曳者都会看到 `hookCd<=0`，一起起钩（实测同时 3 条）。

顺带把拉力从写死的 108 改成 `P.speed * 0.55`。原来那个值跟基础移速 82
差不多，等于直接把人拖走；挂在移速上之后「义体伺服」这条词条顺带成了「抗拽」。

## 十九、量具自己的两个 bug

这一轮两次被自己的工具骗：

1. **测混合比的脚本手动设了 `G.budget = 60`**，而修饰的预算倍率是在
   `nextWave()` 里生效的 —— 于是我调了两轮「兽潮预算」，而测量从头到尾
   没看到 budget。表现是：改完数字**一点没变**。
   幸好没变这件事本身就是线索 —— **改了东西而指标完全不动，先怀疑量具。**
2. **探针机器人不打提前量。** 它瞄目标的当前位置，而子弹飞 100px 要 0.37 秒，
   期间怪走了 9px，而怪的半径只有 5px。后果是探针报了两次「卡住了」：
   场上剩几只慢怪，机器人全速开火 175 秒打不死。
   我先怀疑了掩体挡子弹、怀疑了射程、怀疑了死亡清理 —— 全都不是。
   最后靠打时间序列（`fireT` 稳定、子弹一直有 3~5 颗、目标不死）才定位到。

**「卡住了」这个结论出现的时候，先分清是游戏卡住还是量具卡住。**

## 二十、试玩反馈两句话，查出三个问题（其中两个是我造的）

反馈原话：「分不清经验点和敌人的子弹」「血条没看到」。

**一、只靠颜色区分。** 经验点是「r=4.5 绿色光斑 + 2×2 白芯」，
敌方子弹是「r=6 橙色光斑 + 2×2 白芯」—— 辉光会把颜色往白里洗，
于是两个都只是「带白心的小亮点」，玩家会走过去捡子弹。

**这跟第三节记的「五种敌人都是圆角方块加亮中心，只有颜色不同」是同一个错，
我又犯了一次。** 改法也一样：靠形状和运动区分。
子弹画成沿速度方向的曳光（又直又快、朝向就是它要去的地方），
经验点画成慢慢转的菱形（尖轮廓、几乎不动）。

**二、血条在 HUD 左上角，而打起来眼睛一直在自己身上。**
把血量画成玩家身上的一圈弧：满血不画（平时不糊），掉血就出来，越低越显眼。
低血时再给全屏四边压一层红 —— 激战时视线会跟着敌人跑，需要一个不看也知道的信号。

这里踩了一个小坑：**危险时血环用纯红，正好跟全屏红警同色，
于是它在最需要读它的那一刻消失在背景里。** 改成近白的粉 + 外面套一圈红边。

**三、血条真的被挤没了。** 量了一下：HP 条在 375 宽的手机上只有 **2 像素**
（旁边的经验条是 125）。原因是我这一轮把波次进度条和数字加进了 HUD 顶行，
右边那组挤满之后，左边 `flex:1` 的血条被压成 0 —— `flex:1` 的默认 basis 是 0，
空间不够时会一路压到没。

**「血条没看到」是字面意思，不是「没注意看」。** 加了 `min-width` 和行内换行。

教训：**加一个 HUD 元素的时候，去量一遍同一行里别的元素还剩多少宽。**
挤没了的东西不会报错，只会安静地变成 2 像素。

## 二十一、泄压阀要一路修到底

"一波清不掉就永远卡着"这个问题修了三次，每次都是探针撞出来的：

1. 三十只带盾的正面只进 15% 伤害 → 加时 12 秒后护盾**过热失效**
2. 母巢一直吐无人机，清得比吐得慢 → 加时后 BOSS **停止召唤**
3. 预算 0、场上只剩 2 只、过热已开，还是 152 秒没推进 ——
   两只残兵在远处游荡，玩家得满场追 → 加时后残兵**一律直冲玩家**

前两次我都以为修完了。**"卡住了"这个结论没有用，"为什么卡住"才有用** ——
后来给探针加了卡住时的诊断（预算剩多少、场上几只、BOSS 还有多少血、加时多久、
过热开没开），第三个原因是这行诊断直接说出来的，不是我猜的。

```bash
npm run check:neon   # 279 条零件断言
npm run probe:neon   # 机器人真的把局打下去，看死在第几波
```
