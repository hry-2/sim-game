# 霓虹废钢线 · 验收教训

这一轮加了手柄、临时增益、精英与波次修饰、移动端全屏、30 波终点、三种 BOSS
、首次遭遇提示、四档危险等级、构筑面板，以及可玩性补丁、移动端 UI、分档记录、敌人图鉴和三种新杂兵。功能本身不难，值得记下来的是
**验收方式本身踩的坑** —— 断言从 193 条涨到 830 条，其中有几条是把原来
"绿着但什么都没查"的断言换掉的。

## 一、断言不能贴着实现写

原来有一条：

```js
ok((html.match(/已 暂 停/g) || []).length === 2, '只有一处暂停提示，没有重复叠加');
```

意图是"只能有一处暂停提示"，写法却是"这个字符串出现两次"。加了手柄的
START 提示之后它变成三次，断言红了 —— 但游戏没有任何问题。

改成查意图：

```js
ok((html.match(/ctx\.fillText\([^)]*已 暂 停/g) || []).length === 1, '只有一处画暂停提示的地方');
```

## 二、绿的断言不等于测过的断言

两条一直是绿的、其实一行都没执行：

- **精灵宽度**：正则找的是内联 `sprite([...])`，而字符网格全声明在 `GRID` 里，
  于是永远匹配到 0 个，然后报"0 个精灵块，宽度全部一致"。
  改成遍历运行时的 `NS.GRID`，立刻覆盖到 45 帧。
- **`render()` 从来没被调用过**。整套验收只跑 `update()`。
  也就是说所有绘制代码都是到浏览器里才第一次执行 —— 精英标记环、增益掉落物、
  过热横幅，打错一个字要靠手玩才发现。现在有一节专门把每条绘制路径都画一遍。

判断办法很简单：**让断言打印它数到的数量**。`扫到了 45 帧` 和 `扫到了 0 帧`
都是绿的，但只有前者说明它真的看了东西。

还有一类是**桩把状态吃掉了，导致根本没法写断言**。原来 DOM 桩的
`getElementById` 每次返回一个新对象，`classList` 是空实现 —— 于是
"按钮被置灰了没有""芯片建出来了没有"这类改动在离线环境里完全观察不到，
只能退回去查源码里有没有那行字符串。后来把桩改成**按 id 缓存元素 + 用 Set
实现真的 classList + appendChild 真的记下孩子**，这类断言才写得出来。
**桩要贴着真 DOM 的行为做，不然它会把你能测的东西砍掉一半。**

## 三、零件全对，凑起来仍然可能不能玩

`verify-neon.js` 查的是每个零件对不对。它 279 条全绿的同时，游戏里有三个
真问题，全是 `probe-neon.js`（用假手柄驱动机器人真的把局打下去）撞出来的：

1. **词条全满后升级卡死。** 等级够高之后 `rollOffer()` 返回空数组，
   `showLevelup()` 照样把状态切进 `levelup` 再发 0 张牌 —— 界面弹出来、
   一张牌都没有、点哪都没反应。手玩很难玩到那个等级，所以一直没人发现。
2. **一波清不掉就永远卡着。** 波次推进要求场上清空。第 8 波摇到"铁壁"时
   刷出三十只带盾/重装，玩家正面只能打出 15% 伤害，`waveT` 一路跑到负数，
   人被困在盾墙里耗死。修法是加泄压阀：加时超过 12 秒，剩下的护盾**过热失效** ——
   僵局由玩家动手解开，而不是直接放它过关。
3. **波次修饰比它用到的怪先出场。** "精锐"能摇到第 4 波，于是一级角色
   正面撞上十几只 2.6 倍血的精英。每个修饰现在有 `from`，不早于它用的怪。

## 四、种子必须能从外部钉死

探针第一次跑出 14.2 波，第二次 20.2 波，同一份代码。原因是自由模式的
`start()` 里用 `Date.now()` 重新播种，外部 `seedRun()` 定的种子被冲掉了。

改成 `start(seedOverride)` 并支持 `?seed=`。这不只是为了测试 ——
roguelite 里"这把种子太离谱了"本来就该能分享回放。

顺带一条：探针跨种子之间要把 `PROF` 清回零号档案，否则里程碑奖励会累积，
后跑的种子自带一身加成，比的是跑的顺序不是这一局的难度。

## 五、铺满屏幕会把「画布里」和「视口上」的东西撞到一起

移动端原来是固定 320×180 等比缩放，竖屏上下各剩一大片黑。修法是让逻辑分辨率
跟着视口宽高比走，规则定成**参考框 320×180 永远完整装在里面**，多出来的空间
填成更多可见战场 —— 这样任何方向上看到的都不会比原来少，也不用改任何一处
用 VW/VH 定位的代码。桌面仍钉死 320×180：机台观感不变，也免得视野大小跟着
窗口形状漂（每日局大家看到的战场应该一样大）。

三个不那么显眼的连带问题：

1. **视野可能比场地还大。** 冷却塔只有 608 高，竖屏能看到 693。
   相机的 `clamp(v, 0, A.h - VH)` 这时上界比下界还小。得改成「场地比视野小就居中」。
2. **辉光缓冲写死了 80×45。** 它本来是 VW/4，分辨率一变就错位。
3. **画布铺满之后，画布里画的东西开始跟固定在视口上的触屏按钮抢位置。**
   小地图画在画布右下角，冲刺和开枪按钮固定在视口右下角 —— 以前画布居中缩在
   中间，两者天然错开；现在重叠了。小地图挪到左下。同理 HUD 得自己让开
   `env(safe-area-inset-*)`，因为画布现在真的顶到刘海底下了。

顺带一条：竖屏原来只有中间一条，所以有个「横过来玩，视野宽一倍」的催促。
现在竖屏也铺满、而且看得更高，这句话就不成立了 —— 改成一句「横屏左右更宽」，
几秒后自己消失。**改了表现就要回头看依赖旧表现的文案。**

## 六、曲线：猜错了两次，靠量才找到真因

改之前五个种子的笨机器人**全部**推到第 41 波，血量最低还剩 60–78%。

我的第一猜是"玩家复利、敌人线性"，于是打算砍词条。**量了一下发现猜错了**：

| | 第 1 波 | 第 20 波 | 第 32 波 |
|---|---|---|---|
| 玩家 DPS | 46 | 2680（封顶） | 2680 |
| 小兵血量 | 23 | 88 | 156 |
| 杀一只要几秒 | 0.51 | 0.03 | 0.06 |
| **本波预算** | 13 | 89 | **164 只** |
| **场上同时最多** | 4 | 30 | **16 只** |

第 32 波预算 164 只，场上同时**只有 16 只**。刷怪间隔的下限锁在 0.18 秒
= 5.6 只/秒，而玩家能杀 33 只/秒 —— 一百多只怪以 5.6/s 喂进一台 33/s 的绞肉机，
**场地永远是空的**。曲线平掉的真因是刷怪管道，不是玩家太强。

第二猜也错了：把密度提上去之后，五局反而**全部**通关了 —— 因为怪多了经验也多了，
等级从 61 涨到 74。**质量本身也是经验来源**，加密度会喂大复利。

最后落在四条一起改：

1. **按「场上同时多少只」刷怪**，不按「每几秒一只」。上限 `4+0.6w+0.08w²`：
   第 5 波 9 只（贴着老版本），第 30 波 84 只。附带好处是难度跟着玩家水平走 ——
   清得快就立刻补上，清得慢也不会被埋。
2. **补怪速率写成「每秒几只」**，不写成间隔。写间隔的时候 1/间隔 是非线性的，
   "够快"只在最后几波才到，第 12 波还只有 3.2 只/秒。
3. **升级需求分段**：前 8 级跟老曲线一模一样（开局连着升级的爽感是钩子，不能动），
   之后急刹，一局 30 波落在 29 级 —— 65 层词条只拿得到 28 层，每局都得取舍。
4. **敌人血量改二次**：线性 `1+0.17w` 到第 30 波只有 6.1 倍，改成 `1+0.12w+0.011w²`
   后是 14.5 倍，第 5 波跟原来一样（1.87 对 1.85，开局手感不动）。

**一个通用教训：每次调之前先量，调完再量。** 我两次的直觉都是错的，
而每次量出来的数字都直接指向了下一步该改哪里。

## 七、有终点本身就是设计工具

一局收在第 30 波。这不只是"给个结局"——**无界的曲线没法调，30 波的曲线可以**。
上面那四条全都依赖"第 30 波"这个锚点：密度上限、经验总量、血量倍率，
都是按 30 波这个区间算出来的。没有终点的时候，这些数字没有一个算得出来。

## 八、同一个错我犯了两次：别把还没解锁的内容提前

危险等级的第一版，"高危档"的结构性变化写的是「修饰从第一波就开始」：

```js
const pool = MODS.filter(m => w >= (g.modsEarly ? Math.min(m.from, 2) : m.from));
```

探针立刻给出 0/5 通关、3 局死在第 5 波前。原因是「铁壁」（一屏全是带盾的）
能在第 2 波砸到一级角色身上 —— **而 `from` 这个门槛正是我上一轮为了修这个
坑加的**（见第三节第 3 条）。我把它绕过去了一次。

改法：档位改的是【概率】，不是【内容什么时候解锁】。`modTier` 把摇到修饰的
概率整体往深层挪一档，`m.from` 谁都不能动。

紧接着第二个坑：归零档 `modTier: 2` 让第一层的概率变成 100%，而第 4 波唯一
够门槛的修饰只有「兽潮」—— 于是**每局第 4 波必定是兽潮**，4/5 局死在第 4~5 波。
**池子里只有一个候选时，「每波都有」等于「每波都是同一个」，那是单调不是难度。**
补了两条封顶：池子少于两个候选时概率压到 .35；第一层无论什么档位都留出平稳波次。

第三个坑是形状而不是数值：档位倍率一上来就满档（×1.25 血、×1.1 密度），
两局在第 5 波前就死。**「局还没开始就结束」是个烦人的形状，跟难度高低是两件事。**
倍率改成前八波渐进上来，第 1 波跟标准档一模一样。

## 九、测量工具自己的缺陷会被当成游戏的 bug

探针连着报了几次「卡住了」，诊断写着「场上只剩 1 只，母巢还有 10% 血，152 秒没推进」。

其中有一半是**游戏的问题**（母巢是唯一不会追人的 BOSS，而加时冲锋那条规则
把 BOSS 全排除了，于是它站在原地形成死局），另一半是**探针自己的问题**：
机器人的策略只有「太近就退」和「去捡东西」，**从不主动靠近敌人** ——
一只站在远处的母巢能让它干等三分钟。

两条都得修，但第二条更值得记：**如果只看结论「卡住了」，我会一直在游戏里
找不存在的 bug。** 诊断行（预算剩多少、场上几只、BOSS 还有多少血、加时多久、
过热开没开）是唯一能把两者分开的东西。

## 十、先找「已经存在但看不见」的东西，再想加新系统

被问到"要不要加背包/合成"的时候，正确的第一步不是设计新系统，是去看现有的数据结构：

- `G.stacks` 里存着这一局拿到的**全部 28 层词条**
- `P.owned` 里存着带着的**所有武器**
- 而玩家从头到尾只能在死亡结算看到一行「最常用武器 + 前两个词条」

**背包一直存在，只是没有显示出来。** 一局 30 波、28 次选牌，选的时候看不到已有的，
等于蒙着眼做决策。补一个只读面板：零平衡风险、不增加任何输入处理
（鼠标/触屏/手柄三套一行都不用写），就把最大的缺口补上了。

顺带发现了一个重叠：暂停原来是画在画布上的一行字，新面板也居中，两个会叠在一起。
把暂停整个搬到 DOM 层 —— 一处就够，而且 DOM 里能用真字体排版。
**加新东西的时候顺手检查它会不会跟旧东西抢同一块屏幕。**

真要加"合成"的话，这个类型里好的合成（以撒的道具联动）是**涌现的**，
不是一个合成菜单。这游戏已经有一点了：「穿甲钨芯」对近战自动变成"砍得更远"。
多写几条这种联动一点 UI 都不用写，而格子背包在一个从不停下来的双摇杆射击里是纯摩擦。

## 十一、改了机制，要回头看它拆掉了哪些反馈

把刷怪从「每几秒一只」改成「按场上密度」之后，HUD 上只剩一个 `WAVE 12`。
**旧的 `waveT` 倒计时至少还隐含着「这一波有多长」，新机制把这个信息拿掉了，
而我没有补回去。** 而「现在冲过去捡那个增益，还是再撑一会儿」这个决定全靠它。

补法：`还剩 = 没刷出来的（预算）+ 场上活着的`，一根条子加一个数字。
BOSS 不算进去 —— 它自己有血条，算进去会写成「还剩 1 只」，反而误导。

**换掉一个系统的时候，检查一遍它顺带提供过哪些信息。**

## 十二、桩越像真 DOM，能测的东西越多

这一轮为了测四个交互功能，桩又补了三处，每一处都是被一条假红逼出来的：

| 假红的断言 | 真正的原因 |
|---|---|
| `textContent === '10'` 不成立 | 桩不把 textContent 转成字符串，拿到的是数字 `10` |
| 「重画了三张牌」数到六张 | 桩的 `innerHTML = ''` 不清子元素 |
| 「按 2 换枪」没反应 | 两次 `run()` 共用一个监听器表，第二份构建把第一份顶掉了，
按键其实打到了触屏那份上 |

前两条是**桩不够像**，第三条更隐蔽：**桩自己有状态，而我跑了两份构建**。
现在每份构建的监听器挂在它自己的 NS 上，`key(code, ns)` 指明打给谁。

加上之前的「按 id 缓存元素 + 真的 classList」，这个桩已经能测：
DOM 文本、class 状态、子元素增删、CSS 变量、真实按键。
**每次为了写一条断言而改桩，都换来后面十条断言能写。**

## 十三、手机上最该删的是「它没有的东西」

做移动端 UI 优化的时候，第一反应是「加大按钮」。但在这个游戏里，
**最占地方也最没用的是那些讲键鼠的文案**：

- 标题页四行 `WASD 移动 / 鼠标瞄准 / 空格冲刺 / P 暂停·M 静音 / 手柄 双摇杆`
- 升级页 `选择一条改装 · 按 1 / 2 / 3 · R 重摇`
- HUD 武器标签的 `Q▸`

手机玩家一个都用不上，而它们挤掉的是真正该占位置的东西。删掉这些、换成
`左半屏拖动移动 / 右半屏拖动瞄准开火`，标题页立刻松快了一截。

**每加一个设备就要回头问一遍：现有的文案里，有多少是在讲这个设备没有的东西。**

其余几条是常规但确实需要量的：

| 问题 | 量出来的数 | 改成 |
|---|---|---|
| chip 太小按不中 | 22~28px 高 | 触屏 40px，按钮 44px |
| 矮屏标题页被切 | 内容 795 / 视口 667 | 触屏可滚 + 开始按钮吸底 |
| 升级页两头被切 | 它不是 `.screen`，前面加的滚动没覆盖到 | 单独加滚动 + 窄屏压扁牌 |
| 横屏升级页要滚 | 内容 447 / 视口 375 | `max-height:430px` 再压一版 → 375 刚好 |
| 标题页压着占位 HUD | 桌面居中看不出，手机铺满就压上了 | `body.menu` 藏掉局内 HUD |

两个值得记的细节：

1. **吸底按钮必须有实底。** 按钮本身 `background:transparent`，吸底之后
   后面一排排 chip 会从它身上透过去。加了一层 `.startbar`，桌面上
   `display:contents` 不参与布局，视觉一点不变。
2. **升级页不能把 HUD 藏掉。** 选哪张牌取决于现在剩多少血、第几波 ——
   所以是让内容让开 HUD（顶部留 52px），不是把 HUD 关掉。

## 十四、被问「还能加什么」的时候，先去翻数据结构

这次翻出两个洞，都是**数据已经存在，只是没留住或没显示**：

1. **记录只有一条，升档就被顶掉。** `BEST` 是单个对象，而比较顺序是
   「危险档 → 波次 → 分数」—— 通关高危之后，标准档那条 30 波的记录永远消失：
   看不到，也没法再挑战。一个靠刷自己记录驱动的游戏，四个档位该有四条记录。
   （顺带要写迁移：老存档是扁平的一条，得挂到它自己那一档上，不能让人的旧记录凭空没了。）
2. **应对提示只播一次，之后查不到。** `TIPS` 里九条写得挺具体，但只在这一局
   第一次遇见时弹一次横幅，两秒就没了 —— 而你当时正在躲。文案早就在代码里，
   缺的只是一个能翻的地方（暂停面板加一页图鉴）。

这两个加上之前的构筑面板，是同一类：**先把已经有的东西留住、显出来，
再考虑加新系统。** 这类改动零平衡风险，而且到目前为止收益最高。

## 十五、加内容比调数值更能修难度

三种新杂兵（裂解体分裂 / 钉枪手远程蓄力 / 拖曳者甩钩拽人）上线之后，
基准档笨机器人从 **4 胜 1 败** 变成 **2 胜 3 败**，平均波次 28.2 → 21，
而我**一个数值都没动**。

其中拖曳者是刻意针对探针暴露出的支配策略做的：机器人（和大多数人）都在
「边退边打」，甩钩把你往它那边拽，直接破掉这个。它同时给冲刺加了个新用途 ——
冲刺能挣开钩索。**一个好的新敌人应该让一个旧按键多一个理由被按。**

三个踩到的坑：

1. **`d` 被遮蔽。** 刷怪更新循环里 `d` 是【距离】，我照 `killMob` 的习惯
   写了 `d.standoff` → `undefined` → 钉枪手既不退也不蓄力，完全是块木头。
   断言「离得太近会往后退（80 → 80px）」一眼就报出来了 ——
   **写「变了多少」的断言，连「一点没变」都能抓到。**
2. **一条断言其实一直在测两件事。** 「母巢靠吐兵」数的是 BOSS 召唤 + 波次刷怪，
   之前靠巧合过关，我一改刷怪表立刻翻。把正常刷怪关掉才是真的在测 BOSS。
3. **加一条数据会打乱别的测试。** 给拾荒机兵补了图鉴条目之后，
   「提示两秒内只播一条」红了 —— 因为循环里刷出的小兵往队列里多塞了一条。
   测试要自己把环境钉死，不能依赖「刚好没有别的东西进来」。

## 十六、加了新内容，要回头看它有没有真的进到局里

上一轮加了三种新杂兵，这一轮量了一下它们在【最后十波】的占比：

| | 刀锋犬 | 铁闸 | 爆囊 | 无人机 | 重装 | 拾荒 | 裂解体 | 钉枪手 | 拖曳者 | 中继 |
|---|---|---|---|---|---|---|---|---|---|---|
| 改之前 | 25.5% | 14.0% | 12.9% | 11.0% | 10.2% | 10.1% | **5.0%** | **4.0%** | **3.7%** | **3.6%** |
| 改之后 | 23.7% | 13.3% | 14.7% | 9.0% | 6.5% | 8.5% | **6.5%** | **7.7%** | **4.0%** | **6.0%** |

原因：第 21~30 波有 80% 的波次带修饰，而**修饰会整表替换刷怪表** ——
那三张表是七种敌人时代写的，从没更新过。于是六种「逼你改打法」的怪
在高潮段只占 16.3%，只会直线冲刺的刀锋犬占了四分之一。
**我加了三种新怪，却让它们在最需要变化的地方基本消失了。**

补了三个用新怪做的修饰（裂变 / 封锁线 / 拖网）之后，那六种合计
**16.3% → 52.2%**。并且加了一条元断言：**每一种「逼你改打法」的怪
都必须至少进一个修饰的刷怪表** —— 下次加第十一种怪时会直接红。

## 十七、两条被新内容作废的旧决定

改完之后探针 5 局有 4 局死在第 21~22 波，死因高度集中。查出来是两条
**当初合理、现在不合理**的决定：

1. **「封锁线」让钉枪手占半张表。** 远程怪的威胁随数量是【乘性】的 ——
   第 21 波那张表刷出约 40 个钉枪手，就是每秒 40 条弹线，有预警也躲不过来。
   钉枪手该是「盾墙后面的两个神枪手」，不是一整波。压到 1/4，
   并写进断言：远程怪在任何修饰里不得超过 1/3。
2. **「第三层每一波都带修饰」。** 这是只有 4 个修饰、8 种怪时定的；
   7 个修饰 10 种怪之后，同一条规则把第 21 波变成了一道墙。
   压到 0.82 —— 五波里还能摊上一波平稳的，给人喘口气的节拍。

第二条原来还有一条断言守着它（「第三层每一波都带修饰（故意的）」）。
**断言也会过期：它锁住的是一个决定，而决定的前提变了。**

## 十八、机制的频率不能跟场上数量走

拖曳者的钩索，实测第 25 波：

| | 被钩时间 | 同时几条 | 场上几个 |
|---|---|---|---|
| 一开始 | **84%** | 6 | 7~9 |
| 加「同时只许一条」 | **98%**（更糟） | 1 | 8 |
| 改成全场共享冷却 | **34%** | 1 | 3 |

第二步为什么更糟：八个拖曳者轮着钩，一条刚松下一条立刻接上。
**毛病不在「同时几条」，在「频率跟着密度走」** —— 密度是后期必然上涨的东西，
任何挂在它身上的机制都会在后期失控。改成全场共享一个冷却，频率就跟数量无关了。

还有一个细节：冷却必须在**起钩时**就占住。只在结束时设的话，同一帧里所有
冷却好了的拖曳者都会看到 `hookCd<=0`，一起起钩（实测同时 3 条）。

顺带把拉力从写死的 108 改成 `P.speed * 0.55`。原来那个值跟基础移速 82
差不多，等于直接把人拖走；挂在移速上之后「义体伺服」这条词条顺带成了「抗拽」。

## 十九、量具自己的两个 bug

这一轮两次被自己的工具骗：

1. **测混合比的脚本手动设了 `G.budget = 60`**，而修饰的预算倍率是在
   `nextWave()` 里生效的 —— 于是我调了两轮「兽潮预算」，而测量从头到尾
   没看到 budget。表现是：改完数字**一点没变**。
   幸好没变这件事本身就是线索 —— **改了东西而指标完全不动，先怀疑量具。**
2. **探针机器人不打提前量。** 它瞄目标的当前位置，而子弹飞 100px 要 0.37 秒，
   期间怪走了 9px，而怪的半径只有 5px。后果是探针报了两次「卡住了」：
   场上剩几只慢怪，机器人全速开火 175 秒打不死。
   我先怀疑了掩体挡子弹、怀疑了射程、怀疑了死亡清理 —— 全都不是。
   最后靠打时间序列（`fireT` 稳定、子弹一直有 3~5 颗、目标不死）才定位到。

**「卡住了」这个结论出现的时候，先分清是游戏卡住还是量具卡住。**

## 二十、试玩反馈两句话，查出三个问题（其中两个是我造的）

反馈原话：「分不清经验点和敌人的子弹」「血条没看到」。

**一、只靠颜色区分。** 经验点是「r=4.5 绿色光斑 + 2×2 白芯」，
敌方子弹是「r=6 橙色光斑 + 2×2 白芯」—— 辉光会把颜色往白里洗，
于是两个都只是「带白心的小亮点」，玩家会走过去捡子弹。

**这跟第三节记的「五种敌人都是圆角方块加亮中心，只有颜色不同」是同一个错，
我又犯了一次。** 改法也一样：靠形状和运动区分。
子弹画成沿速度方向的曳光（又直又快、朝向就是它要去的地方），
经验点画成慢慢转的菱形（尖轮廓、几乎不动）。

**二、血条在 HUD 左上角，而打起来眼睛一直在自己身上。**
把血量画成玩家身上的一圈弧：满血不画（平时不糊），掉血就出来，越低越显眼。
低血时再给全屏四边压一层红 —— 激战时视线会跟着敌人跑，需要一个不看也知道的信号。

这里踩了一个小坑：**危险时血环用纯红，正好跟全屏红警同色，
于是它在最需要读它的那一刻消失在背景里。** 改成近白的粉 + 外面套一圈红边。

**三、血条真的被挤没了。** 量了一下：HP 条在 375 宽的手机上只有 **2 像素**
（旁边的经验条是 125）。原因是我这一轮把波次进度条和数字加进了 HUD 顶行，
右边那组挤满之后，左边 `flex:1` 的血条被压成 0 —— `flex:1` 的默认 basis 是 0，
空间不够时会一路压到没。

**「血条没看到」是字面意思，不是「没注意看」。** 加了 `min-width` 和行内换行。

教训：**加一个 HUD 元素的时候，去量一遍同一行里别的元素还剩多少宽。**
挤没了的东西不会报错，只会安静地变成 2 像素。

## 二十一、玩家问「怎么做 X」，等于界面没说 X

被问到「怎么获得新枪」。机制本身是好的，两步：

1. 里程碑把枪**解锁进卡池**（活到第 4 波 → 霰弹枪，近身拆 8 台重装 → 振动刀…）
2. 进池之后两条路拿到手：局内升级三选一抽到（永久带着），或者花 150 废钢买成起手武器

问题在于界面只说了一半。标题页那个 chip 写的是 `霰弹枪 150废钢` ——
**读起来像「想用这把就得付 150」**，完全没提它解锁之后已经在局内卡池里了。
唯一说清楚的地方是解锁那一瞬间的横幅（「霰弹枪进卡池」），一闪就没。

改法：chip 的三种状态给三种说法（未解锁 / 已在卡池里 / 已买下），
价钱前面加「起手」两个字（`起手 150`，而不是裸的 `150废钢`），
再在那一行下面补一句把两条路都讲全。

**「玩家问怎么做某件事」是最直接的 UI 缺陷报告** ——
不用去猜哪里不清楚，他问的那件事就是答案。「分不清经验点和子弹」
「血条没看到」「怎么获得新枪」「商店买的只在这局有效吗」，全都是这种。

最后那条尤其值得记：商店的四样**确实**都只在这一局有效（验过：新一局回到只带
起手那一把、重摇归位、血满、局内废钢清零，档案里的 `bought` 一个没动），
**代码是对的，但面板上一个字都没写。** 同一种货币横跨「局内花」和「存起来换
永久起手武器」两个时间尺度，不写明白，玩家只能靠猜或者靠问。
现在面板上直接写两行：买的东西只在这一局有效 / 没花完的会存进档案。

## 二十二、商店：不引入第三种货币，也不卖数值

加掉落金币 + 波间商店时定了两条：

**一、金币就是废钢，不引入第三种货币。** 已经有经验（局内）和废钢（跨局），
再加一种「金币」只会让人分不清哪个能干什么。改成废钢局内掉、局内能花，
**局末没花完的存进档案** —— 于是「现在买」和「留到下一局」变成一个真决定，
而不是白送一套新系统。

**二、只卖消耗品和内容，不卖永久数值。** 里程碑那条元断言守的就是这个
（元进度给新东西，不给数值膨胀），商店同理 —— 它一卖伤害就变成
「用废钢换 DPS」，而 DPS 这条线已经由词条负责了。四样：
现场修复（回血）/ 注入强化（随机临时增益）/ 多一次重摇 / 军械调拨（买一把已解锁的枪）。
最后那样正好回答了上一轮「怎么获得新枪」：从「等卡池抽到」多了一条「花钱现在就要」。

配套写了一条断言：**逛一圈买光，词条倍率 / 生命上限 / 移速 / 暴击 / 护盾 /
静电场 / 汲取一个都不许动。** 第一版我写成「P.dmg 一个数都不许变」，
结果买枪就红了 —— 换了把枪当然是不同的数值，那不叫膨胀。
**断言要盯住「倍率」，不是盯住某个具体字段。**

定价靠量，不靠感觉：实测一局能捡 1500~3800 废钢（平均约 2800），
所以价钱是 80~300 这个量级。凭感觉定成几十的话商店等于免费。
实测结果：满局买 15~16 次、存 1500~2200；第 5 波就死的那局只捡到 41 废钢，
**商店一次都没弹** —— 它只在「真有东西给你」的时候才拦一下。

## 二十三、量具校准了三次，每次都被当成游戏 bug

这一轮探针报了三次「卡住了」，全是它自己的毛病：

| 症状 | 真因 |
|---|---|
| 剩几只慢怪，全速开火 175 秒打不死 | **不打提前量**：子弹飞 100px 要 0.37s，怪走 9px，而怪半径只有 5px |
| 一只站在远处的母巢让它干等三分钟 | **从不主动靠近**，只会退和捡东西 |
| 一波磨 25 秒，最后某一波触发假卡死 | **死区错位**：「<110 退、>130 追」让它一直悬在 110~130px，那个距离打得最慢 |

第三条最隐蔽：把门槛压到 75/95 之后卡死消失了，但它开始贴太近，
5 局有 2 局第 5 波前就死 —— 两头都不对。最后改成**交战距离跟着周围有几只走**
（`min(130, 70 + 附近数量×9)`），因为人的打法本来就是「人少贴上去、人多拉开」。

**一个固定阈值表达不了「怎么打」，而用固定阈值的量具会替游戏背锅。**

## 二十四、加内容有个反直觉的副作用：稀释

加了三把武器（光束 / 布雷 / 回旋）、四条词条、两种增益之后，探针直接变差：
**5 局里 2 局第 5 波就死**。而我什么数值都没动。

原因：词条从 18 条加到 22 条，而升级是三选一 ——
**每加一张牌，任何一张【特定】的牌就更难抽到。** 开局抽不到伤害，就起不来。

改法：新加的机制牌加 `from` 门槛（第 5~7 波才进池），
让开局的牌池保持紧凑，复杂度往后放。实测开局池 14 条 / 第 9 波 21 条。

**这条对「加内容」这件事是通用的：池子变大 = 池子里每样东西变稀有。
早期需要的确定性，得靠门槛保住。**

三把新武器各自的身份也是刻意区分的，而且都写进了断言：

| | 打法 | 代价 |
|---|---|---|
| 熔切光束 | 一条线咬住最前面那一个，单体最快 | **不穿透** —— 成群最废 |
| 布雷器 | 脚下放雷，不用瞄 | 半秒待发，场上最多 6 颗 |
| 回旋刃 | 飞出去再飞回来，来回各穿一次 | 要把敌人站成一条线 |

光束刻意不穿透 —— 让它穿的话它就是「又快又能扫一排」，比谁都强，那八把枪就白设计了。

## 二十五、量具的能力边界也要写下来

探针换到布雷器就卡住：那把枪的本事是「算他们会走哪」，
而机器人只会瞄着打，换上去一发都打不死。

这不是那把枪的问题，是**量具评估不了技巧是位置性的武器**。
所以让它跳过布雷器，并把原因写在代码注释里 ——
否则下次有人看到「机器人从不用布雷器」会以为那把枪有 bug。

同一轮还修掉一个更隐蔽的：**朝场中的拉力把追击抵消了**。
目标缩在角落时，「追上去」和「回到场中」两个向量打平，机器人在原地打转
（实测：剩一个中继在角落，152 秒不动）。
**已经决定要贴上去了，就别让位置启发式把这个决定撤销。**

## 二十六、逐条 A/B 才找得出是哪一条坏的

这一轮加了场地互动物（传送带 / 熔渣 / 冷凝罐）和精英词缀（五条）。
加完探针从平均 22.4 波掉到 **9.8**，4/5 局死在第 11 波。

我先猜了三次都不对：以为是裂片、以为是护盾挂在快怪身上、以为是机器人看不见地形。
每次"修完"都只好一点点。最后做了**逐条 A/B**：

| 配置 | 平均波次 |
|---|---|
| 基线（无词缀无地形） | 19.2 |
| 只留 自愈 | 20.6 |
| 只留 护盾 | 20.8 |
| 只留 殉爆 | 21.8 |
| 只留 呼叫 | 20.8 |
| **只留 崩解** | **9.0** |
| 全部五条 | 9.6 |

**四条是中性的，就一条把平均波次砍了一半。**
原因：裂片【不占预算只占密度】，而且就在你脸上生成两只快怪 ——
一波清不干净，伤害一直累积。

删掉它，而不是继续调权重：「死了会裂」这个教训「裂解体」那个怪种已经在讲了，
词缀再讲一遍本来就是重复的。删完之后四条词缀全开 19.6 波 vs 基线 19.2 ——
**加了内容而曲线没动**，这才是想要的结果。

**一次加五样东西，出了问题就只能逐条关掉来找。
猜三次的时间够做完整个 A/B 了。**

## 二十七、量具改多了，绝对数字就不可比了

这一轮为了让探针能量这些新东西，又改了它四处：
避开地形危险、集火残血 BOSS（但不能无脑集火，第一版让它 4/5 局死在第 5 波）、
跳过它不会用的布雷器、以及最后一条 ——

**卡死的判据从「波次号没变」改成「波次号没变【而且】一个都没杀」。**
只看波次号的话，一场打满三分钟的 BOSS 波会被误报成卡死。
我为此查了半天「phase=break、场上空、waveT 还是正的」到底哪里坏了 ——
答案是根本没坏，那是这一波【刚打完】的瞬间。

代价是：**探针的绝对波次在不同版本之间不能比。**
这一轮前后的 22.4 → 16.8 里，有多少是内容变难、有多少是机器人变强/变弱，分不开。
可信的只有**同一个版本内部的 A/B 对照** —— 上面那张表就是这么来的。

以后报数字要说清楚是哪一种。

## 二十八、给经营层定规矩：只给选择，不给数值

废钢原来只有一个去处：8 把起手武器 × 150 = **总共 1200**。
而一局能存 1500~3800 —— **打两局就把整个元经济买空了，之后废钢彻底没用。**
这就是加模拟经营该填的坑，不是凭空加个系统。

加的是据点 + 生产链：废钢 --精炼炉--> 精炼钢 --装配台--> 九把枪各一个改装件。
全盖满要 20800 废钢，几十局的长尾。

规矩跟里程碑、跟商店是同一条：**只给选择，不给数值**。所以：

- 五栋建筑没有一栋是「伤害 +x%」——给的是「商店多一格」「开局知道哪几波带修饰」
  「指定一条词条做保底」这种**改变决策**的东西
- 九个改装件**每一个都是交换**：点射管拿射速换穿透、散焦透镜拿单体伤害换扫一片、
  分裂棱镜拿伤害换两条线、遥爆模块让雷改成手动引爆

配了三条断言守这个：建筑的文案里不许出现战斗数值词；每个改装件的说明里
必须写出代价；逐个改装件跑 equip 前后对比，**必须同时有「降了什么」和「升了什么」**。
第三条当场抓到一个：反冲刃的说明只写了好处（"当位移用"），没写它会把你弹离目标 ——
机制本身是交换，但**文案把代价藏起来了**，那玩家就会以为它是纯赚。

最后量了一件必须量的事：**据点全盖满会不会把游戏变简单？**

| | 撤离成功 | 死亡波次 |
|---|---|---|
| 新档案（据点全 0） | 1 / 5 | 15, 26, 8, 5 |
| 据点全满 + 三个改装件 | 0 / 5 | 26, 12, 17, 5, 5 |

**没有变简单。** 这不是我说的，是量出来的 —— 而这正是「只给选择不给数值」
应该产生的结果：元进度扩大的是可能性，不是战斗力。

## 二十九、开店：先让「捡的东西」有身份

被要求「用捡的东西开店」。第一步不是画店铺界面，是承认一件事：
**现在捡的东西没有身份** —— 掉落只有经验、血包、废钢、增益，
而废钢是可替换的数字，不是「一件东西」。

所以先加九种零件，而且**每种绑定到特定的敌人**：
重装机甲掉伺服马达、无人机掉光学镜组、拖曳者掉绞盘齿轮、BOSS 掉核心碎片。
这一步本身就有价值 —— **「今天想要光学镜组」变成「这局多打无人机」，
敌人选择第一次有了战斗之外的理由。**

然后是店铺。这套东西做坏了就是「点一下卖掉」的杂活，分界线只有一条：
**定价要有牙齿**。所以写了三条断言专门守它：

- 贱卖 12 件 → 漫天要价 0 件（**出价高真的会流失客人**）
- 中位价的**单件收入高于贱卖**（所以不是「越低越好」，是个真决定）
- 一直赶客人，名声 80 → 50，来的人从 10 个变 8 个（**贪一次没事，一直贪就没人来**）

反馈分三档，颜色也分三档：灰「爽快掏钱」/ 橙「嫌贵，犹豫了一下走了」/
红「『抢钱呢』，头也不回」。几次之后你就摸出了价位带 —— 这是**教学**，不是惩罚。

行情每局摇一次（两种缺货 ×1.5、一种积压 ×0.6），所以该 farm 什么一直在变。
而刚做的**情报站**正好能提前告诉你 —— 两个系统自己接上了。

最后还是那条规矩：**卖的钱进废钢，喂给据点，不直接变战斗力。**

顺带记一个撞车：我把零件库存写成 `G.parts`，而 `G.parts` 是**粒子数组** ——
`muzzle()` 一调 `G.parts.push` 就炸。改叫 `G.loot`。
**往一个几千行的全局状态对象里加字段之前，先 grep 一下这个名字。**

**后记：紧接着又被问「据点有什么用」。** 三个栏目标题（货摊 / 建筑 / 武器改装）
说得清「这是什么」，说不清「它们怎么串起来」—— 而精炼钢是干嘛的、
为什么要盖精炼炉，全靠玩家自己拼。

补了一行会变的链条说明：`打一局捡零件 → 货摊卖成废钢 → 盖建筑 →
精炼炉炼出精炼钢 → 装配台装改装件`，**做到的步骤高亮、没做到的是灰的**，
下面再跟一句「你现在该做什么」。五个阶段五句不同的话 ——
**讲全套只会糊在眼前，讲下一步才有用。**

这是这轮对话里第六次「玩家一提问就暴露出界面少了一句话」。
系统越多，这种缺口越多：每加一个系统，就多一条它和别的系统之间没人解释的关系。

## 三十、泄压阀要一路修到底

"一波清不掉就永远卡着"这个问题修了三次，每次都是探针撞出来的：

1. 三十只带盾的正面只进 15% 伤害 → 加时 12 秒后护盾**过热失效**
2. 母巢一直吐无人机，清得比吐得慢 → 加时后 BOSS **停止召唤**
3. 预算 0、场上只剩 2 只、过热已开，还是 152 秒没推进 ——
   两只残兵在远处游荡，玩家得满场追 → 加时后残兵**一律直冲玩家**

前两次我都以为修完了。**"卡住了"这个结论没有用，"为什么卡住"才有用** ——
后来给探针加了卡住时的诊断（预算剩多少、场上几只、BOSS 还有多少血、加时多久、
过热开没开），第三个原因是这行诊断直接说出来的，不是我猜的。

## 三十一、数据全对，屏幕上没有

宠物做完了，断言全绿：局内生成了、会追上来、不参与战斗、重开会清。
打开浏览器一看——**没有狗**。

狗一直在，位置也对：跟在玩家身后 15px。可玩家自己的光晕半径就有 13、
身子高 16，狗整个埋在里面，放大八倍才看得见一点橙色边。

同一天的第二个：护航无人机是青色胶囊，画在玩家周围 26px 的轨道上。
问题是电容零件掉落和经验尾迹也是青色胶囊。三个一模一样的东西飘在你身边，
哪个能捡、哪个是你的，看不出来。

这是第三次栽在同一件事上了（前两次是敌人子弹像经验点、低血环像低血暗角）。
每次的共同点都是：**数据层每一条都对，只有画出来那一帧是错的**，
而断言全都写在数据层。

两条结论：

1. **换颜色救不了。** 泛光会把亮色一律往白里洗，分不清的东西换个颜色还是分不清。
   能用的只有**形状、运动、连线**。跟班的解法是从玩家身上牵一根线过去——
   没有任何掉落物会连着你，这是不会撞车的信号。
2. **把桩的画布打开录制。** 原来 `ctx` 是个什么都不做的 Proxy，
   于是"画出来长什么样"在离线环境里根本观察不到。现在 `ctx.__rec()`
   之后每次调用和赋值都进 `ctx.__ops`，能直接断言
   "每架跟班都有一根 moveTo(玩家)→lineTo(跟班) 的线"。

顺手补的两条也是同一类，都只能在画布这一层量：

- 站着不动时宠物停在光圈外（离你 27px > 光晕半径 13）
- 跟班绕到正上方时也在身子外面（最近 20px > 人高 16）

## 三十二、首页的数字会自己过期

加完东西回头看首页，写着"22 条改装词条"——实际已经 23 条了。
不知道是哪一次加的时候忘了回来改。

首页那段介绍通篇是具体数字（九把武器、十一种敌人、三十波、22 条词条），
这些数字是**从代码里读得出来的**，那就不该靠人记得同步。
加了一节断言直接拿 `NS.UPGRADES` / `NS.MOB` / `NS.LAST_WAVE` 去比，
汉字数字也认（"九把武器""三十波"）。

## 三十三、手机上的版面 bug，肉眼看不出「差一点」和「压住了」

这轮手机 UI 是拿 `getBoundingClientRect` 一个个量出来的，不是看截图看出来的。
量之前我盯着同一张截图看了好几轮，只觉得"有点挤"。量完是这样：

| | |
| --- | --- |
| `废钢` 标签 y37，它的值 y58 | 中间隔着一整行 —— 两个都读不成 |
| `btnPause × 武器框`、`× 废钢`、`× 废钢值`、`btnMute × 废钢值` | 四处真重叠 |

原因都很朴素：HUD 的第二行是九个平铺的 flex 子元素，宽度不够就在任意两个之间
断开，正好会把标签和它的值劈成两行；而右上角那两个圆键浮在所有层之上，
分数一变长 HUD 就排到它们底下去。

三条可复用的结论：

1. **标签和值要捆成一个 `white-space:nowrap` 的单元**，让它们一起换行。
   条（`flex:1`）不能直接塞进 `inline-flex` 单元 —— 会缩成 `min-width` 不再伸长，
   得给单元自己 `flex:1 1 auto;min-width:0`。
2. **有浮层按钮的角落要在布局里显式让开**，不能指望内容自己不长过去。
   写成断言就是「让出的宽度 ≥ 圆键那一块的宽度」，两个数都从 CSS 里读出来比，
   而不是写死 108。
3. **弹窗开着的时候整套触屏控件收起来**。摇杆和冲刺这时是死的，
   右上角两个圆键还会压在弹窗自己的文字上（商店那句「买的东西只在这一局有效」
   被盖掉过半句）。暂停页是例外 —— 藏了就点不回来。

还有两个纯粹是"手机上不该长这样"：

- 拾荒犬的九选一铺成九条通栏按钮，手机上 600px 全长一个样。改成 3×3 格子，
  据点整屏从 1544px 缩到 1297px。**单选用格子，通栏留给「有副标题和价格」的条目。**
- 据点是一条一千多像素的滚动，而每个决定都是"买不买得起"，钱却会滚出视野。
  钉住。`#hqBox` 是 grid + `justify-items:center`，横向要用 `justify-self:stretch` ——
  我先写的 `align-self:stretch` 在 grid 里管的是纵向，条只有内容那么宽，两边照样漏。

### 离线能验的和不能验的

`getBoundingClientRect` 在 DOM 桩里是个死值，所以几何量不了。能验的是
**让几何不可能出错的那些约束**：标签没有一个游离在单元外、让出的宽度够不够、
吸顶条是不是横向铺满、弹窗开着时 `#tc` 有没有 `modal`。

最后一条本来也验不了：那三行 `classList.toggle` 原来写在 `loop()` 里，
而桩的 `requestAnimationFrame` 是空函数。抽成 `syncTC()` 之后既能验，
也顺手去掉了"要等下一帧才生效"。**为了能验而抽出来的函数，往往本身就更该抽。**

## 三十四、"整屏都是列表"是三件事凑出来的

被说"据点现在就是纯列表，chain 里文字也展示不全"。拆开看是三个独立的毛病：

**一、中文没有词边界。** 顶上那条链是一句话，`打一局捡零件 → 货摊卖成废钢 → …
→ 装配台装改装件`，手机上被劈成「装配台装 / 改装件」。
换行只发生在宽度不够的时候，而中文任何两个字之间都是合法断点。
改成一排 `white-space:nowrap` 的格子就不可能再断错。

**二、它只是句话，跟下面没有关系。** 既然已经把链拆成五步，
每一步就能 `data-go` 到对应那一栏 —— 顶上这条同时是进度和目录。
手机上据点有近 3000px，"精炼钢在哪买"原来得自己往下翻。

顺手多出来的第三档：原来只有"走过/没走过"两档，
「我现在卡在哪」还得自己数到第一个灰的。加了 `now` 一档之后，
**当前那一步和提示文字就能从同一个地方算出来** ——
之前它们是两条并行的 if 链，改一条忘另一条就会互相打架。

**三、真条目和假条目混在一起。** 「槽位 0/1 —— 每个改装件都是交换」
「拾荒犬今天闻哪一种」「先盖装配台」这些纯说明，全都包在 `.hqi` 里，
长得跟可点的条目一模一样。一屏里十几条一样的框，当然像列表。
说明文字换成 `.phint`，状态（几栋 / 几槽 / 几只）挂到栏目标题上，
建筑的等级从名字后面的罗马数字换成一排格子 —— 盖没盖一眼就看得出。

### 顺带修掉一个自己上一轮埋的

据点吸顶那条钱，上一轮是用 `box-shadow:0 -22px 0` 把容器上内边距那条缝糊住的。
但条**还没吸住、还排在流里**的时候，那块投影会盖掉它上面的东西 ——
正好是这次新加的链条提示，「盖装配台才能……」被糊掉半行。
正确做法是把容器的上内边距挪走，让条真的顶得到 0。

**守着它的那条断言本身也写错了** —— 我写的是「有没有 `box-shadow:0 -Npx 0`」，
于是换了实现就假红。改成「顶上不漏缝：要么容器没有上内边距，要么投影盖住」，
两种修法都认。**断言要认「这个问题解决了没有」，不是「你有没有用我当时那招」。**

### 还有一个

跳转用的是 `scrollIntoView({behavior:'smooth'})`。
这一屏里滑动不是装饰，是唯一的导航 —— 系统开了「减少动态效果」的时候
它不能变成"点了没反应"。改成 `REDUCE ? 'auto' : 'smooth'`。

## 三十五、"在哪看"这种问题，答案通常是"哪儿都看不到"

被问「我的背包和货箱在哪看」。查了一遍，诚实的答案是：

| 什么时候 | 看得到吗 |
| --- | --- |
| 局内捡到 | 闪一条横幅「电容组 收进货箱」，然后什么都没有 |
| 结算页 | 只写 `+N 废钢`，**零件一个字都不提** |
| 据点货摊 | 只列手上有的那几种 —— 空箱子等于这一栏不存在 |

零件是开店那条线**唯一**的原料，捡了一路，三个节点里有两个半装作它不存在。

三处都补：

1. **暂停页加第三个页签「货箱」。** 零件在局内既不能花也不能扔，
   所以它不配占 HUD —— 但「今天缺货的那种我捡到没有」是个真问题。
   列全九种，带当天行情，`+3` 是这局捡的、`箱里 8` 是存量。
2. **结算页写明捡到什么。** `+312 废钢 · 零件 电容组×2 伺服马达×4`。
3. **据点货摊上方一条完整货箱**，九种全列，没有的压暗。

### 顺手踩到两个老坑

**又撞名了。** 新行写成 `.brow`，而构筑面板（`.build .brow`）早就在用这个名字。
`.build .brow` 权重更高，压得住 `display` 和 `gap`，**压不住我多写的
`padding` 和 `border-bottom`** —— 于是构筑面板每一行底下都多了条分隔线。
全部挪到 `.bag` 作用域下。这是第三次（`G.parts` 撞粒子数组、`BASE` 撞玩家属性）。

**改了实现，旧断言变成永远绿的废断言。** 暂停页页签从布尔 `dex-on`
改成具名 `tab-build/tab-bag/tab-dex` 之后，原来那两条
`ok(!byId('pauseBox').classList.contains('dex-on'), …)` 恒为真。
它们**没红**，所以差点没发现 —— 这比直接红了糟得多。
改成「现在亮着的是哪一页」这种会随实现一起失效的写法：

```js
const onTab = () => ['build','bag','dex'].filter(k => cls.contains('tab-' + k));
ok(onTab().join() === 'build', `每次暂停都先回到构筑页（现在是 ${onTab()}）`);
```

**删掉或改名一个 CSS 类 / 状态标志之后，要去搜断言里有没有它** ——
搜出来的每一条，要么跟着改，要么它现在正在空转。

## 三十六、名字要标在「同一类里分不出哪个」的东西上

被问「显示掉落道具的名字，要不不认识」。地上的东西有五类：
经验点、废钢、治疗包、零件、增益。前三类各只有一种形状一个意思，
第一次捡过就认识；**零件九种、增益六种，全靠颜色区分** —— 而泛光会洗色，
这一点前面已经栽过三次了。

所以只标后两类。全标的代价是战场上糊一层字，而且会把「这个我不认识」
这个真信号淹掉。**标注的判断标准是「同一个形状底下有几种意思」，
不是「这个东西重不重要」。**

### 画布上写不了字

游戏的画布是 320×180，`ctx.fillText` 在这个分辨率下必糊 —— 所以这一版
**整个游戏没有一处往画布上写字**，HUD、横幅、暂停面板全是 DOM。
掉落物名字也一样：一个 `.dtag` 池，按百分比贴。
`#stage` 是 `position:relative`、画布是它唯一决定尺寸的孩子，
所以 `.layer{inset:0}` 正好盖住画布，**百分比定位就不用每帧去量
`getBoundingClientRect`**。

配套的断言直接守住这条架构约束：

```js
ok(!/ctx\.fillText/.test(html), '名字走 DOM，不往画布上写字');
```

### 名字说不出「它干什么」

牌子上只写得下名字，而「超频」两个字本身没有信息量。
敌人那边这个问题是靠图鉴解决的 —— 增益原来只有捡起来那一瞬间的横幅，
错过就没了。把六种增益也加进图鉴，写明效果和秒数。

敌人是「遇到过才解锁」，增益不锁：**知道有这东西不构成剧透，
而「值不值得冒险跑过去捡」这个决定恰恰需要先知道它管几秒。**

## 三十七、需要解释才看得懂的标签，就是写坏了

构筑面板上写着「已装载 3 / 72 层」。被问「72 是什么意思」。

72 = 全部 23 条非武器词条**一条不落全叠满**的总层数。而一局打到三十波
也就三十层左右 —— **这是个永远到不了的分母**，除了"还有很多你拿不到"
之外什么信息都没有。当初写它的意图是表达"一局只拿得到一小部分"，
但 30/72 既不是一半，标签本身也没说这句话。

换成真正回答构筑问题的两个数：**`已装载 5 种 · 6 层`** ——
摊了几种、叠了几层，正好是"我是铺开了还是专精了"这个决定需要的。

守着旧写法的那条断言，连它自己的理由都是错的：

```js
ok(h.indexOf('3 / ') >= 0, '总层数也写出来 —— 一局只拿得到一半，这个数字是有意义的');
```

"一局只拿得到一半"是我当时想当然写下的，实际是 42%。
**断言的说明文字也会撒谎，而且比代码更少被复查。**

## 三十八、同一个问题被问第二次，说明答案不在游戏里

「我的背包在哪看」问了两次。第一次我加了暂停页的「货箱」页签 ——
然后在聊天里告诉他在哪。游戏里一个字都没说。会问第二次是必然的。

**指路要在问题产生的那一刻给**，而不是指望人去翻暂停面板：

- 捡到**第一件零件** → 「零件进了货箱 · 暂停 →「货箱」看这一局捡了什么，回据点在货摊卖掉」
- 捡到**第一个增益** → 「只管几秒。六种分别干什么，暂停 →「图鉴」里都写着」

走的是敌人图鉴那套现成机制：同一条提示队列、同一份档案记录、只播一次、跨局也记着。
**功能做完了不等于做完了 —— 还差一条把人领过去的路。**

配套断言里有一条是专门防我自己的：

```js
ok(!!byId('tabBag') && !!byId('tabDex'), '指过去的两个页签真的在');
```

指路文案写死了「暂停 →「货箱」」，页签哪天改了名字或挪走了，
这句话就变成假路标 —— 比没有还糟。

## 三十九、一串「这是什么意思」，说明缺的不是提示而是说明书

短时间内被问了一串：`72 层是什么意思`、`背包在哪看`、`战斗中会掉道具吗`、
`掉的东西不认识`、`据点有什么用`、`怎么获得新枪`。

每一条我都单独补了：改标签、加页签、加地面名字、加首次指路、加链条。
**但这些全是补丁 —— 缺的其实是一处从头讲清楚「这游戏怎么玩」的地方。**
标题页加了「怎么玩」。

写这份东西的三条硬规矩：

1. **说人话，不许拿游戏内造词开头。** 先说「血」，别上来就是「整合度」。
   写了条断言直接禁掉：`ok(['整合度','义体等级','拆解数'].every(w => txt.indexOf(w) < 0))`。
2. **数字一律从数据里读。** 首页那段介绍就是写死数字，结果「22 条词条」
   过期了一阵子没人发现。这份里 `打穿 30 波`、`一共 23 张牌`、`一共 9 把`、
   `敌人 11 种` 全是算出来的，断言再拿同一份数据回比一遍。
3. **操作按设备只给一套。** 手机上出现 WASD 是四行废话。

末尾放一张「卡住了看哪里」的速查表，把前面那一串问题一次性答掉。
配套断言守着这张表：**指过去的页签必须真的存在** ——
写死的路标最容易变成假路标，比没有还糟。

### 顺手踩到的层叠上下文

新面板打开后，标题页那个吸底的「接入神经索」浮在它上面。
原因是 `.screen` 是 `position:absolute` + `z-index:auto`，**不构成层叠上下文**，
所以吸底栏那个 `z-index:2` 是直接跟根层比的，DOM 顺序压不住它。
据点没这个问题，因为 `showHQ()` 会把标题页 `.show` 摘掉 —— 照抄就行。
**同一屏里已经有人解决过的问题，先去看他怎么解的。**

## 四十、「放弃这局回不去」其实是「任何一局结束都回不去」

报的是「放弃这局没法回到最开始界面」。查下来范围比这大：
**结算屏上只有「重新接入」，一按就直接开下一局** ——
换模式、换危险档、换起手武器、进据点、看怎么玩，一局结束之后全都够不着。
放弃的时候最难受，是因为你放弃多半就是想去改点什么。

加了「回标题页」。这类 bug 的特征是**每条路单看都通，只是没有回头路** ——
测的时候顺着玩不会发现，得问一句「这一屏能去哪」。

## 四十一、右上角那块地，第三次撞车了

连击数贴在 `top:60`，而手机上暂停/音乐两个圆键占着 `top 54 → 98`。
全场最该一眼看到的数字压在按钮底下。

同一块地之前撞过两次：HUD 的废钢数字、商店标题那行字。
**修法应该是一样的：让出这块角。** 断言也照着上一次的写 ——
两个数都从 CSS 里读出来比，而不是写死 106：

```js
ok(combo >= top + h, `手机上连击数排在圆键下面（${combo}px vs 圆键到 ${top + h}px）`);
```

### 顺带抓出一条漏了两年的

挪完连击之后回标题页，正在淡出的「x17 COMBO」挂在标题正文上。
`body.menu` 那条只藏了 `#hud` 和 `#buffs` —— 后来加的 `#comboWrap`
和这一轮加的 `#dtags` 都漏在外面。

守着它的断言是这么写的：

```js
ok(/body\.menu #hud, body\.menu #buffs\{display:none\}/.test(html), '标题和结算页藏掉局内 HUD');
```

**它盯的是「这条 CSS 长什么样」，不是「有没有漏下的」** ——
所以新加两层它一声不吭。改成从标记里数出所有 `class="layer"`，
逐个查在不在那条规则里，例外要写明理由：

```js
const layerIds = [...html.matchAll(/<div class="layer" id="(\w+)"/g)].map(m => m[1]);
const exempt = ['tc', 'banner'];   // #tc 自己有一套；#banner 在菜单页本来就是空的
```

这样下次再加一层，它会逼你做一次决定。
**「有没有漏」这类断言，得从数据里数出全集，不能手写名单。**

## 四十二、「看起来选中了两个」是两个 bug 叠在一起

报的是「选了霰弹枪之后框变高亮了，但是脉冲步枪还是选中态」。拆开是两件事：

**一、买不起的时候静默失败。** `buyWep` 在废钢不够或没解锁时直接
`return false` —— 不改任何状态，也不说一个字。玩家点下去，什么都没发生。

**二、触屏上 `:hover` 会粘住。** 点过的那个 chip 挂着青色边框不掉，
而真正的选中态是青色填充。两个一起看，就是「同时选中了两个」。

修法：

- 失败必须说原因，而且要**具体到还差多少**，还要说清「不买也能在局内抽到」——
  否则那 150 废钢看着像一道必须付的门槛。
- 提示**紧跟在「起手」那一排下面**。我第一版挂在面板最末尾，
  你在顶上点的枪，解释出现在四百像素以外，等于没说。
- 带选中态的那几类 `:hover` 关进 `@media (hover:hover)`。
  **一条一包，不能包范围** —— 媒体查询不改权重也不改源码顺序，
  但包一个范围会把中间不该包的规则一起吞掉（我第一刀就是这么下的，当场看出来了）。
  也不能改用 `body:not(.touch)` 加前缀：那会抬高权重，
  `#prof .chip:hover` 会反过来压住 `#prof .chip.on`。

### 断言顺手抓出一个埋着的存档 bug

写「没解锁的枪不许买」那条时它红了：**清空档案之后，磁轨枪居然买得下来。**

根因在 `loadProf`：

```js
Object.assign({}, PROF_DEF, JSON.parse(localStorage.getItem(PROF_KEY)) || {})
```

`Object.assign` 是**浅**的。存档里缺哪个键（旧存档、新加的字段、无痕模式读不出来），
`PROF` 的那个字段就**直接是 `PROF_DEF` 里的同一个对象** ——
之后往 `PROF.unlocked` / `PROF.parts` 里写东西，会把默认值本身改掉。

游戏里暂时没炸，是因为 `PROF_DEF` 加载之后没人再读。但它是个雷，
而且已经真的污染了验收里那个 `fresh()`（清档案重开），
意味着**用同一套 `fresh()` 的别的用例，也可能一直跑在被污染的默认值上**。

改成先深拷一份再合并，并加了两条断言守着：每个字段都得是自己的副本、
往档案里写东西不许污染默认值。

**一条为了复现玩家 bug 而写的断言，顺手挖出了一个跟它无关的存档 bug ——
这就是「断言要验行为不要验写法」的收益。**

## 四十三、「换了跟没换一样」的根因是网格一个字没动

报的是「皮肤有没有更大变化，现在都不明显」。把六套涂装并排烤出来一看就清楚了：
**六个人影的轮廓完全相同，只是重新上了色。**

这本来是当初的设计优点 —— 精灵是「字符网格 + 调色板索引」，
换一份调色板就是一套新皮肤，网格一个字不用改。省事，但也正因为省事，
**它只能改颜色**。而这游戏的画布是 320×180、叠着两层泛光，
颜色会被一路往白里洗 —— 这已经是第四次栽在同一件事上了
（敌人子弹像经验点、低血环像低血暗角、跟班像掉落物，现在是涂装像涂装）。

**能活下来的只有形状。** 每套加一件顶在头上的剪影：
母体长角、磁轨顶环、废钢支天线、霓虹戴灯冠、幽灵罩兜帽，基准款什么都不加。
它必须**露在身体外面** —— 藏在轮廓里的装饰改不了剪影，等于白加。
顺带修了废钢那套：面罩原来跟身体同一个橙色系，整个人是一坨棕的，面罩单独提亮。

同一个道理套在「换枪人物也要变」上：原来只有手上那把枪的形状会变，
人还是同一个人。给八把枪各配一件挂在身上/背上的东西 ——
胸前弹带、背上电容塔、肩上电极叉、腰间弹挂、背后刀鞘、散热鳍、雷囊、环刃架。
同一时刻只出现一件，所以不用跟二十多条词条贴花抢槽位。

### 这两条断言的写法

验「有没有写这几行」是没用的 —— 摆错位置、被身体挡住、压根没调用，全都测不出来。
改成**把画出来的东西录下来比**：

```js
const drawnFor = () => { ctx.__rec(); NS.drawPlayer(30, 30);
  const imgs = ctx.__ops.filter(o => o[0] === 'drawImage').map(o => o[1]);
  ctx.__rec(false); return imgs; };
// 换九把枪，画出来的图块序列不许跟脉冲步枪一模一样
```

这就是当初为了验「跟班有没有牵引线」给 DOM 桩加的画布录制
（见第三十一条）——**为一个问题加的量具，后面还会再用上**。

## 四十四、`G.drops.length = 0` 这一行吃掉了 BOSS 的全部掉落

`setArena()` 里有一句 `G.drops.length = 0`。而 BOSS 打完的**下一波会换场地** ——
于是 BOSS 掉的 25 废钢、必掉的核心碎片（全场最值钱的零件）、治疗包、增益，
只要补给间隙里没一颗一颗捡完，全部凭空消失，而且**一声不响**。

BOSS 一死场上一片狼藉，指望玩家在几秒喘息里捡干净是不现实的。
换场地之前先扫一遍，全部收走。

带出来两个连锁问题：

**一、一次进账好几级，牌只发一次。** 原来经验是「捡一颗判一次」，
一次只可能升一级；扫一遍进来十几颗，跨两级的话第二级就白升了
（`takeUpgrade` 直接把状态打回 `play`）。改成记账：`G.lvQ` 欠几级发几张。
这个 bug 在快速连捡时本来就存在，只是自动回收让它必现。

**二、横幅是覆盖式的，说了等于没说。** 扫完弹一条「自动回收 …」，
立刻被 `nextWave()` 末尾的波次横幅盖掉。改走 `tipQ` 提示队列（它会等上一条播完）。
**顺带修好了一个没人见过的横幅**：「场地 · 熔渣池」一直以来都在换场地那一波
被波次横幅盖掉，从来没显示过。

### 探针红了，但不是这个改动的错

改完探针报「卡住 1 局」（原来 0），平均 20.2 → 17.8。
按老规矩 A/B：同一份代码只开关 sweep，**24 个种子**跑两遍。

| | 平均波数 | 撤离 | 卡住 |
| --- | --- | --- | --- |
| 关 | 16.8 | 4 | 0 |
| 开 | 16.4 | 5 | 1 |

平衡上没有差别（5 个种子时那个 20.2 → 17.8 纯粹是样本太小）。
那一局卡死是真的，但把诊断加厚之后原因很清楚：

```
枪=pulse 伤害=18.0 射速=5.12  场上子弹=16
怪血=96% 91% 99% 96% 96% 100% 100% 96% 100% 100%
词条=spd,rof,leech,mag,dmg,hp,count,pierce,shield
```

机器人打到第 17 波还拿着开局那把枪，词条摊成九种没一种专精，
撞上 `wall`（一屏铁闸）。子弹在飞，386 秒只打掉 4% —— 它在 94px 外边退边打，
基本没命中。**泄压阀本身是好的**（过热已开、残兵直冲都生效了），
缺的是「玩家真的杀不动」时的最后兜底。

这是个既有的洞，我的改动只是让种子 9 恰好走到了那个组合。
**A/B 的价值就在这儿：没有它，我会对着一个跟我无关的 bug 改我自己的代码。**

## 四十五、「多周目就好了」—— 能测，别猜

上一条那个卡死，被问了一句「是不是可以经过培养，多周目就好了」。
这句话是可以量的，而且**原来的探针答不了**：它跑的是新档案，
机器人手里永远只有开局那把脉冲步枪。拿新档案的数据说老玩家的事是答非所问。

加了一档 `full`（里程碑全开、九把枪都在卡池里）。结论：

- **卡住 0 局 / 24 个种子。** 那个卡死的前提是「第 17 波还拿着开局那把枪」，
  而解锁之后你几乎不可能一路拒掉所有换枪卡。**所以它是新档案专属的边缘情况，
  提问的人是对的。**
- **但同一次跑出来的平均波数（7.3，新档案是 16.8）一个字都不能信。**

第二条是这次真正的收获。机器人的选牌表是写死的十条数值词条
（`dmg rof hp count spd pierce leech crit mag shield`），
九把枪全进卡池之后，三选一里经常一条它认识的都没有 ——
于是它随手拿走换枪卡，换上振动刀（近战）或熔切光束，
而它只会「瞄最近的 + 边打边退」。**它不是被游戏打死的，是被自己选牌选死的。**

所以在 `full` 这一档的输出里直接印一段警告：

```
⚠ 这一档的【波数】不可比：机器人的选牌表里只有数值词条，
  九把枪全进卡池之后它经常抽不到会用的，还会换上振动刀这种它不会用的近战。
  这一档只看【卡住几局】—— 那是「这一波收不收得掉」，跟它会不会用枪无关。
```

**新增一个量具档位的时候，同时要写清它测得准什么、测不准什么，而且写在它自己的输出里** ——
写在文档里没用，读数字的人不会回去翻文档。
这是第二十五条（量具的能力边界也要写下来）的实践版：那次是写在文档里，
这次直接印在结果上。

## 四十六、给回放做画面，别给算账做画面

「开店能有画面吗」。原来是点一下「开门营业」、瞬间吐出一整段文字日志 ——
而**定价是这套经营玩法唯一的决策**，「客人嫌贵转身走了」只剩一行可以一眼扫过去的字，
一点被拒绝的体感都没有。

做法上最关键的一条：**`openStore()` 一个字不动。**
它照旧一次性把整场算完、返回 log，画面只是把算好的 log **一位一位放出来**。

这样分工的好处是具体的：

- 经济那边的断言（心理价位带、名声涨跌、卖光了怎么办）全都还成立，一条都不用改
- 画面写坏了也**不会算错账**
- 加了一条断言专门守这个：`ok(NS.PROF.scrap === before + res.earned, '账在 openStore 里就结完了，画面不参与算账')`

### 回放带来的两个必须处理的细节

**一、钱先到、客人后来，会穿帮。** `openStore()` 结完账，`PROF.scrap` 已经是最终值，
而画面才刚开始放第一位客人。所以显示上先退回开张前，每放完一位加回那一笔。
`syncHQ()` 里那行 `el('hqScrap').textContent = PROF.scrap` 也得改走同一个口子 ——
否则任何一次 sync 都会把数字跳回最终值。

**二、按真实时间步进，不是每帧 1/60。** 丢帧的时候固定步长会让整场变慢，
而这是一段有节奏的表演，慢下来就不对味。顺带让离线套件能直接 `tickStore(dt)` 驱动它 ——
浏览器预览面板隐藏的时候 `requestAnimationFrame` 会被节流，我第一次就是这么
观察不到任何进展的。

### 时长也是要量的

第一版每位客人 1.6 秒，九个客人放 14.6 秒，满打满算一天 12 个就是 19 秒。
**这是个菜单界面，没人坐得住。** 压到每位 0.94 秒，并且点一下画面直接跳到结果。
断言直接盯这两个数：

```js
ok(per < 1.1, `每位客人 ${per.toFixed(2)}s`);
ok(t < 14, `整场 ${t.toFixed(1)}s`);
```

### 还有一条是这个项目独有的

摊位和客人的精灵**不许用 B/S/L/C/O/H 这六个字母** —— 那是涂装会重映射的颜色，
用了的话客人会跟着玩家的涂装一起变色。写了条断言直接扫网格挡住它。

## 四十七、同一条规矩，第三次栽

被问「开门营业上面可以加减的是什么」。那一排长这样：

```
■ 伺 服 马 达 ↑   ×3   [−]  46  [+]
```

`46` 是**你给这种零件开的要价**，一下 ±10。前后一个字都没写。

而我自己在第四十条（HUD 让角）里刚写过判断标准：
**「这个数字旁边有没有东西在说它是什么」** —— 没有就必须写。
那次守住了 HUD 的两个裸数字，这次货摊这个漏了。
**规矩写下来不等于用上了，得回头拿它扫一遍别的地方。**

补的是三样：

1. 列头 `零件 · 存量 · 要价/件`
2. 一句说清代价：要高了客人转身走、走多了砸名声；要低了秒卖但赚得少
3. 名字后面那个 `↑/↓` 也解释了（今天缺货 / 积压）

### 列头对不齐比没有列头还糟

第一版列头是随手排的三段文字，看着在那三列附近，其实全错位 —— **它会指错**。
改成按 `.pitem` 的 flex 结构一栏一栏镜像，并且把这层关系写成断言，
数字从 CSS 里读出来比：

```js
ok(w(/\.pcols \.h3\{width:(\d+)px/) === btn * 2 + pv + gap * 2,
  `「要价」列头宽 = 减号 ${btn} + ${gap} + 价格 ${pv} + ${gap} + 加号 ${btn}`);
```

## 四十八、时绿时红的断言，比红的更危险

改完顺手跑验收，连着两遍：一遍红一遍绿，之后二十遍又全绿。
红的那条是「右手没按时，自动瞄最近的敌人」。

根因：那段调的是 `NST.start()` —— **不传种子**。
而 `start()` 不传种子时 `RUN_SEED` 取 `Date.now()`，
于是它每次跑在不同的局上；`update()` 只要还有预算就会再刷怪，
刷出一只比 120px 更近的，自动瞄准就锁到它身上。

整个套件里有 **25 处**不带种子的 `start()`，每一处都是同一个雷。
一个个去传种子既大又容易改错测量目标，所以在**桩那一层**一次钉死：

```js
const FIXED_NOW = Date.UTC(2026, 0, 2, 3, 4, 5);
global.Date = class extends RealDate {
  constructor(...a) { return a.length ? new RealDate(...a) : new RealDate(FIXED_NOW); }
  static now() { return FIXED_NOW; }
};
```

顺带把每日局的 `dayKey()` 也钉住了 —— 它同样走 `Date.now()`，
也就是说**每日局那几条断言原本是跟着真实日期漂的**。

这类 bug 抓到纯属运气：它只在「这一帧恰好又刷出一只更近的怪」这种巧合下才红。
**发现一条闪烁的断言，别只修那一条 —— 去找它的不确定性是从哪来的，
那个源头底下通常还站着一排。**

## 四十九、两块 UI 在显示同一个数

「存量和要价的列表 UI 优化下」。打开一看，真正的问题不是排版：

货摊那一栏上下贴着两块东西 —— 我先做的**货箱格子**（九种全列，答「我的货箱在哪看」），
和原有的**存量要价表**（只列手上有的）。**同一个数量显示了两遍。**
每一块单独看都合理，是分两次加进去的，加第二块的时候没回头看第一块。

并成一张表：九种全列（空箱也看得见，那条需求还在），
有货的带加减价，没货的压暗成一行、不给按钮 —— **定不了不存在的东西的价**。

顺带两个：

- **要价的字号提到 13px 并换成显示字体。** 它是这一行唯一能改的东西、
  也是整套经营玩法唯一的决策，原来跟旁边的小字一样大。
- **底下加一行「按现在的要价全卖掉 1229 废钢」。** 比每行都挂个小计清爽，
  而且「这箱货值多少」才是你真正在优化的量。
- 表头那四行说明缩成一行，展开讲的挪进标题页的「怎么玩」——
  小字压在表头上，看一遍之后每次进来都碍事。

## 五十、同一条布局关系，写了两遍，只验了一遍

列头要跟行里的格子对齐，这个关系我上一轮已经写成断言了：

```js
ok(h3宽 === btn * 2 + pv + gap * 2, ...)
```

然后手机上一看，**整排错了 25px**。
因为触屏上加减按钮从 22px 放大到 34px（`body.touch .pitem button{width:34px}`），
而列头宽度只写了桌面那一套。

**断言也只查了桌面那一套，所以一点没红。**

这类「同一条关系在两种设备下各有一份取值」的东西，断言必须**两份都验**：

```js
ok(w(/\.pcols \.h3\{width:(\d+)px/) === btn * 2 + pv + gap * 2, '桌面：…');
ok(w(/body\.touch \.pcols \.h3\{width:(\d+)px/) === btnT * 2 + pv + gap * 2, '触屏：…');
```

实测对齐（375 宽）：存量列头 `[204,230]` vs 存量格 `[203,229]`，
要价列头 `[236,350]` vs 加减价整块 `[235,349]`。

```bash
npm run check:neon   # 1024 条零件断言
npm run probe:neon           # 新档案：曲线的下限
npm run probe:neon 31 0 full # 多周目档案：只看卡住几局
```
