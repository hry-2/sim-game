# 静街 · 任务拆解 · 「你知道自己为什么死」

> 目标：用最小代价验证核心假设 —— **「延迟后果能被玩家读懂，
> 并因此改变下一局的行为」本身就好玩**。
>
> 不做多人、不做等距、不做几百条配方。做的是僵尸毁灭工程剥掉量之后的骨架：
> 一座能翻完的镇、一具会坏的身体、一份写到你死那天的日志。
>
> 预估总量 **约 5 周**（单人全职）。带 ⚠️ 的是风险点，★ 的是地基或验证关键。
> 沿用本仓库的规矩：单 HTML、零依赖、美术程序化生成、**不用 `Math.random`**。

策划见 [静街策划](静街策划.md)，具体数值见 [静街数据规格](静街数据规格.md) ——
本文只说做什么和怎么验，不再重复数字。

## Phase 0 · 地基（4.5 天）

### T0 · 幸存者精灵与调色板 ✅（0.5 天）

**目标**：画风在写第一行游戏代码之前就定下来（见[策划第十一节](静街策划.md)）。

**改动**
- `tools/survivor_gen.js`，从 `character_gen.js` **分叉**（不改原件，市井还在用）
- 调色板：16 色主板，饱和度降 20%、亮度上限 82%；四季各一套 4 色环境偏移
- 比例：**头身比 1:3.18**（头 11 行），一帧仍是逻辑 32×42（帧高必须整除 `RS=3`，市井 T31 的坑）
- **六类贴花**：绷带（6 部位）、血渍三档、冻伤、冬装、背包、五件武器；层序
  绷带 → 血渍 → 冻伤 → 冬装 → 背包 → 武器
- **湿透不是贴花**，是渲染层的乘算（和 lightmap 同一条路）
- `npm run survivors` 出图 + `--embed` 嵌回（游戏还不存在时自动跳过嵌入）

**验收**：图集每一帧宽高一致（**打印数到的帧数** —— 霓虹教训二：`扫到 0 帧`也是绿的）；
贴花全开与全关是两个明显不同的样子；预览图里四季各出一排。

**做完了** —— `npm run survivors` 出图，`npm run check:street` 的「精灵图集」一节 20 条断言。
`tools/survivor_gen.js` 从 `character_gen.js` 分叉，但**只抄画法**：
PNG 编码与图集拼装是 `require` 过来的（`tools/` 本来就是这个仓库真正的共享层）。
调色板是**算**出来的（鲜艳的 `RAW` → 统一降饱和 20%、压亮度 82%），
于是"降了没降"可以断言，而不是手敲一堆十六进制。

**改掉的两处文档错误**：① 头身比 —— 量过市井是 1:2.62，"拉到 1:2.6"等于没改，现在 1:3.18；
② 湿透 —— 策划写的是"整体压暗 + 偏蓝"，我却实现成了贴花，画出来像囚服。

### T1 · 镇子生成器 ✅（1.5 天）★

**目标**：`?seed=` 给定时，同一座镇每次生成完全一样；房屋有内部、有容器、容器里有东西。

**改动**
- 镇子 96×80，6 个街区（`BLOCK[]`：住宅 ×2 / 商业 / 工业 / 公共 / 镇外）
- 四层数据表：`HOUSE_TYPE[]` → `ROOM_GRAMMAR[]` → `CONTAINER[]` → `LOOT[]`
- 房型 **10 种**：民宅 / 商铺 / 超市 / 药房 / 五金 / 仓库 / **加油站** / 警局 / 诊所 / 教堂
  （加油站是写规格时补的第 10 种 —— 断电后发电机要汽油，汽油得有个明确产地）
- 全部数值（数量、面积、门锁概率、容器表、战利品权重）走
  [数据规格第一节](静街数据规格.md)，这一步不做设计决定
- 房间语法按面积摆：民宅 = 客厅 + 厨房 + 卧室 ×(1~3) + 卫生间
- 战利品表键 = `容器类型 × 房型 × 已搜次数`，每个容器有 `searched` 位
- 瓦片类型：地面 / 墙 / 门（开关 + 可撬 + 可锁） / 窗（可翻 / 可破 / 可钉） /
  家具（挡人不挡视线） / 栅栏（僵尸要拆）

**验收**：同一个 `?seed=` 连生成 10 次，瓦片哈希一致；10 种房型每种至少出现 1 栋；
32 栋建筑每栋过连通性检查（**≥2 条出路**）；随机抽 50 个容器，`LOOT` 表命中率 100%
（**断言要打印数到的数量**）。

**做完了** —— `games/quiet-street/index.html`（约 1150 行），96×80、六街区、32 栋、131 个容器。
断言 99 → **100 条**（新增的那条是镇级可达性，见下）。
地图是真的；噪音迁移 / 身体 / 感染 / 日志 / 传承是照契约从自检靶子移植的已知正确实现，
T2~T7 逐个换成真的。

**顺带做了两件不在 T1 计划里、但不做就没法验的事**：
- `pathStep()` —— BFS 寻路。门窗当可通行（人能开、能撬、能翻），僵尸拆板破门以后也用这套。
- `reachAudit()` + 一条新断言：**镇上每个容器都走得到**。
  房内连通只是一半 —— 一栋房自己通，但门口被别的建筑堵死，那栋房里的东西等于不存在。

**探针抓到四个真 bug**（`verify` 那 99 条一条都没红，全是"零件对但凑起来不对"）：
1. **静默丢房。** B 街区计划 8 栋，宽度摇大时一排只塞 3 栋，第三排超出街区高度 ——
   两栋商铺被直接丢掉，断言报「30 栋，表里写的是 32」。修法：挤不下先退回最小尺寸，
   本街区排不下的兜底去别的街区，而不是丢掉。
2. **翻窗喊了一声，人没过去。** `interact()` 返回"翻窗过去"却不移动玩家，
   机器人卡在窗前反复喊，每天噪音从 55 冲到 **752**，全镇僵尸被喊过来，
   死因里"被围"占到 67%。看着像战斗太难，其实是这一格没把人送过去。
3. **互动优先级错了。** 眼前五格按坐标顺序一路 return，于是"刚翻进来的那扇窗"
   排在身边的橱柜前面 —— 机器人爬进屋、站在柜子旁、又从窗户爬出去，
   一整天只翻到一个柜子。现在的顺序是：**容器 → 门 → 窗**。
4. **日志里出现「第 4 天 24:00」。** 采样写在跨日判断之前，23 点加一小时先记下 t=24。
   签名功能上的文案 bug，先跨日再采样。

**量具自己的五个洞**（霓虹教训二十三：量具校准了三次，每次都被当成游戏 bug）：
撞墙不会绕（8/12 局报假僵局）· 只推时钟不调 `update(dt)`（僵尸一步没动，死因里永远没有被围）·
不会开门撬门（门有 45%~95% 锁着，搜刮覆盖率卡在 1%）· 一小时的步数标定成 22 而不是 60
（`move()` 一次走 SPEED 格，而 SPEED 是格/游戏分钟）· 用直线距离 `<1.6` 判"够得着"，
于是斜着站在柜子旁边反复喊"眼前没什么可弄的"（游戏扫的是十字五格，斜角不算）。

**画面上改的三处**（断言看不见构图，只能靠眼）：画布原来没有 CSS 尺寸，1512px 宽直接溢出窗口；
地面颗粒按格 ±6 再撒 ±9 的点，整张地像床被子；墙 `#6b6258` 和地板 `#5c5042` 两个棕色贴在一起，
房子看着像一块补丁。

**手玩抓到的一个大 bug（断言和探针都没抓到）**：`movePlayer()` 一次走 `SPEED` 格，
而 `SPEED` 的单位是"格/**游戏分钟**"，主循环却每帧调一次 ——
**玩家实际快了 22.5 倍**，按一下方向键人就飞出半条街；僵尸那边反过来按现实秒走，
又慢了 2.7 倍，看着像僵尸不会动。探针发现不了：它一个游戏小时只调 60 次 `move()`，
语义正好是对的。现在 `move(dx,dy,stance,mins)` 显式带上"走几个游戏分钟"，
主循环传 `dt / 0.375`，噪音也按游戏分钟发而不是按帧发（否则 60fps 下每秒发 60 次）。
校验器补了 5 条钉住时间基准（第 17~20 条不变量）。

**顺带定了个规矩**：`Sec` 结尾的字段是现实秒，`Min` 结尾的是游戏分钟。
冲刺尸的 `burstSec: 20` 原来被当游戏分钟减，20/60 游戏分钟 = 0.125 秒现实，
**冲刺压根没发生过**。现在是冲 4 秒、累瘫 12 秒，都是现实秒。

**留给 T3/T20 的一条观察**：站在商业街上一屏能看见二十几只 ——
320 只摊到 96×80 可能偏密。这不是 bug，但它意味着 **T6 近战和 T8 开场没做之前，
探针的死因分布读不出东西**（现在是被围 58% / 存活 1.6 天）。量具的能力边界，记在这里。

### T2 · 搜刮：容器 / 背包 / 负重（1 天）

**目标**：进屋、翻箱、拿东西、被重量拖慢。

**改动**
- 容器面板：左边容器 / 右边背包，单件与全部转移
- 腰包 6 格（永久） + 背包 12 格（要找到）
- 负重两档：正常 / 超重（移速 -35%、噪音 +50%），超重时屏边有明确提示
- 翻箱需要时间（3~8 秒，按容器大小），期间会出噪音（2）且不能动

**验收**：装到超重时移速与噪音半径都真的变了（读运行时数值，不查源码字符串）；
背包满了再拿会说话（沿用市井 T29「用不了也要说一声」）。

### T3 · 噪音传播 + 僵尸存量与迁移（1.5 天）★⚠️

**目标**：整个项目的赌注。开一枪，半小时后这条街真的变危险。

**改动**
- `noise(pos, r, dur)`：以格为单位的圆，穿墙衰减 ×0.6/层（走夜港的 DDA）
- 僵尸两态：**游荡 / 追击**（不做三态 —— 本作没有"警觉度"这层）
- 两个品种：普通 88% / **冲刺尸** 12%（冲刺 1.70 四秒 → 冲完 0.40 → 累瘫 12 秒）。
  两个不等号是红线：冲刺 > 玩家跑、冲完 < 玩家走。**全程跑的僵尸不做，也不做开关**
- 普通僵尸追击 **0.45 < 玩家走 0.60**（改过一次，理由见[策划决策 9](静街策划.md)）：
  走得开一只，所以"跑"是你自己选的，不是被迫的
  - 游荡：朝所在街区的噪音重心缓慢移动；没有噪音就布朗
  - 追击：视锥 ±60°、视距 6 格（夜 2.4 格）；听到噪音直接走向噪音源
- 街区密度 `BLOCK[i].pop`，全镇总量固定 320，只在相邻街区之间迁移
- 迁移速率跟"噪音积分"走：`flow = k * (noise_j - noise_i)`，**每天结算一次**
- 街区密度杀到 10% 以下 → 该街区 7 天内 `refillLock`
- 小地图画街区热度（四档颜色），这是玩家读懂噪音的唯一界面

**验收**（这一条不过不进 Phase 1）：
1. 在 A 区开三枪，24 游戏时后 A 区密度上升、相邻区下降，**打印前后四个数**
2. 蹲行穿过两只僵尸中间不被发现
3. 全镇总量在跑完 30 天后仍是 320 ± 浪潮增量 —— **守恒是这套模型的正确性底线**

## Phase 1 · 活着（5 天）

### T4 · 身体六表 + 部位伤（1 天）

**改动**
- 六表：饥饿 / 口渴 / 疲劳 / 体温 / 恐慌 / 情绪（体温这一阶段只做背景值）
- 部位 6 处 × 伤型 6 种；手臂伤影响挥击速度，腿伤影响移速
- 处理链四步：清洗 → 消毒 → 缝合 → 包扎，每步缺失留一档感染概率
- 每一次状态恶化都往事件总线记**因**（`bite{part,src,pos,t}` / `cold{...}`）
- `accuracy()` 返回 `{ melee, gun }`：**恐慌只压 gun，melee 只看手臂伤** ——
  同一个状态不许被两套机制罚两次（踉跄链已经在罚被围）
- `sleep()`：**睡在自己据点的床上 +10 情绪**，睡陌生地方 0 ——
  六表里唯一奖励经营据点的那条

**验收**：腿伤后移速真的降了；四步处理链每种缺失组合的感染概率都能取到。

### T5 · 两条感染线与四阶段征兆（1 天）★

**目标**：玩家被咬之后知道自己处在什么状态，而不是猜。

**改动**
- 伤口感染：任何伤口不处理，12~48 游戏时恶化；抗生素可治
- 尸毒感染：咬 35% / 抓 7%；潜伏 36~96 游戏时；**不可治**
- 四阶段征兆（不适 / 发热 / 呕吐 / 抽搐）全部在状态面板上写明，用词与伤口感染完全不同
- 颜色：伤口感染黄、尸毒感染红，且红色只在**确诊后**出现

**验收**：两种感染的界面文案没有任何一个词重合（这条要真的比字符串）；
潜伏期内四个阶段都能被采样到。

### T6 · 近战与踉跄链 ✅（1 天）

**改动**
- 挥击三帧：抬手 / 命中 / 收手，收手期间不能动（硬直）
- 一次只有效命中一个目标；两只以上贴身进踉跄链，三只以上基本必死
- 反制全部是位置性的：关门、翻窗、绕车、栅栏后面戳
- 武器五件：撬棍 / 斧 / 锤 / 长矛 / 菜刀，差别在**攻速 × 硬直 × 耐久**，不是伤害数字

**验收**：被三只围住时确实走不掉（打印踉跄触发次数）；
关门能把追击的僵尸挡在门外，它们会拆门。

**做完了**（手玩问"怎么近战"之后做的 —— 在那之前你只能跑和躲）。
操作：桌面**左键或空格**挥击、朝向跟鼠标；手机多一个「挥」键、朝向跟摇杆。

数值与规则见[数据规格「近战」一节](静街数据规格.md)。几条值得单独记的：

- **打退半步**：打中会把它推开，于是连打第二下常常够不着 ——
  **间距是你自己制造的**，不是靠冷却。这条让"打一下退一步"成了真打法
- **打倒 ≠ 打死**：血剩 1 时有一半概率倒地，12~20 秒后自己爬起来。
  于是"清完了"和"暂时安全"是两件事
- **蹲着打翻倍**：潜行的第三个支点（前两个是噪音 0 和缩短它的视距）
- **踉跄链按时长算**：三只按住 1.5 秒才死，一闪而过不死 ——
  这样"被围"读得出过程，而不是走过去就没了

**验收补了 10 条**（第 30~34 条不变量），断言 147 → 159 条。
其中一条查的是"两只贴在一起挥一次只有一只掉血" —— 这是"别被围"这条规则的底线，
一旦有人为了手感改成范围伤害，它会立刻红。

### T6 补做：推开、站位、密度 ✅（手玩报"一下就被打死，怪越来越多"）

**"一下就被打死"是两件事叠出来的：**

1. **被围那一秒半没有答案。** 挥击一次只打一只、还带硬直。补了**推开**
   （右键 / `Q` / 手机长按挥键）：范围推开、清零被围计时、不掉血。
   而且**踉跄不挡推** —— 第一版把它也挡进来了，等于把唯一的解法锁在它要解的状态里。
2. **僵尸会叠在同一个点上。** 没有任何站位约束，追击时全部收敛到玩家坐标，
   于是"三只贴身"几乎必然。现在僵尸间距 0.72、与玩家 0.55（**硬钳位**，
   软力的平衡点会被后面挤上来的压到 0.38）。它们围成一圈，不叠成一摞。

**"怪越来越多"一半是设计（噪音把它们迁过来），一半是起点就太挤**：
320 只摊到 96×80 是 5.5%，一屏 11 只。**降到 180**（3.1%，一屏 6 只、看得见 4 只），
浪潮跟着 120 → 70 —— 浪潮该是"这一下不一样了"，不是"把镇子填回去"。

**顺带抓到两个真 bug**：
- `swing()` 跳过倒地的目标 —— 你把它打趴下之后**只能挥空**，眼睁睁看它爬起来。

- 倒地/眩晕的处理写在了"追击"分支里 —— **游荡状态被打趴下的会永远躺着**

探针：被围从 40% 降到 **20%**。断言 159 → 168 条。

### T7.7 · 感知：视锥、游荡、隔墙看不见 ✅（0.4 天，计划外）

### T7.8 · 进房子要有用 ✅（0.2 天，计划外）

手玩报的："还是跑不过怪物，而且进房子也没用"。

先量：空地上跑，**每秒净拉开 2 格**（4.00 vs 2.00），速度没问题。
真问题是第二句 —— **僵尸和玩家共用一个 `passable()`**，
窗对两边都是通的，于是你翻窗进屋它们跟着翻窗进屋，门不关就直接跟进来。
**没有任何地方能甩掉它们**，所以只能一直跑；而跑的噪音是 7，越跑越多，
读起来就成了"跑不过"。

僵尸改用 `zPassable()`：不会开门、不会翻窗、板窗也拦得住。
**拆门拆板留给 T9** —— 那时才该给它们这个动作，而且要有进度和声音。
在那之前"关上门"是一个干净的逃生答案。顺带：关门时会报还有几只在外面找你。

**验收**：新增 5 条（第 27~29 条不变量），其中一条是整条流程 ——
翻窗进屋后追着的那只六秒进不来。断言 140 → 145 条。

### T7.9 · 走要走得开 ✅（0.1 天，计划外）

手玩报的："我走路也应该比怪物快"。**他是对的，而且理由比手感更硬。**

原红线"走不掉、跑得掉"（追击 0.75 > 走 0.60）本意是给噪音定价，
实际效果是：全镇 320 只、每一只都比你走得快 → 你永远只能跑 →
**跑的噪音 7 从"一个选择"变成了"过路费"**。一个你必须一直付的代价不是决策，
它把决策 2 自己架空了。

现行：**蹲 0.30 < 追击 0.45 < 走 0.60 < 跑 1.50 < 冲刺 1.70**。
实测被一只追着、起始 3 格，十秒后：蹲行 0.0（八秒被追上）/ 走 7.0 / 跑 33.2，
而丢失目标要 11.3 秒 —— 走开十来秒正好脱身。

**顺带修掉一个同源的坑**：`chase` 速度在 `SPEED` 和 `ZOMBIE_KIND` 里各写了一遍，
改了前者后者不跟，所以第一次改完"怪还是老速度"。现在 `chase` 直接引 `SPEED.僵尸追击`，
并且加了一条断言：每个品种的常速必须**等于**表里的值。

### T7.10 · 「太丑」那一轮：视野、迷雾、地面密度 ✅（1 天，计划外）

手玩报的原话是"太丑了，怎么能做到和僵尸毁灭工程一样"。

**做了的**

- **地面信息密度**（⑥）：地砖烤一次 × 4 张变体、8 种手摆杂物、血迹留痕进镇子档
- **建筑件**：墙顶/立面程序化烘焙（带壁板缝与受光），门/窗/板窗**手摆** 24×10 立面

**没做的**：①等距 ②手绘瓦片 ③八向角色（Q1 明确否掉），⑤色温曲线与⑦雨/分级留到下一轮。

墙是重复表面，靠的是颗粒和横向结构线，逐像素手摆并不比调好的噪声强；
门窗有轮廓有细节，那才值得手摆。

**抓到一个静默 bug**：`swing()` 里 `const W = WEAPON[w]` 把全局的**地图宽 `W`（96）遮住了**，
于是 `Math.floor(best.y) * W` 算出 `NaN`，而 **`Uint8Array[NaN] = x` 是静默无效的** ——
血一滴没留、一声不吭。断言抓到的。

**量具自己第七次栽在站位上**：视锥测试把人放在商业街，东边六格就是墙，
"正前方看得见"必红。现在测试先扫出一段左右各 7 格全空的地方。

断言 179 → **204 条**（新增第 34.5~40 条不变量）。

**试玩把 ④ 推翻了一半**：原话"太丑了，去掉迷雾"。**迷雾改成默认关**（`?fog=1` 可开），
理由记在 [ADR-0003](adr/0003-vision-not-isometry.md) 的后续一节 ——
在 17×12 的俯视图上压暗大半个屏幕，丢掉的可读性比换来的气氛多。
留下来的是 ⑥ 那一组（纹理密度、杂物、血迹、建筑件），**那一半确实让画面密了一档**。

**同一轮报的另一件是真 bug：「走路的时候地上的元素在抖动」，两个源头**
1. **镜头没有对齐整数世界像素** —— 每格的落点是小数，关掉插值后有的格向上取有的向下取，

2. **杂物的偏移按屏幕坐标哈希** —— 屏幕坐标随镜头每帧都在变，

两条各钉一条断言 —— 这种毛病最容易悄悄回来。

### T7.12 · 房子要立起来 ✅（0.2 天，手玩第四轮）

原话：「房屋改成 2.5D 的，现在还是看着俯视」。

第一版立面和脚下的影几乎同色，抬升做了也看不出来。

### T7.16 · 打击手感 ✅（0.4 天）

「打僵尸手感很差怎么解决」—— 不是一个问题，是**五件东西全缺**：
没有声音、没有顿帧、结算在按下那一瞬（顺序是反的）、没有受击反应、打空和打中一样。

五件一起做（细节见[数据规格「打击手感」](静街数据规格.md)）：
结算挪到挥击 45% · 顿帧 60/110ms · 震屏 · 受击闪白 · 五种实时合成音效。
**这游戏在此之前一个音效都没有** —— 手感是听觉和视觉一起给的。

**两条结构上的收获**：
- 特效计时必须和世界时间**分开**（`tickFX` 不是 `update`）——
  顿帧冻住的正是 `update`，把倒计时放进去就永远解不了冻
- **视觉与音频的随机要单开一条**（`vrnd`）——
  震屏抖动和噪声缓冲用游戏的 `rnd()` 会消耗种子序列，`?seed=` 当场不可复现。
  校验器钉了一条：响 30 次音效之后同种子的结果必须一模一样

顺带给桩补了 **AudioContext**：不补的话 `sfx()` 直接 return，
上面那条"音效有没有偷偷消耗随机数"就永远测不到 ——
**桩偷懒的地方就是测不到的地方**（霓虹教训十二）。

断言 228 → **239 条**。

### T7.17 · 动作感 ✅（0.5 天）

「怎么更像动作类游戏」。先把它拆成**改不改变类型**两半：

- **做了（半改，但奖励已有打法）**：**处决** —— 对倒地目标的独立路径 + 第 7 列独立姿势
- **明确不做**：闪避翻滚、体力条 ——
  它们会让战斗变成解决问题的主要手段，而决策 9 是「逃跑永远正确」。
  真要做得先改决策 9，那是个要写进 ADR 的决定。

细节见[数据规格「动作感」](静街数据规格.md)。断言 239 → **254 条**。

游戏里一行赋值就崩。**桩每偷懒一处，将来就崩一次或者测不到一样东西**（第三次了）。

### T7.18 · 动作僵硬 ✅（0.3 天）

「人物动作僵硬怎么办」—— 四条，其中一条是真 bug：

1. **攻击只有一拍**（bug）：`P.swing > 0` 就显示"出手"，斧子那 0.95 秒里手一直伸着。
   改成**预备 → 出手 → 收手**三拍，**不需要新帧**（预备复用"收手"那张）。
2. **站着是绝对静止** → 待机呼吸 1 像素，不加帧。
3. **起步停步瞬时** → 输入向量指数平滑，约 0.12 秒过渡。
4. **步频跟按键不跟速度** → 改成跟实际速度，慢慢挪的时候腿也慢慢迈。

顺带加脚步声（落在触地的第 0、2 帧）。细节见[数据规格「动作的拍子」](静街数据规格.md)。

**一条要守的边界**：加减速只加在**主循环**里，不动 `move()` 的语义 ——
探针和验收都按"一次调用 = 一个游戏分钟"在用它，改了它整套速度断言全假红。

断言 254 → **261 条**。姿势选择抽成 `poseSlot()` 纯函数，才钉得住"攻击有三拍"。

**没能亲眼验的两样**：待机呼吸和加减速都靠 rAF 驱动，
而这个环境里浏览器窗格隐藏时 rAF 不触发（首页缩略图那次踩过同一个坑）——
这两样只有断言在守。

### T7.19 · 弧度 ✅（0.3 天）· 但没做完

「人物和动作还是丑，完全直线，没有任何弧度」。事实确认：`draw()` 里一条斜线都没有。

加了 `px.shape()`（按每行半宽画）给头、躯干、腿、胳膊做锥形；
腿和手改走椭圆轨迹；正面的腿幅度调小（照侧面画会劈叉）。
相邻帧差异 373~400 → 440~459。细节见[数据规格「弧度」](静街数据规格.md)。

**没做完的部分要说清楚**：头和躯干的轮廓、腿的轨迹有弧度了，
但**胳膊仍然读成横在胸前的一道条**。改了三轮都没解决 ——
这是参数化生成器的天花板：每个部件都是"带规则的矩形"，
而正面视角的手臂需要的是**逐像素挑位置**。

下一档只有两条路，都是 Q2 里列过的：
**(d) 把玩家这一行 28 帧手摆**（霓虹 GRID 那条路）或 **(b) 外部美术**。

### T7.20 · 手摆底板 + 分辨率提一档 ✅（1 天）

「人物和动作还是丑」→「最好像 pz」→「像素高一些」→「脸太丑了，改成偏动漫风格」。

- 逻辑尺寸 **32×42 ×3 → 48×63 ×2**，设备像素不变、图集不涨，细节 2.25 倍
- **去掉统一黑描边**（卡通 vs 写实像素最明显的分界），改成只压脚底那一圈
- 头/躯干/四肢**手摆**，28 帧靠**部件 + 位移**拼出来
- 脸改成**动漫向**（大眼、小鼻小嘴、收尖下巴），虹膜保持低饱和
- 接回生成器：底板共用，**颜色仍按角色生成**，16 行变化保住
- 断言 261 → **262**，新增"每帧都是一整块"

**守卫真的用上了一次**：生成器一直借市井的 `Sheet`，而它的 `blit` 用的是
**它自己的** `LW/LH`（32×42）—— 静街一提到 48×63，再借就只会拷左上角一块。
那行 `throw` 就是为这个存在的。

**没做的**：发型不再随角色变（只变颜色 + 帽子）。
`decal()`（绷带/血渍）还是按常数定位，和手摆的身体不是严丝合缝。

### T7.21 · 手机上的界面 ✅（0.4 天）

「交互 UI 都不好看」「主要看移动端」。拆出来六件事，最要命的是**人被自己的按钮埋了**
—— 镜头顶死在地图下边界，而开局就在镇外南缘。
允许镜头越界之后，贴南缘站时人从屏幕 **88% → 61%**。

其余：状态表重排（字在自己那条表左边、行距大于字高、低饱和分色）、
顶栏加底板、提示条不再被「挥」压住、浮层重做（压暗 + 收起控件 + 按内容定高 + 轻点关闭）、
按钮分三档、**补上手机端打开日志的入口**（原来根本打不开）。

断言 262 → **268**，新增一条 `setTouch` 钩子。
细节见[数据规格「手机上的界面」](静街数据规格.md)。

**没做**：桌面侧栏。

### T2 · 搜刮：容器面板、背包、重量 ✅（0.6 天）

「搜刮物品操作现在很奇怪，UI 也丑」。查出来是两件事叠在一起：
**操作**上开容器等于全自动拿走（没有选择）、**UI** 上面板只是一串顿号连起来的只读文本。

- `openContainer` / `takeItem` / `putItem` 拆开，**开不等于拿**
- 补上**格**这个量（以前只有公斤），腰包 6 格 / 背包 +12 格
- 负重三档：≤15kg 正常 · 15~25kg 超重 · >25kg **走不动**
- 面板重做：容量常驻标题栏、柜子/背包两页、逐件拿与放回、全拿、关闭
- 画布 UI 的**命中测试**（触屏轻点 + 鼠标点击 + 桌面数字键 1~9）

**照出来两个真 bug**：背包一直穿不上（+12 格是死规则）、木匠开局 7 格超过腰包的 6 格。

断言 268 → **282**。细节见[数据规格「搜刮：开不等于拿」](静街数据规格.md)。

**没做**：T2 里的"重量影响体力消耗"、容器翻找耗时。

### T2.1 · 装备与窄屏排版 ✅（0.3 天）

「搜索框超过屏幕宽度，撬棍怎么装备」。

- **装备以前不存在** —— `weapon()` 按写死的优先级表挑，你不能选。
  现在背包页点一下就是「拿起」，再点交回自动，选中的那把没了自动退回优先级。
- **窄屏被切** —— 画布可以比视口宽一格，而浏览器把居中退化成靠左，
  超出的全在右边。面板/小地图/提示条改成按 `visX()` 的可见区排。
- **提示条宽度按字数猜**（`长度 × 9`）对中英混排是错的，且没有上限 —— 改成量。
- 顺带修掉我自己上一轮写坏的：**Tab 打开背包变成了死的**（新面板要求有容器）。

**桩的第四、五个缺口**：`measureText` 固定返回 10、`getBoundingClientRect` 固定返回
960×640。后者造成的是最阴的假绿 —— 面板和断言用同一个错值，两边一致、双双错。

断言 282 → **291**。

### T2.2 · 去掉格子、装备看得见 ✅（0.4 天）

「背包不需要格子，怎么打开背包装备武器，装备了武器，人物没变化」——
三句话，后两句都是真缺口。

- **去掉「格」**。它只是在你和"拿不拿"之间加一道不产生决定的算术。
  背包改成**超重线 +8kg**，不是多几个格子。
- **手机上补「背包」按钮**。Tab 在手机上不存在，所以原来**根本没法换武器**。
- **贴花图集一直没嵌进游戏**：十七行生成了，`decal` 在游戏代码里一次都没出现。
  武器贴花还按旧的 32×42 坐标画，撬棍只有 1×8 一条线。
  修完端到端量：空手 vs 撬棍从 **36 → 152** 个像素（噪声底 0）。
- `handAt()`：贴花和底板**共用同一套位移**，不再各算各的。

断言 291 → **298**。

### T2.3 · 背包里能做什么 ✅（0.4 天）

「从背包里怎么操作物品」。真答案是：**大部分都不能**。

**最大的洞**：`treat()` 只定义、**从没被调用过** ——
被咬了根本没办法包扎，绷带酒精针线在包里是死重，四步处理链一次都没跑过。

- **伤口单独列在背包页最前面**，一行一条，一次做下一步。
  颜色就是"能不能做"：绿=有耗材，红=缺什么直接写出来。
  做成"物品的用法"是错的 —— 它是**有顺序的工序**（咬四步、抓两步）。
- **动词代替一律的「用」**：吃/喝/穿/背上/拿起/· 手上。
- 处理伤口的东西写 `消毒用`/`缝合用`/`包扎用`，不是只显示重量。
- **每行加「丢」** —— 以前只有开着容器才能放回。
- 机器人也教会了包扎。

断言 298 → **307**。

**诚实的平衡记录**：包扎接上之后探针数字**一点没动**（仍 2.3 天）——
机器人活不到失血要紧的时候。要看到效果得先有 T8。

### T7.22 · 走路的拍子 ✅（0.2 天）

「动作僵硬」的另一半：**四帧等长就是节拍器**，和画得好不好无关。
着地两帧停留 32%、腾空两帧 18%；跑起来着地占比从 64% 降到 53%。
外加侧面走动时上身前倾一格（贴花跟着压）。

这条判断来自量 LPC 动捕：它帧间差异 484/392/496/532，我们是 404/412/412/404。

**第一版改错了一半**：正面和侧面用了同一张拍子表，而正面两个着地帧本来只差 792 像素
（侧面 2396）—— 拉长它们等于把"静止"拉长，手玩报上来「动作太慢」。
拆成两张表：正面 28/22、侧面 34/16。

同轮还砍了出手时长（撬棍 1.20 → 0.85 秒，斧 1.55 → 1.09 秒，轻重次序不动）、
步频提一档。探针死因和天数不变。

断言 307 → **320**。

### T2.4 · 美术选型：LPC 试过了，暂不采用

用真 Chrome 驱动 LPC 生成器，配了 male 体型 + 棕 T 恤 + 海军蓝长裤 + 棕靴 + 深棕寸头，
导出、过 `sprite_import.js` 进了图集。**管线全通**，但比例不合：

| | 尺寸 | |
|---|---|---|
| 现在的手摆 | 42 × 110 | 瘦高 |
| LPC | 60 × 94 | 宽 43%、矮 15% |

LPC 是给塞尔达式俯视 RPG 设计的矮壮比例。另外 T 恤太长把腿盖住了，
眼睛偏大是 RPG 的可爱脸。**布料层次和动作确实更好**，但调性不对。

管线（`png_io.js` / `sprite_import.js` / `render_sprites.py`）都留着，随时能换源。

**过程里的坑**：内置浏览器下载是沙箱化的、且禁止页面访问 localhost；
LPC 页面默认勾着 `Show transparency grid`，会把棋盘画进 canvas，
取消勾选后画布不自动重绘 —— 但下载走的是另一条渲染路径，导出的 PNG 是干净的。

### T8 · 第一天：脚本化开场（0.5 天）

**目标**：别让前 10 分钟平静无事（风险清单第 1 条）。

**改动**
- 开局在自家屋里，水电还通，冰箱里有两天的东西
- 07:30 有一只僵尸砸窗进来 —— 必须逃或必须打，二选一
- 第一间目标屋的门是锁的，**只能破窗**（于是玩家第一次体验到噪音的代价）
- 开局广播念出三个拐点的日期（决策 6）

**验收**：脚本三个节点在 20 个种子下都触发（打印触发次数）。

## Phase 2 · 据点（5 天）

### T9 · 加固门窗（1 天）

木板 + 钉 → 窗钉 1~4 层（每层 10 噪音一下）；门可加锁、可用家具堵。
`board()` 返回 `{ did, lack }` —— 钉不上要说清缺的是木板还是钉（市井 T29）。

**据点**在这一步成立：一栋房里同时有**床**（木板 ×2）和**储物箱**（木板 ×1 + 钉 ×1）
就是一个据点，可以有好几个。`built` 里**一个 owner 字段都不许有**
（[ADR-0002](adr/0002-strongholds-have-no-owner.md)）。

**快进闸门**也在这一步：夜里 + 窗全钉齐 + 8 格内没僵尸，三条全满足才放开 ▶▶，
`why` 要说清是哪一条没过。**这不是省时间的按钮，是据点质量的读数。**
僵尸拆木板有进度且有声音 —— 夜里听见拆板声是本作最好的恐怖来源，不要省这个音效。

**验收**：四层板的窗僵尸拆穿需要的时间是一层的 4 倍 ± 10%。

### T10 · 断水断电倒计时（1 天）

D7~D10 自来水停、D14 电停（日期按种子在区间内取一次，**开局就写进日志**）。
电停之后：冰箱失效（食物开始腐坏计时）、夜里屋内全黑、发电机 + 汽油成为课题。

**验收**：断水那天之后所有水龙头都取不到水（遍历运行时的水源物件，不查字符串）；
冰箱里的食物在断电后真的开始走腐坏。

### T11 · 火 / 烹饪 / 体温（1 天）

火堆 / 灶（从市井搬料理）；体温 = 衣物保暖 + 环境温度 − 潮湿；
淋雨 → 潮湿 → 保暖归零，这条链是入冬后的主要死因。

**验收**：淋雨后保暖值归零、烤火后回升；三种火源的半径与噪音都取到。

### T12 · 制作三十条（1 天）

上限 30 条，**每一条都要在某个拐点前后被真的用到**（否则删掉）：
木板 / 钉 / 绷带（布） / 雨水收集器 / 火堆 / 长矛 / 燃烧瓶 / 陷阱 / 净水（煮） /
腌菜 / 熏肉 / 修理（各武器） / 撬门器 / 简易床 / 储物箱 …

**验收**：30 条配方的产物全部能在背包里出现（逐条跑一遍）；
没有一条配方的材料在镇上找不到（反查 `LOOT`）。

### T13 · 农业（0.5 天）

从市井直接搬四阶段作物 + 季节。改一件事：**田在屋外，弯腰干活会出噪音（6）**。

**验收**：一季能收一茬；干活期间噪音真的在发。

### 别忘了：加固和制作都要能拆回去

沿用市井 T32 的结论 —— **地图从此是动态的**，
读档顺序、寻路的可通行判定、`wipeBuilt` 都要跟着改。每加一张可建表，
就要在 `wipeBuilt` 里加一行（市井 T33 漏过一次）。

## Phase 3 · 长线（4 天）

### T14 · 技能八条与书（0.5 天）

近战 / 枪械 / 木工 / 烹饪 / 医疗 / 农业 / 潜行 / 维修。做事给经验，书给 ×2 倍率到下一级。
死了清零（决策 5）。

### T15 · 冬天（1 天）

D21 入冬：环境温度曲线、雪（视距降低、脚印）、作物停长、水面结冰。
体温从背景变成主要杀手。

**验收**：不穿外套在冬天户外 3 小时进冻伤；穿齐能撑 12 小时。

### T16 · 传承：镇子 + 上一个你（1.5 天）★

**目标**：本作唯一的重玩引擎。

- 镇子存档与角色存档**分离**：加固、田、储物箱、已搜过的容器、街区密度全部留在镇子档里
- 上一个角色死在哪，几小时后在那儿站起来，穿着他的全套装备，名字保留
- 遗嘱三选一：技能 +1 级 / 他藏东西的位置标在地图上 / 他的死因在本局给一次预警
- **遗嘱池在镇子档里**（`town.legacy`），**没有全局的 `qs.legacy`** ——
  否则 A 镇的遗嘱会漏到 B 镇去用，而"上一个你"来自另一座镇
- **镇志**（`town.deeds`，八条）跨局累积，每天把八个谓词跑一遍；
  遗嘱页上那句「他做到了 3 件，剩下的 7 件归你」就是 `deedsLeft()`
- **新角色从镇外走进来**：`spawnPoint()` 取离最近据点最远、又不在最密街区的那条入镇路。
  于是"回到自己的据点"是第一天的目标而不是起点

**验收**：第二局开局时，第一局钉的板还在、翻过的容器还是空的、
上一个你带着上一局的武器（逐件比对物品 ID）；镇子档里搜不到任何角色名；
`qs.legacy` 这个键不存在。

### T17 · 浪潮、渗入与清空结局（1 天）

D30 / D60 外来浪潮 +120，方向提前一天可见。清街的 7 天 `refillLock`。
每天渗入 1~3 只、累计上限 60。

**全镇被清空是一种结局** —— 日志最后一页写"最后一条街也安静了"，
镇志记一条，然后这一局可以继续，只是再也没有对手
（[ADR-0001](adr/0001-zombie-stock-is-finite.md)）。

**验收**：守恒式用**街区表初值**算，不许写死 320；被清空的街区在锁定期内密度不回升；
渗入累计不超过上限。

## Phase 4 · 成型（4 天）

### T18 · 手机、存档与镇子列表（1 天）· 触屏部分 ✅

**触屏已经做了**（手玩反馈"没适配移动端"之后提前做的）：摇杆 + 互动/跑/蹲三键、
安全区避让、切后台松手、听 `visualViewport` 与转屏、竖屏删掉键盘提示。
竖屏的逻辑分辨率取 **7×11** 而不是更多格 —— 手机上宁可少看两格也要人物看得清（市井 T17），
7×11×24 = 168×264 正好能整数放大 2 倍填满手机屏。小地图与状态行跟着画布宽度缩。
**全屏那一轮**（手玩报"适配移动端，全屏画面"）：
逻辑分辨率改成**算**出来的 —— 倍率先取 2，参考框 7×10 放不下就降到 1，
再用 `ceil` 把格数撑到铺满。转屏会重新算并重建画布。
侧栏在触屏上收起，六表 / 时间 / 提示条改画在画布上；镜头把人抬到 **40% 高度**
（底下那条是拇指的地盘）；CSS 断点改成看**形状**不只看宽度。

第一版三个错，都写进规格了：上限 16 格导致横屏铺不满 ·
参考框放不下时直接**裁掉**了画面下面 105 像素（规则是"装得下"不是"裁"）·
812×375 的横屏窗口被当成窄屏竖排。

**还没做**：存档界面、镇子列表。

**镇子列表**：最多三座（`TOWN_CAP = 3`，UI 上限不是技术上限）。
每座显示种子、最好成绩活到第几天、镇志做成几件、现在还剩几只。

虚拟摇杆 + 三键（互动 / 挥击 / 跑）。
**手机上最该删的是它没有的东西**（霓虹教训十三）：删掉噪音数值面板，只留噪音圈与热度小地图。
逻辑分辨率跟视口宽高比走，参考框永远完整装在里面（霓虹教训五）。

### T19 · 音效与观感（1 天）

全部 WebAudio 合成。必须有的五个：拆木板、破窗、脚步（按地面材质）、
咬中、以及**夜里远处的枪声**（不是玩家开的 —— 暗示镇上还有别人，为 v0.2 埋线）。

顺带把**日志页的视觉**做完：泛黄纸 + 手写感 + 一页一天，不带任何 HUD 元素，
死亡回溯写在最后一页上。这是玩家会截图的那一屏，值得多花半天。

### T20 · 平衡与打磨（2 天）

以探针的死因分布为准调数值。目标分布（30 天内）：
尸毒 ~30% / 被围 ~25% / 冻死 ~15% / 饿渴 ~15% / 伤口感染 ~10% / 其他 ~5%。
任何一项超过 40%，都说明别的系统在当装饰。

## 验收工具

沿用霓虹废钢线那一轮的教训，**两件工具从第一天就要建**：

**这两件已经写好了**（在 T0 之前），跑 `npm run check:street` / `npm run probe:street`。
游戏还不存在，所以它们暂时打在 `tools/_street_fixture.html` 这个自检靶子上 ——
桩里只有一行常量指向游戏，`games/quiet-street/index.html` 一出现就自动换目标，
**断言一条都不用改**。契约见[数据规格第九节](静街数据规格.md)。

### `tools/verify-street.js` —— 零件对不对

- 断言查**意图**，不贴实现写（教训一）
- 每条断言都要**打印它数到的数量** —— `扫到 45 个容器` 和 `扫到 0 个容器` 都是绿的（教训二）
- DOM 桩要贴着真 DOM 做：按 id 缓存元素、`classList` 用 Set 真的实现、
  `appendChild` 真的记下孩子。桩越像真 DOM，能测的东西越多（教训十二）
- **`render()` 必须被调用**。专开一节把每条绘制路径都画一遍：
  容器面板、状态面板、日志页、死亡回溯屏、热度小地图、噪音圈、伤口人形图、
  lightmap 乘算层、贴花全开与全关

### `tools/probe-street.js` —— 凑起来能不能活

零件全绿不代表游戏能玩（教训三）。探针用假输入驱动一个机器人**真的活下去**：

```bash
node tools/probe-street.js 20        # 跑 20 局不同种子
```

输出四张表：
1. **死因分布**（第一优先，见 T20）
2. 每局存活天数分布
3. 每天的噪音总量与街区密度曲线（验证 T3 的守恒）
4. 卡死检测：连续 N 分钟位置不变、或背包与地图状态都无变化 → 报僵局

**种子必须能从外部钉死**（教训四）：`start(seedOverride)` + `?seed=`，
`start()` 里不许再用 `Date.now()` 重播种。跨种子之间要把传承档清回零号镇，
否则后跑的种子自带上一局的据点，比的是跑的顺序不是这一局的难度。

`package.json` 加两条：

```json
"check:street": "node tools/verify-street.js",
"probe:street": "node tools/probe-street.js 20"
```

## 三个可能翻车的地方

**① T3 的存量模型可能让玩家学会"完全不出声"。**
如果蹲着不动就能活，整个游戏会退化成蹲房子。三个拐点（断水 / 断电 / 入冬）
就是逼他出门的装置 —— 做 T10 和 T15 之前，这个风险一直是敞开的。
探针要盯一个数：**每天的活动半径**。如果它随天数递减，说明游戏在奖励缩着。

**② 死亡回溯可能写成机器味的账单。**
因果句模板不够，还要有"当时怎么做才对"这一段，而这一段需要
**游戏知道正确答案在哪**（药房的位置、你什么时候路过它）。
这要求事件总线记的不只是伤害，还有"你曾经站在哪、什么东西在你附近"。
T1 生成镇子时就要把每个关键物资的位置记进索引，别等到 T7 再补。

**③ 加固会把僵尸的寻路憋死，然后玩家自己也出不来。**
市井 T30 踩过：**卡住了要能自己出来**。红线两条 ——
每间屋至少两条出路，窗永远能从里面翻出去（哪怕钉了板，拆板只是要时间）。
探针的卡死检测（第 4 张表）就是为这条准备的。

## 砍范围的顺序

钱不够时间不够，从下往上砍：

1. T17 浪潮与清街（存量模型本身已经成立）
2. T14 技能（前 30 天练不动，删了几乎没损失）
3. T15 冬天（但要保留 T11 的体温，否则拐点只剩两个）
4. T13 农业
5. T16 传承 —— **砍到这里就要停**。传承是唯一的重玩引擎，
   砍掉它等于承认这是个一次性 Demo。
