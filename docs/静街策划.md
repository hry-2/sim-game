## 〇、名字

**定了：静街。** 街上安静不是因为太平，是因为**你一直没出声** ——
名字直接指向本作的引擎（见决策 2）。副标题「疫后小镇生存日志」。

目录 `games/quiet-street/`（量具里那行常量已经指着它）。落选：长夜屯 / 余温 / 第九日。

## 一、一句话定位

**你是疫后小镇里的一个普通人。没有终局，只有一份写到你死那天的日志 ——
而你的死因，总是三天前你自己做的某个决定。**

与僵尸毁灭工程的关键差异：**我们不比量，比因果的可读性**。
PZ 里玩家死了常常不知道为什么（"莫名其妙就发烧了"）；
本作把死亡做成一次**因果回溯**，用本仓库已有的事件总线把链条倒推出来给你看。

---

## 二、核心假设（整个项目押在这一条上）

> **「延迟后果能被玩家读懂，并因此改变下一局的行为」本身就好玩。**

具体地说，玩家应该能在死亡屏上读到这样一句话，并且认账：

```
你死于尸毒感染，第 9 天 04:10。
真正的死因在第 6 天 14:20 —— 肉铺后巷，你为了省一发子弹改用撬棍，
被咬中左小臂。你背包里当时没有酒精（最近的一瓶在药房，你第 4 天路过没进去）。
```

这条假设如果不成立，这个项目就只是一个更简陋的 PZ，没有存在理由。
因此 MVP 的唯一任务是尽快证伪或证实它（见第八节）。

## 三、四条循环与它们的耦合

```
      ┌──────────────┐   物资 → 木板/钉/药   ┌──────────────┐
      │ A 搜刮        │ ───────────────────→ │ B 据点        │
      │ 进屋→翻箱→带走 │ ←─────────────────── │ 加固/水/火/田  │
      │ 反馈：分钟级   │   安全的落脚点 → 敢走远 │ 反馈：天级     │
      └──────┬───────┘                      └──────┬───────┘
             │  ↑                                  │  ↑
   伤口/体力 │  │ 药品、食物、休息           过冬/断电 │  │ 技能→效率
             ↓  │                                  ↓  │
      ┌──────┴──────────────────────────────────────┴───┐
      │                  C 身体                          │
      │   伤 → 感染 → 死    反馈：跨天，且不可逆           │
      └──────────────────────┬──────────────────────────┘
                             │ 死亡
                             ↓
      ┌──────────────────────────────────────────────────┐
      │  D 日志（局间）                                    │
      │  镇子保留 · 上一个你变成僵尸 · 一条遗嘱加成          │
      │  反馈：局级                                        │
      └──────────────────────────────────────────────────┘

      A/B/C 都在消耗 ★ 时间 ★，并且都在支出 ★ 噪音 ★
```

三条局内循环不是主次关系，是**同一天里争夺时间的三个去处** ——
这一点沿用市井的结论。新增的是第二种共用资源：**噪音**。

**六条耦合边全部存在。** C 是单向的：身体只会变坏，A 和 B 只能延缓它。
这是本作与市井最大的结构差别 —— 市井没有不可逆的东西，所以没有压力。

| 1 | 核心幻想 | 「我活到了第 N 天」+「我知道自己为什么死」 |
| 2 | 主循环引擎 | **噪音**是引擎。时间是预算，噪音是代价 |
| 3 | 僵尸模型 | **存量 + 迁移**，全镇总量固定，不刷怪 |

### 展开：需要理由的几条

**决策 2 · 为什么引擎是噪音而不是饥饿**

饥饿是计时器，计时器只会让你去做那件唯一正确的事（找吃的），不产生选择。
噪音会：**每一个有产出的动作都在出声**，于是"要不要现在做这件事"变成真问题。

| 行为 | 噪音半径（格） | 性质 |
|---|---|---|
| 走 / 蹲行 | 2 / 0 | 持续 |
| 跑 | 7 | 持续 |
| 近战挥击 | 4（挥空 6） | 一次性 |
| 破窗进屋 | 12 | 一次性，且窗永久破着 |
| 撬门 | 8 | 持续 6 秒 |
| 锤钉木板 | 10 | 每钉一下 |
| 手枪 / 霰弹 | 40 / 55 | 一次性，整条街都听见 |
| 发电机运转 | 18 | 持续，只要在跑 |
| 汽车喇叭 | 70 | **主动引怪工具**（把一个街区抽空） |

修正系数：雨 ×0.5（雨天是搜刮窗口）、夜 ×1.4、屋内隔一层墙 ×0.6。

- 否决：噪音只做"附近的僵尸会来"。那是局部效果，玩家学不会预算。
  必须让噪音改变**街区级的密度**，才会有"这条街被我吵活了"这种长期后果。
- 否决：噪音做成一条数值条。它是空间量，只能画成圈和热度图。

**决策 3 · 存量 + 迁移：一个比刷怪更可读的模型**

全镇 320 只，分 6 个街区记密度。它们**不生成、不消失**，只在街区之间迁移：
噪音把邻区的僵尸拉过来，无人区的僵尸缓慢扩散。

这个模型一次解决三件事：

1. **清街是真的成就。** 一个街区杀到 10% 以下，7 天内不回流 —— 玩家的劳动有存量意义。
2. **噪音有战略价值。** 你把它们引到东边，西边就真的空了。喇叭从此是工具不是错误。
3. **避免了市井 T26 的老账：无限的水龙头会淹掉一切。** 刷怪就是水龙头。

代价：第 30 / 60 天要有一次**外来浪潮**（+120，从镇外某个方向压进来），
方向提前一天可见（远处的鸟群 / 夜里的声音）；另加每天从两条出镇路**渗入** 1~3 只
（累计上限 60），让"安静"是需要维护的东西，而不是一次性买断。

**镇子真的会被清空，而这被当成玩家挣来的一种结局** —— 不是漏洞。
理由，以及被否掉的那个诱人选项（浪潮规模跟已杀数挂钩 = 橡皮筋），
都记在 [ADR-0001](adr/0001-zombie-stock-is-finite.md)。

- 否决：按时间曲线刷怪（PZ 的做法之一）。省事，但"我清掉的街又满了"会直接毁掉据点循环的意义。

**决策 5 · 局间传承：上一个你**

永久死亡 + 什么都不留 = 每局都在重复第一天，这是同类作品最常见的弃坑点。
本作的传承有三样，全部是"世界的记忆"而不是数值成长：

1. **镇子保留**：你加固过的窗、修的门、种的田、放的储物箱，下一个角色进去都还在。
2. **上一个你还在**：死在哪就躺在哪，几小时后站起来，**穿着你上一局的全套装备**。
   想拿回自己的斧头，得先杀掉自己。这一条比任何数值奖励都值钱。
3. **一条遗嘱**：从上一局的日志里挑一条带走 —— 他最擅长的那条技能给你 +1 级，
   或者他藏东西的位置在地图上标出来，或者他的死因在本局给你一次预警。三选一。

- 否决：跨局技能等级累积。那会让第 5 局的开局强度失控，也让死亡不再是损失。
- 否决：全新地图重开。丢掉的正是本作唯一便宜的重玩引擎。

**决策 6 · 压力用写死的日程，不用随机事件**

三个拐点，日期写死，开局就在日志首页告诉玩家（"电力公司广播：预计还能维持两周"）：

| 天 | 事件 | 逼玩家做什么 |
|---|---|---|
| D7~D10 | **自来水停** | 提前做雨水收集器 / 屯水 |
| D14 | **电力停** | 冰箱里的东西开始坏；夜里全黑；发电机+汽油成为课题 |
| D21 | **入冬** | 体温从背景变成主要杀手：外套、柴火、封窗 |
| D30 / D60 | **外来浪潮** | 据点要真的挡得住一次 |

写死的好处：玩家可以**规划**。随机事件只能让玩家反应，不能让玩家规划，
而规划正是生存游戏的乐趣所在（也是霓虹废钢线教训七的结论：有终点本身就是设计工具）。

- 否决：随机灾害表。往系统里灌新鲜感，撑得住前 2 小时，撑不住第 20 小时。

**决策 16 · 镇志：目标结构的最小实现**

仓库里那份[对标星露谷](对标星露谷.md)第三节的原话是「目标结构：完全没有」，
市井后来靠 T27 祠堂补上。静街本来只有"活着"和"清空"，
而永久死亡 + 技能清零会让人反复问"我这几十小时攒了什么"。

**镇志**是一份八到十条的清单，记这座镇**被做成过**哪些事：
清空一个街区 / 有人活过一个冬 / 把发电机弄回据点 / 有人活到第 30 天 /
全镇柜子都翻过 / 立起过一个据点 / 杀掉过上一个你 / 收过一茬庄稼。

关键是它**属于镇子，不属于角色** —— 和传承同一个道理（世界的记忆，不是数值成长）。
收益全在遗嘱页上那句话：**「他做到了 3 件，剩下的 7 件归你」**。
成本接近零：日志已经在记事件，镇志只是每天把八个谓词跑一遍。

- 否决：镇外撤离点 + 限期赶到。一有撤离点，玩家就会把整局玩成赶路，而"没有终局"是决策 4。

**决策 7 · 死亡回溯是本作的签名功能**

事件总线（市井已有）在这里终于有了最好的用途。规则：

- 每一条状态恶化都记因（`bite{part,src,pos,t}`、`wound_untreated{...}`、`cold{...}`）
- 死亡时沿着致死指标**倒推**，取出因果链上的 3~5 条，按"因果句"模板写出来
- 日志每天一页，只记有故事价值的（沿用市井 T15「事件流降噪」的 `isStory` 纯函数约定）

死亡屏必须回答三个问题：**我死于什么 / 什么时候种下的 / 当时怎么做才对**。
第三条要给出**具体**的替代方案（"药房在你西南 40 格，第 4 天你从门口路过"），
不给道德评价。

**决策 8 · 两种感染必须在界面上分得开**

PZ 新手最常见的误解是"被咬就是死"，结果不敢出门，游戏变成蹲房子。
本作显式区分，且用词完全不同：

| | 伤口感染（可治） | 尸毒感染（不可治） |
|---|---|---|
| 来源 | 任何伤口不处理 | 咬伤 35%，抓伤 7% |
| 界面 | 黄色「发炎」+ 部位 | 红色「已感染」+ 倒计时段 |
| 处理 | 清洗→消毒→缝合→包扎；抗生素 | 无。只剩安排后事 |
| 时长 | 12~48 游戏时恶化 | 潜伏 36~96 游戏时 |

尸毒的四个阶段（不适 / 发热 / 呕吐 / 抽搐）**全部在界面上写明**。
玩家应该有足够时间把物资搬回据点、写完日志 —— 这段"知道自己要死"的时间
是本作最有味道的部分，不要用随机死亡把它抹掉。

**决策 9 · 战斗的规则是「别被围」**（速度关系改过一次，见本条末尾）

近战一次只能有效攻击一个目标，挥击有硬直；两只以上贴身会把你打进
**踉跄链**（stagger lock），三只以上基本必死。结论：逃跑永远是正确答案。

- 枪能解决眼前，但噪音把街区密度拉到你头上 —— 这就是决策 2 的落点：
  **每一场战斗的真实代价在半小时后才到账。**
- 反制手段全部是位置性的：门（关上）、窗（翻过去）、栅栏（僵尸要拆）、
  楼梯口（一次只能上来一只）。而不是给玩家更高的伤害数字。
- **会跑的僵尸只做一种：冲刺尸。** 冲刺 1.7（比玩家跑 1.5 快，这 **4 秒**你跑不掉），
  冲完掉到 0.4（比玩家走 0.6 慢，之后你一定跑得掉），累瘫 12 秒。
  全程跑的僵尸**不做，也不做成开局开关** —— 那会让"逃跑永远正确"这条前提失效，
  而我们只有一份平衡预算。

**改过一次：普通僵尸的追击速度从 0.75 降到 0.45，低于玩家走的 0.60。**
原来的设计是"走不掉、跑得掉"，本意是给噪音定价。实际玩下来正相反：
全镇 320 只、每一只都比你走得快，于是你永远只能跑，
**跑的噪音就从"一个选择"变成了"过路费"** —— 一个你必须一直付的代价不是决策，
它把决策 2 自己架空了。

现行关系：**蹲 0.30 < 追击 0.45 < 走 0.60 < 跑 1.50 < 冲刺 1.70**。
于是：走得开一只拖着脚的（慢，但安静）· 蹲着被发现就得站起来 ·
跑是急救而不是通勤 · 冲刺尸那 4 秒只能靠地形。

**决策 10 · 房屋内部用语法生成，不手搓**

搜刮的深度靠的是"屋子里有什么"，手搓 20 栋房的内部必然烂尾。做成三层数据：

```
房型（民宅/商铺/超市/药房/五金/仓库/加油站/警局/诊所/教堂）
  → 房间语法（卧室*2 + 客厅 + 厨房 + 卫生间，按面积摆）
    → 容器（衣柜/冰箱/橱柜/床头柜/工具架/货架）
      → 战利品表（按容器类型 × 房型 × 是否被搜过）
```

好处：整座镇由种子决定，`?seed=` 能钉死（霓虹教训四），而且**下一局同一个镇
但战利品已经被上一个你搬走一部分** —— 传承落到了物品层。

**决策 11 · 技能只留 8 条**

近战、枪械、木工、烹饪、医疗、农业、潜行、维修。做事给经验，书给到下一级的 ×2 倍率。
PZ 有十几条，多出来的那些在前 30 天里根本练不动 ——
沿用「跟星露谷还差在哪」的结论：**不要追量**。

## 五、身体：六表 + 部位伤

| 指标 | 满格耗尽 | 见底的后果 | 主要来源 |
|---|---|---|---|
| 饥饿 | ~2 天 | 掉体力上限，最后昏迷 | 食物（熟食回得多） |
| 口渴 | ~1 天 | 比饥饿快一倍见效 | 自来水（D10 前）/ 雨水 / 瓶装 |
| 疲劳 | 清醒 16 小时 | 视野收窄、手抖、最后强制睡 | 睡（安全的床才睡得好） |
| 体温 | 冬天户外 3 小时 | 行动变慢、判定变差、冻伤 | 衣物保暖值 + 火 + 干燥 |
| 恐慌 | 视野里僵尸越多越高 | **只压枪械精度 −40%，一点都不碰近战** | 离开视野 / 酒 |
| 情绪 | 独处久了走低 | 行动效率折扣 | 收音机（噪音 6）、书、**睡自己据点的床 +10** |

部位 6 处（头 / 躯干 / 左右臂 / 左右腿），伤型 6 种
（咬 / 抓 / 撕裂 / 骨折 / 烧 / 玻璃划）。手臂伤影响挥击，腿伤影响移速。
处理链固定四步：**清洗（水）→ 消毒（酒精）→ 缝合（针线）→ 包扎（绷带）**，
缺一步就留一档感染概率。这条链是"我当时没有酒精"这句死亡回溯的来源。

恐慌**只压枪械精度**：近战已经有踉跄链在罚被围了，同一个状态不许被两套机制罚两次。
于是恐慌只剩一份明确的工作 —— 给"别在被围的时候掏枪"这个直觉一个数值支撑。
情绪则绑在据点上：**睡在自己据点的床上 +10，睡在陌生地方 0**。
它因此成为六表里唯一奖励"经营据点"的指标，而不是又一笔维持税。

背包：腰包 6 格（永久） + 背包 12 格（要找到）。负重两档：正常 / 超重（移速 -35%，
噪音 +50%）—— 不做 PZ 那套连续负重曲线，玩家读不懂也用不上。

## 六、一天的时间预算（D5 的典型一天）

| 时段 | 长度 | 去处 |
|---|---|---|
| 06:00–07:00 | 1 时 | 维持：吃、喝、处理伤口、看昨天的日志 |
| 07:00–12:00 | 5 时 | **搜刮**（往外走，走多远是今天最大的决定） |
| 12:00–14:00 | 2 时 | 搬回来、清点、做饭 |
| 14:00–18:00 | 4 时 | **据点**：加固 / 田 / 制作 / 修东西 |
| 18:00–20:00 | 2 时 | 天黑前的最后一趟（近处，只拿轻的） |
| 20:00–06:00 | 10 时 | 夜：出门属于自杀；守夜或睡觉，**门窗钉齐且外面没人时可快进** |

白天一律 1x —— 白天的每一秒都该有决定要做。夜里那十小时在满足条件时压到一分钟以内，
**于是"今晚能不能跳过去"本身就是据点质量的读数**：熬实时的那一夜，是因为有一扇窗没钉。
一天的有效长度因此落在 6 分钟上下，30 天约 3 小时 —— 和市井（1x 一天 6 分钟）、
霓虹（打满 30 波 26~32 分钟）是同一个量级。

维持性开销约占 15%，比市井低（那边是 30%）——
因为本作的稀缺不在时间，在**你敢走多远**。可支配时间刻意够用，
**安全的活动半径刻意不够用**。

## 八、MVP：一周试玩

**唯一任务**：验证核心假设 —— 玩家读完死亡回溯之后，下一局的行为会变。

### 必须有的

- 一条街 4 栋房（民宅 ×2 + 五金 + 药房），内部语法生成，容器可翻
- 僵尸存量 + 噪音传播 + 街区密度（只做 2 个街区）
- 饥饿 / 口渴 / 疲劳三表，咬伤 + 两种感染
- 近战 + 踉跄链 + 门窗
- **日志（每天一页）+ 死亡回溯屏**
- 第一天的脚本化开场：一次被迫逃跑（别让前 10 分钟平静无事）

### 不做

技能、农业、体温、冬天、电、传承、枪、手机适配。

### 规模

约 1500 行，2~3 天。

### 验证方法（比 MVP 内容更重要）

1. **探针 20 局不同种子**（`tools/probe-street.js`）：看**死因分布**。
   如果 80% 死于同一个原因，那不是难度问题，是别的系统全是装饰。
2. **人试玩 3 局，记录前后差异**：第 2 局起，玩家的
   *跑步占比 / 开枪次数 / 最远活动半径 / 伤口处理完成率* 应该明显变化。
   这四个数不变 = 死亡回溯没被读懂 = **核心假设证伪**。
3. 让玩家复述自己的死因。复述不出来，就是文案问题而不是机制问题。

## 十、技术选型：不引入引擎

三款已发的游戏都是单 HTML / Canvas 2D / 零依赖，4600~5700 行。这不是习惯，
是这个仓库的三条硬约束：**双击即玩、Pages 零构建、单文件可以独立拿走**。

引擎（Godot / Unity / Phaser）能买到的东西，这里已经全部写完、而且测过：

| 引擎给什么 | 本仓库现成的 | 在哪 |
|---|---|---|
| 瓦片地图 + 摄像机 | 62×52 分区地图、摄像机跟随、小地图 | 市井 T16/T17/T36 |
| 像素管线 | RS=3 后备存储放大、整数倍 CSS 缩放、`imageSmoothing` 关 | 市井 T31 |
| 精灵流水线 | 逐像素部件生成器 + 自写 PNG 编码 + base64 嵌回 | `tools/character_gen.js` |
| 输入 / 手柄 / 移动端 | 虚拟摇杆、手柄、逻辑分辨率跟视口走 | 霓虹（教训五、十三） |
| 物理 / 视线 | 瓦片碰撞、DDA 视线遮挡、门 | 夜港 T1 |
| 存档 | localStorage + 读档顺序那几个坑 | 市井 T20/T32 |
| 音频 | WebAudio 实时合成 | 霓虹 |
| AI | 效用打分内核、日程锚点 | 市井 |

引擎要付的代价，条条戳在要害上：

1. **构建步骤回来了** —— 双击即玩和 Pages 零构建同时没了
2. **离线验收全废。** `verify-*.js` / `probe-*.js` 是 Node + DOM 桩跑的，
   十一个脚本近七百条断言。换引擎这套要按引擎自己的测试框架重写，
   而"机器人真的把一局打下去"这种探针在引擎里成本高一个数量级
3. **授权分离**（代码 MIT / 资产专有）要重新设计
4. 还得花约一周，把上面那张表重新实现一遍

**唯一能说服我换引擎的理由是多光源实时阴影，或者上千实体的物理。** 本作的预算：

- **实体**：全镇 320 只，视口外不渲染、非当前街区只跑天级迁移结算 ——
  存量模型（决策 3）天生就是 LOD。同屏峰值约 40 只
- **光源**：手电 1 个 + 火堆与灯 ≤6 个，半径都在 10 格内
- **碰撞**：瓦片网格，不需要刚体

Canvas 2D 绰绰有余。

**但有一条要说清楚。** 单文件规矩意味着静街不能 `import` 市井的模块，
只能把内核**抄**过来；抄过来就会分叉，市井以后修的 bug 不会自动到静街。
这个代价是明知故犯的，缓解办法是本仓库已有的那一层：
**`tools/` 才是真正的共享层**（生成器改一次，`--embed` 嵌回每款游戏）。
人物生成器、PNG 编码、图集这三样走 tools；渲染与逻辑内核认赌服输地复制。

**什么时候该改主意**（现在写下来，免得以后靠感觉决定）：要做真 2.5D 分层、
要多层动态阴影、同屏要上千实体、或者单文件超过 8000 行且抄来的内核已经和
市井对不上账 —— 四条里任意一条成立，就停下来重新算。

## 十一、画风：低饱和的场景，一点高饱和

**第一原则：画风服务于可读性。** 本作视觉上最重要的一件事不是好看，
是让玩家一眼看出**哪里安全、谁听见了我**。

| 维度 | 决定 | 理由 |
|---|---|---|
| 视角 | 正交俯视，一格 24 世界像素，`RS=3` | 直接沿用市井的管线，一行不改 |
| 一帧 | 人物逻辑 32×42（与市井同尺寸） | 帧高必须整除 `RS`（市井 T31 的坑），图集几何不动 |
| 比例 | 头身比 **1:3.18**（头 11 行 / 全身 35 行） | 换比例就换气质。**原来写"从 1:2 拉到 1:2.6"是错的** —— 量过市井：它已经是 1:2.62，照那个数改等于没改 |
| 调色 | 16 色主板；饱和度比市井降 20%，亮度上限压到 82% | 给 UI 让出整个高饱和区间（见下） |
| 季节偏移 | 每季一套 4 色环境偏移（秋黄 / 冬灰蓝 / 春绿 / 夏燥） | 沿用市井季节，最便宜的"过了很久"的感觉 |
| 地面 | 3px 颗粒撒点，**不许纯色** | 市井踩过：地面撒成纯色，整张画面立刻塑料感 |

**唯一允许在场景里出现的高饱和色是僵尸的眼睛。** 一格两点，
夜里在手电范围外也看得见 —— 黑暗里你先看见的是几点眼睛，然后才是轮廓。
这条同时解掉了"低饱和 + 夜晚 = 什么都看不清"这个陷阱的一半。

**UI 反过来：纯色、高饱和、1px 硬边。** 噪音圈（白色虚线扩散环）、
街区热度（四档）、伤口人形图（黄 / 红两色）永远从场景里跳出来。
低饱和的场景就是为了这一刻。

### 立面：做伪 2.5D，不做等距

**决定：墙和家具有"层高"，实体按行交错画；不做真等距。**

每样有体积的东西都画两块：顶面往上挪 `WALL_H`（墙 10 世界像素 / 家具 6），
立面补在下面那一条，中间一道亮边。从上往下一行一行画，
先画这一行的墙和柜子，再画站在这一行的人 —— 于是站在南墙**里侧**的人
会被那道墙的顶面盖住小腿，站在墙南边的人盖住墙。
**遮挡关系自己就对了，不需要深度排序。**

- 否决：**真等距（PZ 那种）。** 地图逻辑不用改（还是网格），但要重写整个渲染层，
  而且精灵要 4~8 个朝向 —— 现在一个人 4 帧，换等距是 16~32 帧，
  画法代码乘 4，图集、贴花层序、离线断言全部跟着乘。再加鼠标↔格子映射、
  噪音圈与视锥的画法。估 1~2 周，会吃掉整个美术预算。
  而且它正是第十节列的**换引擎四条触发线之一** —— 真做了，Canvas 2D 手写这条路就该重新算账。
- 伪 2.5D 的成本是半天，拿到的是同一件事里最值钱的那部分：**房子读成有高度的实体，
  而不是贴在地上的补丁。**

校验器钉三条：行号一路不减、玩家之后还有更南边的物件要画、层高墙 > 家具。

### 和僵尸毁灭工程的距离：拆成七件，只做四件

被问"怎么能做到和 PZ 一样"时，把它拆开：**①等距投影 ②手绘瓦片 ③八向角色
④视野锥+记忆迷雾 ⑤动态光照 ⑥杂物与血迹 ⑦后期分级**。

**做 ④⑤⑥⑦，不做 ①②③。** 理由、成本与被否掉的等距方案见
[ADR-0003](adr/0003-vision-not-isometry.md)。一句话：
**玩家说"像 PZ"时指的往往是"只有一小块是亮的、其余是灰色记忆"，而不是斜的墙** ——
而那一件对我们最便宜。

美术产能的路线是 **(c)+(d)**：程序化密度打底（每种地面烤 4 张变体、噪声颗粒、结构线），
**手摆**那几样玩家天天盯着看的（门、窗、板窗、8 种杂物）。角色不动。

### 唯一要新写的渲染层：光

这是静街和另外两款视觉上最大的区别，也是唯一真的要写新代码的地方：

- 一张 **1/3 分辨率**的离屏 `lightmap`，每帧清成"环境暗度"
  （白天 0 / 夜里 0.82 / 断电后的室内 0.95）
- 手电画锥形（径向渐变 + 扇形裁剪），火堆与灯画圆形，都往 lightmap 上加
- `globalCompositeOperation='multiply'` 一次性乘回主画布

成本约半天。1/3 分辨率是刻意的：光斑边缘的像素颗粒和地面颗粒同一个尺度，
不会出现"像素场景 + 高清光晕"那种割裂（霓虹的辉光管线是同一个思路）。

### 状态外显：身上要看得出自己什么状态

霓虹立过规矩 —— 每条词条在人物身上都有对应的一件东西。生存游戏更需要这个：
玩家不该靠翻面板才知道自己在流血。贴花层（沿用霓虹 `DECAL` 的做法）：

**六类贴花**（叠加）：绷带（六个部位）、血渍（三档）、冻伤（手脚发白）、冬装、
背包（找到才画）、手上的武器（五件五个样子）。

**一个渲染层效果**（乘算）：**湿透** —— 整体压暗偏蓝。它做不成贴花：
贴花只能往上加东西，压暗要乘。第一版当贴花画成了满身横条，整个人像穿了囚服，
预览图一眼就看出来。它和 lightmap 走同一条路。

**贴花有层序**：绷带 → 血渍 → 冻伤 → **冬装** → 背包 → 武器。
外套压住绷带和血（不然像把绷带缠在大衣上），包和武器在最外面。

### 签名功能要有签名视觉

日志页和游戏内 HUD 应该是完全两种东西：**泛黄纸 + 手写感字体 + 一页一天**，
不带任何 HUD 元素。死亡回溯就写在最后一页上。这一处值得多花半天 ——
它是玩家会截图的那一屏。

### 新增的生成器

`tools/survivor_gen.js`，从 `character_gen.js` **分叉**（不是改它，市井还在用）：
换调色板、拉比例、加贴花部件。瓦片仍然全部在代码里程序化画（市井就是这么做的，
不出图集），只有人物走图集。

```json
"survivors": "node tools/survivor_gen.js --embed"
```

### 十一之二、脸改成动漫向（后来改的）

原来这节定的是**低饱和写实像素**，脸也照写实画。实际做出来玩家的评价是"太丑"，
于是把**脸**改成动漫向：大眼睛、鼻子一格、嘴两格、下巴收尖、刘海压低。

**改的只有脸。**身体比例、低饱和、光从左上、伪 2.5D 这些都没动 ——
换句话说这是"写实像素的身体 + 动漫的脸"，不是整体换风格。

**有一条刻意守住**：虹膜用**低饱和的蓝灰**。
全场唯一的高饱和留给僵尸的眼睛，那是"黑暗里先看见几点眼睛"的硬规则（见本节开头），
动漫化不该把它吃掉。

**画动漫眼睛踩过的三个坑**（都是渲染出来看了才发现的）：

| 试的 | 读成了 | 为什么 |
|---|---|---|
| 4 格宽、大块白眼球 | **眼镜** | 白色成了镜片，上面那道通长深线成了镜框 |
| 4×4 全填虹膜 | **墨镜** | 没有白眼球，就是个纯色块 |
| 虹膜**两侧留白** | 眼睛 ✅ | 动漫眼的读法靠留白，不靠大 |

外加两笔：**眉毛**（把"眼镜"读回"眼睛"最有效的一笔）、**刘海压低**（动漫脸额头短）。
