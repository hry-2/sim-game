# 美术管线：外部素材怎么进游戏

> 六轮迭代（参数化 → 手摆 → 分辨率翻倍 → 动漫脸 → 28 帧部件位移）之后，
> 结论是**参数化到顶了**，而手摆解决不了"动作僵硬"。
> 换路：**3D 渲染成精灵**。这也是僵尸毁灭工程自己的做法。

## 为什么是 3D，不是 AI 出图，也不是精灵包

| | 人丑（单帧静态） | 动作僵硬（帧间运动） |
|---|---|---|
| AI 出图 | ✅ 能 | ❌ **不能** |
| 免费精灵包 | ✅ 能 | ⚠️ 只能用它有的 |
| **3D + 动捕** | ✅ | ✅ |

AI 出图**每张独立生成**，要 28 帧就会得到 **28 个长得略微不一样的人**。
走路循环要求逐帧亚像素级一致，这恰好是扩散模型最不擅长的。
再加上生成的"像素风"带抗锯齿、不在像素网格上，缩到 96×126 会糊。

Kenney 的包 CC0 授权最干净，但**没有四向带攻击的生存者**。
LPC 有四向走/劈/刺，但 **CC BY-SA / GPL 是传染性的**，而且是塞尔达式 RPG 风。

## 管线

```
Mixamo（免费动捕，不用建模不用绑骨）
   ↓ 下载 FBX
blender -b -P tools/render_sprites.py -- --walk 走.fbx --attack 挥砍.fbx --out /tmp/frames
   ↓ 28 张 576×756 的 PNG（带 alpha）
node tools/sprite_import.js /tmp/frames --colors 20 --row 0
   ↓ assets/sprites/imported96.png（2688×2016）
嵌回游戏（base64）—— 单文件属性不受影响
```

**单文件属性不受影响**：美术做成 PNG 图集、base64 嵌进 HTML，
现在的 `survivors96.png`（169KB）就是这么干的。

## 导入器做的四件事

| | 为什么 |
|---|---|
| 对齐到 96×126，**按脚底对齐** | 中心对齐会让走路时整个人上下浮动 |
| 盒式降采样，**只对不透明部分平均** | 把透明像素算进平均会让边缘发灰 |
| **整组 28 帧共用一张调色板** | 每帧各量化各的，走起来会闪色 |
| **硬边 alpha** | 像素画不做半透明边；软边缩完会糊成一圈灰 |

`tools/png_io.js` 补了仓库一直缺的一半：**PNG 读取**（以前只能写，外来美术进不来）。
零依赖，Node 自带 zlib。

## 已知风险：降采样会吃掉脸

压力测试（576×756、4462 色、带软边）过管线之后：尺寸对、20 色、0 个半透明像素，
但**脸糊了** —— 眼睛成了两团污迹。

原因很硬：**96×126 的帧里一张脸只有约 15 像素宽。**

所以：

1. **模型要风格化** —— 平涂、强剪影、五官夸张。写实模型渲出来必糊。
2. **脸在这个尺寸上注定简陋**。PZ 自己的角色在默认视距下基本没有脸 ——
   它靠剪影和动作，不是表情。"人丑"有一部分其实是**脸做得太细，反而经不起看**。
3. 实在要脸，就把帧做大（128×168，脸有 20 像素宽），代价是重新定标。
