# 点头：规则对所有词包一视同仁 —— 表演人可以说话，只是不能说禁字

[ADR-0005](0005-three-packs-may-speak.md) 为三个知识包开了「可以说话」的例外，
好保住其余七包「全程不许出声」那条核心规则。这条决定**撤掉那个例外，
也撤掉它想保护的规则本身**：现在表演人怎么描述都行 —— 比划、说话、演 ——
唯一的约束是不能说屏幕上那个词里出现过的字（禁字）。

## 为什么连规则一起撤

例外本身是能工作的，问题在于它**让规则不再是全局的**，而这笔账一算就不对：
讲规则要多说一句话、菜单要多一个角标、词屏要逐词标注、
量具要多五条断言来钉住「随机包里逐词判断」这件容易漏的事。
四处结构成本，只为保住一条规则。

而那条规则**不承重**。点头的乐趣在两处：60 秒的时间压力，
以及屏幕朝外带来的"猜的人什么都看不见、只能听声音"。
「不许出声」既不产生这两者，也不被它们需要 —— 它只是最初描述玩法时
顺手写下的一句话，后来被当成了前提。

## 代价：失去了唯一一个跟同类游戏不一样的规则

市面上的你说我猜大多也是「不能说词里的字」。撤掉默演之后，
**点头的差异点完全落在翻手机判定和屏幕朝外上**，词和规则这一层跟别人一样了。
这是清醒接受的：差异点本来就该长在那两处，靠一条约束硬撑出来的差异不牢。

## 后果

- **比划从规则降为手段。** 游戏名「点头」指的是判定动作（下翻＝猜中），
  不是表演方式，所以名字不受影响。`CONTEXT.md` 里「表演人」的定义跟着改了。
- **契约收回三项**：`SPEAK` / `canSpeak` 撤掉，`packOf` 留着（量具验随机包混抽要用）。
  量具里钉了一条反向断言：这两个名字**不许回来** ——
  它们再出现就说明规则又被按包拆开了。
- **禁字同样没有代码在管**，靠桌上的人自觉。这一点和 0005 一样，是有意的：
  真要拦得盯着表演人说什么，而这游戏连麦克风权限都不想要。
