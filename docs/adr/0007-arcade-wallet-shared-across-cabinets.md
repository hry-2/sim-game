# 币袋：一份账本，全柜通用 —— 单文件游戏的代价是两份十二行的实现

聚宝盆是本柜唯一产币的机台，而它的余额一直只活在它自己的存档
（`coinpusher.jubaopen.v1`）里。现在要求是：**把它当成街机厅里的一台机器，
赢到的币全柜通用。**

## 决定

币从机台里搬出来，放进一份共享账本：

```
localStorage['arcade.wallet.v1'] = { v: 1, coins: <int>, t: <ms> }
```

- **首页**（`index.html`）只读并显示；第一次进来时播下 300 的初始币。
- **聚宝盆**读写：余额就是这个世界里的 `coins`；机台自己的存档不再管余额，
  「重置机台」只清分数/能量/进度/台面，**不动币袋**。
- 两边都挂 `storage` 监听：另一个标签页在机台里花/赢了币，这边跟着变。
- 老存档第一次接进来时，把旧的 `bal` 写进币袋——不因为换账本把人清零。

## 为什么是「复制一份」而不是抽共享模块

单文件是这个仓库的卖点，首页文案自己写着「单个 HTML 文件、双击就能跑」。
抽一个 `assets/wallet.js` 出来，每个接入的游戏都多一条外部依赖：
拷走一个 HTML 就不能玩了，`file://` 下也更容易出现加载顺序问题。

而这个"模块"的全部内容是一个字段的读写加一次取整，**十二行**。
重复它的代价，小于破坏单文件。代价写在下面，不藏着。

## 代价

- **两份实现要一起改。** 两边都有 `WALLET_KEY` / `WALLET_SEED` 和同一段读写，
  改结构（加字段、换键名）必须同时改两个文件。两处注释里互相指着，指向这条 ADR。
- **不同步设备。** localStorage 是本机的：换手机、换浏览器、清站点数据，
  币袋从 300 重新开始。
- **没有服务端**，所以也没有"防改"这一说——玩家手改 localStorage 就是能改。
  这个柜子没有排行、没有交易，币只是玩下去的理由，不值得为它上服务端。

## 后果

- 聚宝盆的 HUD 从「余额」改叫「币袋 · 通用」；重置弹窗改成"币袋里的币不动"。
- 投币路径必须**立刻**落盘（原来余额只在页面隐藏时补写），因为首页和别的标签页
  看的是同一份账本——这就是 `spawnPlayerCoin()` 末尾那句 `save()`。
- `tools/verify-pusher.js`：清档要清两个键；新增两条断言
  `wallet == balance`（投币后账本与机内余额一致）和 `home purse == wallet`
  （首页显示的数字就是账本里的数）。少了这两条，"余额接进币袋"可以悄悄失效。
- 以后哪台机台想接：读写同一个键，遵守「`coins` 是整数、非负」，别在机台里
  另存一份余额。
